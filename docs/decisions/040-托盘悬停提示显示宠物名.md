# 040 · 托盘悬停提示显示宠物名（而不是产品名 `desktop-pet`）

- **状态**：已接受
- **日期**：2026-09-22
- **决策人**：用户（原话：「我想更改托盘里鼠标悬停时显示的程序名称，把 desktop-pet 改为淘淘」）
- **影响**：`src/host/tray.ts`、`src/host/pet-menu.ts`（`PetMenuView.petName`）、
  `src/main/index.ts`（宠物名收成一处）、`tools/status-arbiter.test.mjs`（结构性断言）

## 背景与决策

托盘图标的悬停提示此前写死两处：`setToolTip('desktop-pet')` 与
``setToolTip(`desktop-pet · ${view.statusLine}`)``。`desktop-pet` 是**产品/进程名**，
而用户在面板上看到的是这只宠物的名字（「淘淘」）—— 同一个东西在两处显示两个名字。

1. **提示改为 `${宠物名} · ${状态}`**，名字**取自宠物包**（`pet.json` 的 `displayName`，
   回落 id），不硬编码 —— 与面板上的身份位（ADR 016 决策 4）**同一个来源**，换宠物包自动跟着变。
2. **删掉那句初始 `setToolTip('desktop-pet')`**：`refresh()` 紧接着就会调用，
   两处写同一个值只会让下一个人不确定该改哪一处。
3. **宠物名在主进程里收成一处**（`const petName = ...`）。
   此前 `buildPayload` / `barView` / `__petDebug` 各写一遍
   `pack.manifest.displayName ?? pack.manifest.id` —— 三份副本正是"两处显示两个名字"的温床。
4. **`PetMenuView` 加 `petName` 字段**，而不是让 `tray.ts` 自己去读宠物包：
   托盘与菜单都不持有状态（ADR 010 的唯一真值约定），名字由调用方现读传入。

## 不许顺手改的地方

**宠物窗口的标题必须保持 `desktop-pet`**（`src/renderer/index.html` 的 `<title>`）——
**所有真机探针都靠 `getTitle()` 找窗口**（`waitFor('desktop-pet', ...)`），
改了它整套回归会静默失效（找不到窗口 ⇒ 报"未等到桌宠窗口"，看起来像启动失败）。
已加结构性断言钉住。用户要改的是**托盘悬停提示**，不是窗口标题。

## 实测

- 单测：新增两条结构性断言 —— 托盘源码里不再出现 `desktop-pet`（**先剥掉注释再查**）、
  提示取自 `view.petName`；另加"宠物名只有一处定义"与"窗口标题仍是 desktop-pet"。
- 判据的一个副作用值得记：第一次写这条断言时**被自己的注释判红** ——
  `tray.ts` 里那句"**不再用 `desktop-pet`**"的注释本身含有那个字符串。
  ⇒ 给测试文件加了个 `stripComments()`：**结构性检查一律先剥注释**，
  否则"断言比它要测的东西更脆"。

## 负面结论

1. **托盘提示里的名字与 exe 文件名/进程名不再一致**（托盘显示"淘淘"，
   任务管理器里仍是 `desktop-pet.exe`）。这是刻意的：托盘提示是**给用户看的**，
   而进程名是机器标识，改名要动打包脚本与自启值名（ADR 036 的领域），收益不成比例。
2. **宠物包没写 `displayName` 时会回落到 id**（如 `taotao-new`），
   提示会变成 `taotao-new · 空闲`。可接受，但不如名字好看 —— 换包时记得写 `displayName`。
