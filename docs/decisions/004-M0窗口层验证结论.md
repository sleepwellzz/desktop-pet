# 004 · M0 窗口层验证结论：改用分层窗口原生命中测试

- **状态**：已接受
- **日期**：2026-09-15
- **决策人**：用户 + agent（依据 `spikes/m0-window/` 实测）
- **影响**：**修订 001 第 5 条**（WM_NCHITTEST 方案作废）；影响 M1 渲染层设计

## 背景

001 里锁定"点击穿透用 `WM_NCHITTEST` 采样 alpha，不用 `setIgnoreMouseEvents` + 前端回传"，
理由是前端回传有延迟与边缘抖动。M0 的任务就是验证这条路线是否真能跑通，
同时验证不夺焦点与全屏让位。

## 实测结果

环境：Windows，主显示器 2560×1600 @150%；Electron 44.4.0（内嵌 Node v24.21.0）；koffi 3.3.0。

| 判据 | 纯 Win32（koffi） | Electron 宿主 |
|---|---|---|
| 透明区域点击穿透到**其他进程**窗口 | 通过（native 与 NCHITTEST 两种模式都通过） | **通过（native 模式，无需任何原生代码）** |
| 不透明区域由宠物吃掉点击 | 通过 | 通过 |
| 点击不夺焦点（`WS_EX_NOACTIVATE`） | 通过 | 通过 |
| 全屏窗口出现时检测翻转 | 通过（前台矩形 ⊇ 显示器矩形） | 通过 |

三条退出判据全过，**Electron 选型不作废**。

## 决策

1. **放弃 `WM_NCHITTEST` 采样 alpha 方案**（001 第 5 条作废）。
   改为直接依赖 `WS_EX_LAYERED` 的**原生命中测试**：alpha=0 的像素自动把鼠标消息让给下层窗口，跨进程有效。
2. **不再把渲染层的 alpha 掩码回传主进程**，取消该 IPC 通道与每帧几十 KB 的传输。
3. **不再用 koffi 子类化 `GWLP_WNDPROC`**。实测 `SetWindowLongPtr` 返回成功（非 0），
   回调却一次都没被调用，且窗口变成**整窗穿透**——连不透明区域也不再接收点击。
   推测：Chromium 在非 Node 线程派发窗口消息，koffi 无法在该线程回调 JS，
   `WM_NCHITTEST` 因此拿到默认返回值 0（`HTNOWHERE`）。这是**静默失效**，不报错、只行为异常。
4. 扩展样式以 Electron 原生能力为准：`transparent` + `alwaysOnTop` + `focusable: false` 已自动带上
   `NOACTIVATE | LAYERED | TOPMOST`；仅补 `WS_EX_TOOLWINDOW`（或用 `skipTaskbar`）。
5. 原生代码（koffi 或后续 C++ 插件）**只保留全屏检测**一项，未来再加全局快捷键与托盘。
6. 全屏判据：以「前台窗口矩形 ⊇ 显示器矩形」为主，
   `SHQueryUserNotificationState == RUNNING_D3D_FULL_SCREEN` 为辅。
   **不使用 EnumWindows 扫描**（系统窗口恒为覆盖态，误报严重）。

## 理由

原生方案把命中测试交给 Windows 合成器，零延迟、零 IPC、边缘与渲染结果逐像素一致，
比在 JS 里采样掩码更简单也更准。实测两套方案在 Win32 层都通过，但只有原生方案在 Electron 下真正生效。

## 后果

- **正面**：M1 渲染层不需要掩码回传，宿主适配层从四项能力缩到「全屏检测 + 未来的快捷键/托盘」。
- **约束**：渲染层**必须**保证想穿透的区域 alpha 严格为 0。调试用的半透明遮罩、HUD、
  阴影都会让那块区域变成可点击，M1 需要把宠物本体与调试 UI 分层到不同窗口。
- 若将来要做"宠物半透明时可点"这类需求，原生方案做不到（alpha>0 即命中），届时需重新评估。
- koffi 在 Electron 44 下 ABI 兼容、无需重编译，可继续用于全屏检测；
  若要彻底去掉原生依赖，可用 Edge.js 之外的方案另议，当前维持 koffi。
