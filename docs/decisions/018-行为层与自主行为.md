## 背景

`desktop-pet.json` 的 `behavior` 段从第一版就在（漫游区间、微动作、打盹、边界策略），
但**一行代码都没实现** —— 宠物只是站在角落里循环待机。M3 的第一块就是把它做出来。

这同时兑现了一条早先的承诺：§3 记过"运行中看起来像在忙这个诉求交给 M3 行为层"。
本轮**没有**做那个（理由见负面结论 1），做的是"没人用它时它像个活物"。

## 决策

### 1. 有任务时**不动**：`status !== 'idle'` 就整体让位

自主行为只在"没人用它"的时候发生。运行中宠物要跑掉反而像擅离职守；而且
`needs-input` 时它正举着手等确认，飘走会让"举手"这个提示失去位置感。
实现上很便宜：规则 0 一条判断，把相位归零并**交回动画**（`play: null`）。

### 2. 策略做成**纯函数**（`kernel/behavior.ts`），时钟与随机数可注入

与 `bubble-policy` / `bar-policy` 同一个理由：这套规则全是"到点才发生"的，
在屏幕上**看不出对错**（25 秒还是 28 秒后开始走都只是"它在走"），而它又是最容易把宠物弄坏的一块。
拆开之后，22 项断言的离线单测秒级跑完；真实窗口那部分只留 7 条"只有窗口能回答"的判据。

### 3. 位移速度按缩放线性归一化

`speed = speedPxPerSec × scale / defaultScale`（默认缩放 0.7 → 96 px/s）。
放大的宠物走得快些，但"每秒走过几个身位"不变 —— 这正是 sidecar 里那句"保证不同尺寸下观感一致"。
单测按 1 秒的位移量量出来（0.7 → ≈96px，1.4 → ≈192px）。

### 4. 边界：目标点**夹进工作区**，够不到就换方向

`edgePolicy` 的落地方式。宠物不会走出工作区（真实探针全程采样，越界 0 次）。
**跨屏漫游不做**：那要先定义"窗口矩形跨越两块屏时算在哪一屏"与"多屏工作区并集"，
是另一轮的活；本轮的范围写进了 sidecar 的 `edgePolicyScope`。

### 5. 打盹计时**不**被漫游与微动作重置

只在"主状态离开 idle"或"用户碰了它（单击/抓住）"时重置。
否则每 25–90 秒走一次会把 5 分钟的计时无限推后 —— **它永远睡不着**，
而且屏幕上只会表现为"它就是不打盹"，没有任何报错可循。已用单测钉住
（"走完这一程就打盹（计时没被漫游重置）"）。
打盹也**不打断正在走的这一程**：走到一半突然趴下比多走两秒再趴下更像个 bug。

### 6. 位移姿态与微动作候选**不硬编码状态名**

位移姿态按 `role`（`locomotion-left` / `locomotion-right`）从包里推导；微动作候选过滤掉
包里不存在的状态并告警；打盹姿态取自 sidecar 但同样校验存在性。
换一个宠物包（哪怕行语义一样、状态名不同）这套也能跑 —— 这是"宠物包是数据、运行时是代码"的延续。

### 7. 拖动的边沿由**渲染层显式上报**（`CH.dragState`），不靠"多久没收到增量"猜

用户抓着不放、手停一下是常态；按"若干毫秒没有拖动增量就当松手"来猜，会让宠物**在他手里自己走起来**。
这条是"绝不与用户的手抢方向盘"的唯一防线，真实探针专门验了它（抓住 3 秒，位置变化 0 次）。

### 8. 动画覆盖与业务状态**分开走**（`CH.behavior`）

漫游/微动作/打盹都不是业务状态，塞进 `statusMap` 会让托盘、气泡、控制条开始显示一些
不存在的业务状态。所以另开一个通道，语义三态：**缺省 = 不变 / `null` = 交回仲裁器 / 对象 = 按它演**。
覆盖期间渲染层不再把播放器收敛回主状态（否则每帧被拉回去，走不动）。

### 9. 给回归探针加 `--no-behavior` 接缝

宠物会自己走 ⇒ 位置类断言全部变脆（探针读一次窗口位置、再按它算点击坐标，中间宠物走掉了就点空）。
与既有的 `--no-status-source` 同一套路。**既有 7 个探针全部带上它**；
行为层自己的判据在 `spikes/m3-behavior`（那边当然不带）。

## 实测（2026-09-17）

**离线（`tools/status-arbiter.test.mjs` ⑭，22 项；总数 138 → 191）**：
启动不立刻乱跑 / 到点才走且朝向与方向一致 / 速度按缩放归一化 / 目标夹进工作区 / 贴边换方向 /
抑制期间一步不动且保留目标 / running 期间不动且交回动画 / 打盹与醒来 / 漫游不重置打盹计时 /
微动作只在候选里挑且播完交回 / 减少动态效果下不动但打盹照常 / 交回是边沿不重发 / 总开关。

| 只沿地平线走 | ✅ 出现过的 y 只有一个值 |
| 不越出工作区 | ✅ 越界采样 0 |

控制条两探针 PASS、状态端到端 PASS、气泡与快捷键 PASS、陈旧快照 22 项 PASS。

## 负面结论

1. **"忙碌动作"没有做，而且是刻意不做**：它与"只在 idle 时活动"直接冲突 ——
   要做就得先回答"任务进行中宠物能不能离开原位"，那是**产品决定**，不该由我在实现里顺手拍。
   它仍然是"运行中看起来像在忙"的兑现路径，但需要一个明确的取舍（在**原地**小幅踱步？还是允许走开？）。
2. **单位必须写进字段名**：`...Ms` 就必须是毫秒。第一版把秒留在字段里、用时再 `× 1000`，
   单测按名字写 100 毫秒、实际变成 100 秒。名字与单位不一致是纯粹的负债。
3. **"没有新指令"和"撤销覆盖"必须是两种信号**：合并成一个 `null` 会让接收方每 tick 被重置一次
   （走路会被每秒压回去 30 次）。凡"边沿触发"的命令都要显式留出"不变"这一态。
4. **探针的判据必须走产品路径**：注入点击要先用命中状态**扫出一个真的落在精灵上的点**
   （趴卧姿态的精灵贴在图集底部，窗口中心是透明的 ⇒ 那时窗口整窗穿透，按下到不了渲染层）。
   第一版探针直接打窗口中心，报出两条假失败（"拖动没生效""单击没唤醒"），真因却与它们无关。
5. **自主行为会让"位置类断言"集体变脆**，这是本轮唯一的横切代价。要么给接缝（本轮做法），
   要么让每个探针自己会找宠物 —— 前者便宜且明确，就选了前者。
