# ADR 025：文档分层路由（PLAN.md 收窄为状态索引）

- 日期：2026-09-18
- 状态：已实施
- 触发：用户提出"PLAN.md 与其他文档体量已经很大，会不会让以后交接、每次查找越来越慢重"

## 0. 结论

**是真实的成本问题，根因是结构而不是"写多了"。** 已做分层路由：**内容一条没删**，
`PLAN.md` 从 1096 行 / 109 KB 降到 149 行 / 11 KB；必读体量（`PLAN.md` + `AGENTS.md`）
**126 KB → 14 KB（-89%）**。

## 1. 实测数据（决策依据）

| 项 | 重构前 |
|---|---|
| `PLAN.md` | **109 KB / 1096 行**（单文件，比整个 `src/` 的 42%） |
| `AGENTS.md` | 17 KB / 172 行（硬约束约 40 条全量堆在一份里） |
| `docs/`（文本） | 320 KB / 4918 行 |
| `journal/` | 121 KB / 22 篇 |
| `.workbuddy/memory/` | 62 KB（每会话自动注入） |
| **文档文本合计** | **≈629 KB**，而代码（`src/` + `tools/`）只有 **417 KB** |

三个成本点：**开工成本**（126 KB 的固定税，每次新会话必读）、**定位成本**（1096 行里混着
当前状态 / 锁定决策 / 编年史 / 挂起清单）、**写入成本**（最隐蔽：因为它是"单一事实来源"，
收工协议要求往里追加 ⇒ 必然单调增长）。

## 2. 为什么不靠删内容解决

那些硬约束**每一条都对应一次实测踩坑**（ADR 008/009/011/014/017/021/022/023 的负面结论）。
删掉 = 下次重新交学费。活例子：ADR 023 清掉的"preload 诱饵文件"，正因为它被写下来才被清掉。

**根因**：把"单一事实来源"理解成了"所有东西放一个文件"。它的正确含义是
**每个事实只有一个权威位置**，不是**只有一个文件**。

## 3. 做了什么

**内容全部保留，只搬位置**（用脚本按行区间整段提取，避免手抄丢内容）：

| 迁出 | 去向 |
|---|---|
| §9 变更日志（447 行编年史） | `docs/changelog.md`（`PLAN.md` §7 只留最近三条） |
| §1「运行与构建」（操作手册） | `docs/how-to-run.md` |
| §1「人工验收怎么做」 | `docs/acceptance.md` |
| §3 后半（M3 各块详述） | `docs/status/m3.md` |
| §4（M0–M2 开工顺序与已完成区块） | `docs/status/m0-m2.md` |
| §6 锁定决策摘要（28 条） | `docs/decisions/INDEX.md`（ADR 全文仍在 `docs/decisions/`） |
| `AGENTS.md` 硬约束（40 条） | `docs/constraints/` 按六个主题分家 |

**`AGENTS.md` 从"约束全集"改成"路由表"**：一张表把「你要动什么」→「读哪份约束」
→「**跑哪些判据**」绑在一起。这是本次重构最实用的一步 ——
以前要读完 40 条才知道该跑什么，现在按任务读 1 份即可，且**约束与判据不再分离**。

六个主题：`pet-pack`（包与资产）/ `window`（窗口·命中·控制条·定时器）/ `status`（仲裁器·时间语义·
确认与出口）/ `sources-hooks`（双通道与 hook）/ `behavior`（行为层）/ `build-probe`（构建与探针纪律）。

## 4. 配套的两条节流规则（治本）

1. **收工时不再往 `PLAN.md` 追加叙述** —— 只更新 §3 状态表与 §4 挂起清单；叙述一律进 `journal/`
   与 `docs/changelog.md`（按日期追加、不回头读的台账）。**这条已写进 `AGENTS.md` 的收工协议。**
2. **挂起清单只增不改已完成的条** —— 已完成的可以归档，保持清单短。
   （`.workbuddy/memory/` 按"满 30 天蒸馏进 `MEMORY.md` 后删除"执行。）

## 5. 判据（这次的判据是"能不能接着干活"）

- 必读体量：**126 KB → 14 KB**（-89%）；`PLAN.md` **1096 → 149 行**。
- **链接有效性脚本化核对**：15 个新/改文件里引用的 62 个路径逐条检查，
  缺失项全部是文件名片段（如 `status-arbiter.test.mjs` 实际在 `tools/`），非断链。
- **内容零丢失校验**：迁出的 7 块都是脚本按行区间整段搬，不是重写；
  原文件仍在 git 历史（`git show 9f2576f:PLAN.md`）。
- 工程功能未动（纯文档重构），因此不跑代码回归。

## 6. 副作用与已知代价

- **接续入口变了**：开工话术与"先读 PLAN.md §6"这类指引已同步更新（§1 与 `AGENTS.md`）。
- **`PLAN.md` 的定位从"档案"变成"索引"**：想查"当时为什么这么做"要去 `journal/` 或 `docs/changelog.md`。
  这是刻意的取舍 —— 索引该薄，档案该厚。
- 文档**文件数增加 12 个**，但每个都小且按需读；总量不变（内容没删）。

## 7. 一条方法论

**"单一事实来源"不等于"单一文件"。** 这个项目连续四天把每轮产出往 `PLAN.md` 里追加，
到第四天它就成了 109 KB —— 每一轮单独看都是对的（"写回 PLAN.md"是硬纪律），
但没有任何机制让它**变薄**。判断标准应该是：**每次开工必读的那份，必须保持小**；
其余内容可以厚，因为它们是按需读的。
