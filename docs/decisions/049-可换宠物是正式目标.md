# ADR 049：可换宠物是正式目标 —— 先建判据，再建界面

- 日期：2026-09-29
- 状态：已采纳
- **取代 ADR 046 的「不打算做成可换宠物的平台」**（那句保留为历史，见下）
- 相关：ADR 002（不污染 `pet.json`，自研参数走 sidecar）、ADR 003（根目录引用网）、
  ADR 015（M2 ⑤ 多宠物切换，搁置）、ADR 036（自启值名 = exe 版本资源 ProductName）、
  ADR 010（宠物包投毒防护）、ADR 047（判据必须能自证新鲜）、
  `docs/constraints/pet-pack.md`、`tools/pet_sheet_probe.py`

## 背景

用户提出（2026-09-29）：想把工程做得「非常完备且具有可塑性」，
并明确提出**换宠物**的需求 —— 不只是"软件里能切到别的宠物"，
还包括「制定其他宠物的制作要求」「把其他宠物导入进来的框架」。

**这个决策与已锁定的 ADR 046 相反**，所以必须先说清楚为什么改。

ADR 046（2026-09-28）的原话是「不打算做成可换宠物的平台」，
理由是「换任意宠物包」从**卖点**降级为**内部实现细节**。
⇒ 它当时是对的：那是在回答"对外定位是什么"，而定位答案确实不该是"什么都能换"。

**但用户现在问的是另一个问题**：不是"对外怎么说"，而是
**"这个工程将来能不能被别人接手、能不能长出我没想到的东西"**。
可塑性服务的是**你**（和未来维护者），不是访客。
一个换不了宠物的工程，它的每一处实现都只能是"这只宠物专用"——
美术规格、锚点、动作数量一旦定下就锁死。**这是工程属性问题，不是产品定位问题。**
⇒ 改判：**对外定位仍是「这是叫淘淘的软件」（ADR 046 那句保留），
但内部必须做到"换包不换码"**。

## 核实：基础比预想的完整

动手前逐条查了代码，**结论是这件事已经有一大半**，不是从零设计：

| 能力 | 现状 | 位置 |
|---|---|---|
| `loadPack(packDir)` 收**目录参数** | ✅ 非写死路径 | `src/kernel/pack.ts:40` |
| `--pet=<目录>` 启动参数 | ✅ 已存在 | `src/main/index.ts:59` |
| 网格规格 | ✅ 由 `spriteVersionNumber` 推导（V1 1536×1872 / V2 1536×2288） | `src/kernel/image-size.ts:74` |
| 状态 → 行号 | ✅ 全走 `behavior-map.json` 的 `row`，**代码零硬编码行号** | renderer 用 `f.row` |
| 路径穿越防护 | ✅ `resolveInside` | ADR 010 |
| 契约校验器 | ✅ `tools/validate_pet.py` | — |
| 模板生成器 | ✅ `make_pet_template.py`（blank / guide） | — |

**全仓只查出一处真正的绑死**（本轮已修，见下）。
⇒ 这条决策的成本**不在功能**，在**规范与判据**。

## 决定

### 一、修真 bug：托盘图标必须随包走

`src/main/index.ts` 原先写死 `join(__dirname, '..', '..', 'assets', 'tray.ico')` ——
而 `tools/make-tray-icon.py` 的开头**自己就写着**
「换一只宠物包就该换一次图标，手画等于每换一次包就欠一笔债」。
**两边是矛盾的**：用 `--pet=<别处>` 换包后，托盘上还是上一只宠物的脸，**且无任何报错**。
托盘图标是用户在任务栏唯一能看见的那个形象。

改为：**包内 `tray.ico` → 工程 `assets/tray.ico`（向后兼容）**，
两条都没有时打印明确提示（而不是静默用一个错的图标 ——
**静默用错的比没有更难排查**，同 ADR 042 的形状）。
**不碰** ADR 036 的自启值名机制（它取自 exe 版本资源，与此无关）。

### 二、先建判据，不先建界面

新增 `tools/check-pet-swap.mjs`：**不启动 Electron**，对**任意**宠物包做体检。
接进 `tools/status-arbiter.test.mjs` ⓪d 节（主单测 452 → **456** 项）。

它专门堵 `loadPack` **不管或只 warn** 的四条缝：

1. **少配一个状态不会报错。** `pack.ts:87` 对「behavior-map 有、desktop-pet.json 没有」
   的状态只 `warnings.push` 后 `continue` ⇒ **宠物静默少一个动作**。
   这是换宠物最常见的翻车方式：包能加载，宠物没了"挥手"或"左右走"。
2. **`loadPack` 只强制要求 `idle`。** 而 **5 个业务状态**（`PET_STATUSES`）
   与 **9 个面板动作**全靠 `statusMap` / `actions.list` 指过去 ——
   少配一个 ⇒ 该状态永远不出现、面板少一个按钮，**同样无报错**。
3. **statusMap 悬空**：指向不存在的动画状态 ⇒ agent 进入该状态时宠物无动作可演。
4. **锚点不自洽**（`offsetY ≠ groundY - baselineY`）在加载时才抛，静态阶段先算一遍。

**判据体检工程根自己** —— 理由：「换宠物」的全部意义是
"别的包也要能过同一套检查"，**自己过不了的判据没有资格要求别人过**。

⚠️ **本轮只交付静态部分**。运行时「切换宠物」UI（托盘菜单加一项、扫描目录、
重建窗口与仲裁器）**不在本 ADR 范围内**，理由见「后果」。

### 三、不重复 `loadPack` 已有的校验

魔数、尺寸、体积、路径穿越、行号/帧数一致性 —— **判据不该把它能查的重复一遍**
（ADR 044 §2 纪律：判据不该被它测以外的东西判红）。
新判据只做 `loadPack` 做不了的：**跨配置的一致性**与**"缺了会静默"的那些洞**。

## 后果

- **主单测 456 项**，⓪d 会对工程根做宠物包体检。
- **未实跑验证**：本轮改的是**主进程托盘装配**，按 `docs/constraints/build-probe.md`
  的纪律，托盘/窗口路径改动**应跑** `spikes/m2-menu/run-tray.mjs`。
  **本轮未跑**（用户决定不跑 GUI 探针）⇒ **这一条要记在账上，不是"已验证"**。
- 运行时切换 UI 仍是**未做**。它的风险明确：会动窗口生命周期，
  而 **ADR 035 / 038 / 042 三个崩溃都出在这条路上**，且每次改动需跑五套真实窗口回归。
  ⇒ 建议顺序：**先有 ≥2 个真实宠物包跑通 `check-pet-swap` → 再考虑 UI**。
- `examples/demo-pet` 与 `examples/broken-pet` **仍然缺 sidecar**（只有 `pet.json` + 图集），
  `check-pet-swap` 会正确报 FAIL。这不是判据的 bug ——
  它们是"图集契约样例"，不是"可运行宠物包"。**要造完整样例应复制工程根三份配置再改。**
