# 016 · 控制条交互模型修订：去掉悬停唤出，右键宠物唤出，面板显示宠物名

- **状态**：已接受
- **日期**：2026-09-17
- **决策人**：用户（产品判断：三条唤出入口互相遮挡、悬停多余）+ agent（实现与判据）
- **影响**：`src/kernel/bar-policy.ts`（大幅缩小）、`src/main/index.ts`、`src/shared/ipc.ts`（`BarView`）、
  `src/renderer/control-bar.{html,ts}`、`src/renderer/renderer.ts`（注释与语义）、`desktop-pet.json`、
  `spikes/m2-control/probe-{control,key-path}.js`、`tools/status-arbiter.test.mjs`
- **设计文档**：`docs/design/m2-control-bar.md`（§3 双路径显示、§4 状态机已被本次修订取代）
- **修订**：ADR 014 第 2 条（双路径显示）与第 4 条（`armed` 位）—— 两者的前提都是"悬停唤出存在"

## 背景

M2 ④ 人工复验后，用户提出三件事（原文要点）：

1. "我不需要控制条在我每次鼠标悬浮在上面的时候就出现，这个完全不需要的功能"；
2. "我可以右键宠物，然后出现控制条。但是右键托盘菜单呢，出现的是现在的右键菜单"——
   两处右键要做不同的事；
3. 面板上那个只读的 `70%` 缩放文本没意义，"你可以直接显示这个宠物的名字淘淘"，
   并明确"把悬浮条当做一个框架性的功能，以后想加东西再加"。

## 决策

### 1. 悬停唤出**整条路径删除**（不是调参、不是默认关）

用户给的选项是"彻底去掉悬停"或"悬停 2–3 秒才触发"，本 ADR 选**前者**。三条理由：

1. **光标经过宠物是"顺便"发生的**：桌宠常驻屏幕角落，拖窗口、去任务栏、切应用都会路过它。
   任何基于悬停的自动弹出都必然产生"我没叫它、它自己冒出来"的体验。延迟只是降低频率，
   不改变性质 —— 而"不主动干预的陪伴"是这个产品的核心诉求。
2. **与左键单击的新语义打架**：左键单击宠物要播一个动作（见第 5 条）。若"把光标停在宠物上"
   还会触发另一种 UI，用户"瞄准再点"的这个动作就同时带着两个含义，语义上必然有歧义。
3. **入口收敛**：三条唤出路径（悬停 / 快捷键 / 菜单）+ 两张菜单面（宠物右键、托盘右键）
   被用户判断为"没必要这么复杂"。收敛后是**两条语义清晰的入口**：
   宠物右键 = 控制条；托盘右键 = 完整菜单。

**代价（如实记录）**：少了一条"零记忆负担"的发现路径 —— 新用户不再能靠"鼠标扫过宠物"
发现面板。补偿是：面板里放了一个「⋯」直达完整菜单，且右键宠物这个手势在桌宠类产品里
是通行约定。

### 2. 面板唤出一律**抢焦点**；关闭路径共五条

悬停消失后，"可能正在打字"这个前提不再成立 —— 三条唤出路径（右键宠物 / `Win+Alt+P` /
托盘菜单「控制条」）都是用户明确的动作，所以**只有一种显示模式**：`show()` + 抢焦点。

| 关闭方式 | 实现 |
|---|---|
| 按 Esc / 点面板 × | `request-close` 事件 |
| 再唤出一次（右键宠物 / 快捷键 / 菜单项） | `toggle` 取反 |
| 点到别处 | 窗口失焦 → `blurHideMs`（200ms）后收起 |
| 宠物被隐藏（托盘 / 右键 / 全屏让位） | `pet-hidden` 事件 |
| 面板里的「隐藏宠物」 | 同上（宠物不在，面板不该锚在半空） |

抢焦点换来的正是"点到别处即关"与"Esc 可收" —— 面板因此像**一个真窗口**而不是贴纸。

### 3. 状态机从"七条规则 + 两个补丁位"缩到**五条规则**

`kernel/bar-policy.ts` 删掉了 `hoverSince` / `hideAt` 的悬停分支 / `suppressUntil` / `armed`。
`armed` 与 `suppressUntil` 当年是为两条**悬停专有**的易错规则存在的
（"快捷键收起后不被悬停弹回来"、"宠物让位回来不自动冒出来"）；悬停不存在，它们要防的场景
也不存在，所以**连同机制一起删掉**，而不是留着当死代码。

### 4. 面板的"身份位"：从只读缩放值换成**宠物包里的名字**

面板动作排现在是 `[隐藏宠物] … [宠物名] … [⋯]`。名字取自 `pet.json` 的 `displayName`
（当前是"淘淘 New"），**不是硬编码"淘淘"** —— 换宠物包时它自动跟着变。
缩放操作只在菜单里（托盘右键 / 「⋯」），面板不再出现大小相关的任何东西。

### 5. 左键单击宠物 = 播一次「拜一下」+ 确认（`ack`），**不唤出任何面板**

第 3 行 `waving` 在淘淘 New 里画的正是**双手抱拳致意**的姿态（依据 `docs/status-reference.png`，
不按状态名猜外观）。这一条改动**实际上只有语义澄清**：单击本来就在播 `waving`
（`ready` 状态也映射到它）。

保留 `ack()`（单击同时解除 `needs-input` 粘滞）的理由：**用户的注意力确实落在了宠物身上**，
"我看到了"这条语义与"陪一下"并不冲突，而且它是 `needs-input` 最顺手的解除入口
（另一处是面板里的「确认」）。
**如果用户想要"单击纯粹只是玩一下"，摘掉这一行 `window.pet.ack()` 即可** —— 已在此记录，
免得下次有人以为它必须留着。

### 6. `⋯` 弹原生菜单时必须屏蔽"失焦即收"

原生菜单弹出时，Windows 把它算成"弹出它的窗口失焦"。不屏蔽的话，面板会在菜单弹出的同一瞬间
吃到 `blur`，`blurHideMs`（200ms）后连菜单一起消失 —— 表现就是"⋯ 点了没反应"。
做法：主进程加一个 `barMenuOpen` 位，菜单开着时忽略 `focus` 事件；菜单关闭的回调里**按当时的
真实焦点补一次记账**，避免反向留下"面板以为永远失焦"的账。

> **实测与推断的界线（本项目的纪律）**：本 ADR **实测**的是"菜单打开 1.2 秒后，面板仍然可见"
> （`probe-control.js` ⑪，真实 DOM 点击⋯）。"不屏蔽就一定会被收掉"是**推断**，没有单独验证
> （要验证得先临时摘掉屏蔽再跑一轮）。所以这条屏蔽是**防御性**的，判据只钉住"菜单开着时
> 面板必须活着"这个可观测结果。

## 实测（2026-09-17，`spikes/m2-control` 两个探针全 PASS）

- **悬停不再唤出**：光标停在宠物中心 1.8 秒 → 面板不可见；再停在"面板消失前那块矩形"内
  1.8 秒 → 仍不可见（同时把旧的"幽灵悬停区域"回归用例换了方向：从前验"不许被旧矩形叫回来"，
  现在验"任何悬停都不许叫出来"）。
- **右键宠物 = 唤出**：真实注入右键 → 面板出现且 `isFocused()=true`；再右键一次 → 收起。
- **键盘路径不变**：右键唤出后注入按键收得到（keyDelta=1）；`hide→show` 往返后照旧收得到
  —— ADR 009 那个"隐藏后输入通路失效"仍然**不适用**于键盘路径，控制条依旧不需要 reload。
- 位置（下间距 8 / 水平偏差 0 / 高度 72↔128）、翻转、跟随、`WS_EX_TOOLWINDOW=0x188`、
  命令白名单、点 × 立即收起且**不会自己弹回来** —— 全部与上一轮一致。
- 面板显示 `淘淘 New`（= `pet.json` 的 `displayName`），不再是 `70%`。
- 单测 **131 → 138 项**（删掉悬停相关的 8 条，补入新规则与新字段的断言）。

## 负面结论

1. **"少一条发现路径"是这次改动的真实代价**，不是没有代价。它换来的是"绝不会自己冒出来"，
   对新用户不如从前友好；补偿只有「⋯」按钮与右键约定。若将来要做引导，应该是
   "首次启动提示一次"，而不是把悬停加回来。
2. **删机制比留开关好**：`showOnHover: false` 这个 sidecar 开关也被删了 ——
   留一个"开关式的、永不使用的路径"等于把复杂度从代码搬进了配置，下一个人仍然要读它。
3. **探针里的"前置"必须走产品路径**：本轮把控制条探针所有"确保可见"的前置统一改成
   **真实右键宠物**（`ensureBar()`），而不是直接调调试钩子。这样手势一旦失效，
   整个探针会立刻报错，而不是静默地用另一条路径把用例跑绿。
