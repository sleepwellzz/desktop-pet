## 6. 锁定决策摘要（详见 ADR）

1. **Electron 先行 + 内核纯 TS 解耦**，保留 Tauri 2 迁移路径。（ADR 001）
2. **不污染 `pet.json`**，自研参数走 sidecar（`behavior-map.json` / `desktop-pet.json`）。（ADR 002）
3. **行级固定锚点** `groundY = 202`，禁止逐帧基线锁定。（ADR 002）
4. **根目录暂不整理**，因存在相对引用网。（ADR 003）
5. 点击穿透的实现方式几经修订（**别再用前两条**）：
   ~~`WM_NCHITTEST` 采样 alpha~~ → ~~`WS_EX_LAYERED` 原生命中测试~~（ADR 008 证明其生效区域是整个窗口矩形）
   → **命中判定由渲染层按当前帧精灵 alpha 显式给出**，窗口常态 `setIgnoreMouseEvents(true)`
   整窗穿透，主进程 16ms 轮询光标驱动采样。（ADR 008）
6. **位移速度按屏幕像素/秒归一化**（默认缩放 0.7）。
7. **渲染层与 preload 用 esbuild 打包**，内核纯 TS 不 import electron，init 走"渲染层报到 → 主进程下发"握手。（ADR 005）
8. **命中区域 = 精灵轮廓**（单点判定，不做邻域膨胀）；窗口移动一律用 `setContentBounds` 并复位内容尺寸，
   防止 150% 缩放下 DIP↔物理取整误差累积。（ADR 008）
9. **宠物窗口每次重新显示后必须重载渲染层页面**（`overlay.reload()`）+ 强制重报命中状态。
   实测 `hide()` → `showInactive()` 会切断 Windows 对**真实鼠标按钮事件**的路由（移动事件不受影响），
   只有重建渲染层能可靠恢复。（ADR 009）
   **注意适用范围**：实测该现象**不适用于键盘路径**，也不适用于不接收按钮事件的窗口 ——
   气泡层与 M2 ④ 的控制条都不需要 reload（ADR 014 负面结论 1）。
10. **控制条是本项目唯一可聚焦的窗口**，也是唯一不适用第 5 条逐像素纪律的窗口
    （矩形直角面板，窗口矩形 ≈ 可视矩形；代价是不做圆角）。
    **唤出一律抢焦点**（2026-09-17 修订，ADR 016 —— 取代 ADR 014 的"双路径显示"）：
    三条唤出路径（右键宠物 / `Win+Alt+P` / 托盘菜单）全是用户的显式动作，
    "可能正在打字"那个前提随悬停一起消失了。
11. **`Win+Alt+P` 的语义 = 唤出/收起控制条**（修订 ADR 012 的"切换宠物显示/隐藏"，规格 §3.4）。
    隐藏宠物仍有三个入口：托盘单击 / 右键菜单 / 面板里的按钮。（ADR 014）
11b. **两处右键分工不同**：**宠物右键 = 控制条**；**托盘右键 = 完整菜单**（面板「⋯」也是这份）。
    **不要再把悬停唤出加回来** —— 自动弹出必然变成"我没叫它它自己冒出来"，
    而且与"左键单击播动作"在同一个目标上争抢语义。（ADR 016）
11c. **左键单击宠物 = 播「拜一下」（第 3 行 `waving`）+ 确认**，不唤出任何面板。
    想改成"纯粹玩一下"，摘掉 `renderer.ts` 里那一行 `window.pet.ack()` 即可。（ADR 016）
12. **控制条显示策略是纯函数状态机**（`kernel/bar-policy.ts`），现在只有五条规则
    （`toggle` / `request-close` / `focus` 进 / `focus` 出 / `pet-hidden`）。
    ~~`armed` 位与 `suppressUntil`~~ **已随悬停一起删除**（ADR 016）——它们防的是
    "快捷键收起被悬停弹回来""宠物让位回来自动冒泡"这两个**悬停专有**的场景。
    新增：**`⋯` 弹原生菜单期间屏蔽"失焦即收"**（原生菜单会夺走面板焦点，不屏蔽则面板连菜单一起消失）。
13. **控制条必须显式设 `WS_EX_TOOLWINDOW`**：`skipTaskbar: true` **不会**加这个样式位，
    只靠它控制条会出现在 Alt+Tab 列表。（ADR 014）
14. **不要用 `win.isVisible()` 做显示记账** —— `show()` 之后同一 tick 内它可能仍返回 `false`，
    会让抢焦点的路径重复 `show()` 一次（第二次是 `showInactive`，正好把刚拿到的焦点让出去）。
    用窗口的 `show`/`hide` 事件记账。（ADR 014）
15. **状态快照里"没有 `ts`"不等于"刚刚"**：无 `ts` 的条目按**快照写入时刻（mtime）**兜底，
    且**不参与"ts 变了算心跳"那条分支**（同一份文件里所有会话共享一个 mtime）。（ADR 017）
16. **「清空状态会话」必须清三处**：文件 → 适配器的记忆（`StatusSource.reset?()`）→
    仲裁器的记录（`StatusArbiter.clearSessions()`），缺一处用户看到的都是"没清干净"。（ADR 017）
17. **行为层分两套模式**（2026-09-18 修订，ADR 019 —— 取代 ADR 018 的"`status !== 'idle'` 就完全不动"）：
    `idle` → 空闲模式（漫游 / 微动作 / 打盹）；非 idle → **踱步模式**（低频、短距离、锚在进入任务状态
    时的位置附近）。规则做成**纯函数**（`kernel/behavior.ts`，时钟与随机数可注入），
    接线与渲染层都不做判断。（ADR 018 / 019）
18. **打盹计时只由"状态离开 idle"与"用户碰它"重置** —— 漫游/微动作**不得**重置它，
    否则 25–90 秒走一次会把 5 分钟推后成"永远睡不着"；有任务时压根不计。（ADR 018 / 019）
19. **动画覆盖走独立通道 `CH.behavior`，且命令是三态**（缺省 = 不变 / `null` = 交回仲裁器 /
    对象 = 按它演）。合并成两态会让接收方每 tick 被重置一次。（ADR 018）
20. **绝不在用户抓着的候自己动**：拖动的开始/结束由渲染层**显式上报**（`CH.dragState`），
    不靠"多久没收到拖动增量"去猜 —— 用户手停一下是常态，猜错就是宠物在他手里自己走。（ADR 018）
21. **回归探针要带 `--no-behavior`**：宠物会自己走，位置类断言（命中图、控制条贴边、
    托盘点击坐标）全都变脆 —— 探针读一次窗口位置、再按它算点击坐标，中间宠物走掉了就点空。
    与 `--no-status-source` 同一套路。（ADR 018）
22. **踱步的目标必须由"锚点"算，不能由"当前位置"算** —— 后者会越踱越远，
    让用户要求的"不超过几百像素"在几分钟后悄悄失效，而且屏幕上只表现为"它怎么跑那么远"，
    没有任何报错可循。锚点在**进入任务状态时**与**每次抑制结束后**重记。（ADR 019）
23. **不跨屏是锁定范围，不是"暂时不做"**：只在宠物所在显示器的工作区内活动，
    把宠物拖到哪块屏它就在哪块屏活动（锚点重记是它的落地机制）。
    真要做跨屏得先定义"穿越时窗口矩形算哪一屏"与"多屏工作区并集"。（ADR 019）
24. **状态源是两条通道，不是每个 agent 一套适配器**：**A 事件驱动 hook**（WorkBuddy / Codex /
    将来的 Claude Code —— **同一套事件名与 stdin 契约**，所以是"1 份映射 + N 个配置路径"）｜
    **B 被动会话源**（Proma）。两条都产出 `StatusEvent`，内核不动。（ADR 020）
25. **一个 agent 只由一条通道负责，两条通道互斥。** 两个**不同** agent 天然不冲突
    （仲裁器从 M2 ① 起就是多会话形状，`+N` 角标即为此）；会打架的是**同一个 agent 被两条通道
    同时盯** —— hook 说 running、被动源说 idle，来回刷且无任何报错。
    被动源是"降级来源"，**是切换不是叠加**。（ADR 020）
26. **`sessionId` 必须带来源前缀**（`wb:<pid>` / `proma:<uuid>`），**标题必须带来源名**。
    不带前缀时两个 app 的 UUID 万一相撞会互相覆盖；标题不带来源则两个 agent 同时在跑时分不清谁是谁。
    副产品：用户"只想连某一个 agent"就是一次按前缀过滤，不需要新机制。（ADR 020）
27. **hook 客户端 / 映射层不许有能力影响 agent**：客户端**退出码恒 0**（Claude 系约定里 2 = 阻断，
    我们只观测）、有超时上限、任何异常都吞掉；映射层未知事件**忽略而不是报错**。
    配置只写**工程级**（用户级会作用于用户正在用的所有会话）且默认 `settings.local.json`
    （命令含本机绝对路径，已 gitignore）；安装器**默认 dry-run**、幂等、可卸载、带备份。（ADR 020）
28. **判断一个信号的时间分辨率，要看它的更新频率，不是看它当前的年龄。** 这条是踩坑换来的：
    "心跳文件看起来很新"推不出"它一直在写" —— 实测 151 秒里只刷新 5 次（粒度约 30 秒）。
    同源的纪律：**被动源给的"存在"不等于"在干活"**，把它当 running 判据会制造假阳性。（ADR 020）
29. **无控制台启动的正确姿势是 `Start-Process` + `-ArgumentList '.'` + `-WorkingDirectory`**，
    **不是 `start`**（关窗会把宠物一起带走）。`-ArgumentList '%CD%'` 也不行：
    工程路径含空格，PowerShell 会**按空白把参数拆开**（实测报 `Unable to find Electron app at <工程目录>`）。
    **推论：打包成 GUI exe 后这条根因消失**（由 explorer 直接启动，没有父控制台这回事）。（ADR 028 / 029）
30. **双通道冲突时按通道优先级逐出，不按到达顺序**：hook 高于被动源，低优先级的上报被**丢弃**
    （在所有记账之前，否则会污染迟滞窗口）；主导通道沉默超过 `holdMs`（10 分钟）才释放 ——
    这是"hook 卸载/崩溃后被动源必须能接管"的安全底线。**告警必须在逐出之前**
    （否则一旦逐出生效，冲突永远不再报警）。（ADR 027 / 030）
31. **主观判据要连口径一起记，不能只记结论。** 判据 9 的第四问用户答"没用过快捷键"，
    这回答的是**使用频率**，不是**误触率** —— 二者没有蕴含关系，如实记"未取得数据"而不是"通过"。
    同源纪律：**事件占比 ≠ 气泡在屏幕上待了多久**（中间隔着仲裁层的出口：
    `ready` 60s / `needs-input` 5min / `running` 气泡 2s）。（ADR 031）
