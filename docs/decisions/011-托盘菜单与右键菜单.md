# 011 · 托盘菜单与右键菜单

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：用户 + agent
- **影响**：`src/host/{tray,pet-menu,prefs,autostart}.ts`（新增）、`src/host/{overlay-window,fullscreen}.ts`、
  `src/shared/ipc.ts`、`src/main/{index,preload}.ts`、`src/renderer/renderer.ts`、`tools/make-tray-icon.py`、`assets/tray.ico`
- **设计文档**：`docs/design/m2-tray-menu.md`（开工前先出设计，用户确认三点后才动手）

## 背景

M2 ② 的目标是"用户能掌控这只宠物"的最小集合。其中"退出"是硬性验收项（PLAN §8：
不能被误判为流氓软件）。设计阶段确认了三个点：切换宠物本轮不做（单独一轮）、
右键菜单先探针验原生方案、缩放档位收到 0.5–1.5。

## 决策

### 1. 托盘与宠物右键共用一套菜单模板与一张动作表

`src/host/pet-menu.ts` 出模板，`tray.ts` 与 `main/index.ts` 的右键处理都用它；
菜单里的每个值（可见性、缩放、自启、状态行）都由主进程通过 `getView()` **现读**，
菜单自己不持有状态 —— 延续 ADR 010"仲裁器是全应用唯一真值来源"的约定。

本轮落地项：状态行（只读）、隐藏/显示、宠物大小（0.5–1.5，按宠物包声明生成）、重置大小、
开机自启（勾选）、退出。**托盘图标左键单击 = 切换显示/隐藏**（Windows 上左键不弹菜单）。

### 2. 右键菜单用原生菜单，不用自绘

宠物窗口带着 `WS_EX_NOACTIVATE | WS_EX_TOPMOST`，原生菜单能不能弹出/点击是纯平台行为，
按工程约定**先探针实测**（`spikes/m2-menu/probe-menu-native.js`）：

- 截图为证：菜单**弹出成功**（在屏幕右下角会整体上移以避开屏幕边缘）；
- 真实点击命中菜单项：偏移 **(+76,−103) / (+40,−103) / (+100,−103) → ITEM-B**、**(+76,−39) → ITEM-C**；
- 菜单交互之后再点宠物，渲染层仍收到 `pointerdown` → **输入通路未被破坏**。

结论：原生菜单可用，省掉整套自绘菜单（自绘要占用宠物以外的画布 ⇒ 必须改窗口尺寸 ⇒
直接触碰 ADR 008/009 的命中边界）。

右键的**触发点在渲染层**：窗口常态整窗穿透，只有渲染层知道这一下右键落在精灵轮廓上还是空白处
（ADR 008）。新增 `pet:context-menu` 通道，不带坐标（Electron `popup()` 默认在光标处弹出）。

### 3. 显示与缩放共用唯一的恢复入口 `resumePet()`

ADR 009：`hide()` → `show()` 之后 Windows 不再把**真实鼠标按钮事件**路由到窗口，唯一可靠恢复是
重载渲染层。因此 `resumePet()` = `overlay.show()` → `overlay.reload()`（reload 触发渲染层重新报到，
由 `CH.ready` 统一补发 init / 强制重报命中 / 补推状态）。**托盘显示、宠物右键、全屏让位恢复三处共用**，
任何地方不再单独写 `win.show()`。

缩放变更走同一条：改尺寸 → 重建 init 载荷（`payload = null`）→ `resumePet()`。

### 4. 缩放的窗口处理

尺寸 = `round(cell × scale)`，一律 `setContentBounds`（ADR 008）；锚点取**窗口底边中点**
（宠物像站在原地长大），再夹进宠物当前所在显示器的工作区。
实测：0.7 → 1.0 时底边中点漂移 0（贴边时允许被工作区夹住几像素，这是防跑出屏幕的夹取）。

### 5. 缩放偏好存 `~/.desktop-pet/prefs.json`

不写进工程的 `desktop-pet.json`：那是宠物包的 sidecar 且已进 git，运行期偏好写进去会造成
版本库 churn，换个包还会丢。"重置大小"= 删掉该项，回到宠物包声明的 `defaultScale`。

### 6. 开机自启走注册表 Run 项，勾选态一律回读

用 `app.setLoginItemSettings` / `getLoginItemSettings`（不写文件、不写服务、不写计划任务）。
**开发态与打包态的注册命令不同**（实测核对见下）：开发态必须带应用路径，打包态不能带。
勾选态不缓存，每次都回读（用户可能从系统设置里直接改）。

## 负面结论（本轮踩到的坑，别再踩）

1. **`pointermove` 的 `e.button` 是 −1**。
   给拖动处理加"只处理左键"的判断时顺手把 `pointermove` 也判了 → 整段拖动静默失效。
   症状极具欺骗性：`pointerdown/pointerup/pointermove` 计数**全都正常**（down=1 up=1 move=10），
   但窗口一动不动。`dragging` 只有左键按下才会置真，`pointermove` 里不需要重复判断。
2. **命中判定只跟着光标走，不跟着动画走**（`probe-tray.js` 抓到）。
   判据是"当前帧的精灵 alpha"，而光标停着时动画仍在换帧 —— 用户点一下宠物（切到挥手姿态）
   后不移动鼠标直接拖动，光标下的像素已变空白 → 窗口被切成穿透 → 按下直接穿透过去。
   修法：渲染层每帧用"最近一次已知的光标位置"复评一次（代价只有一次 alpha 查表，
   `setInteractive` 只在真正变化时发 IPC）。
3. **全屏误判：桌面被当成全屏应用**（同一次探针顺带抓到）。
   点任务栏右下角的"显示桌面"条之后，前台窗口变成 **WorkerW**（2560×1600、空标题），
   `GetShellWindow()` / `GetDesktopWindow()` 两个排除项**都拦不住它**（WorkerW 是 Progman 的子窗口，
   是第三个 HWND）→ `coversMonitor=true` → **宠物自己隐藏**。用户视角是"点一下桌面，宠物不见了"。
   修法：按窗口类名排除 `WorkerW/Progman/Shell_TrayWnd/Shell_SecondaryTrayWnd`。
4. **`GetClassNameW` 的返回值不含结尾空字符**，按 `(len−1)*2` 截断会把 `WorkerW` 读成 `Worker`，
   白名单恒不匹配 —— 这个差一错误让上面那个修复**静默失效过一轮**（"改了但没生效"，
   只有把类名打进日志才看得出来）。现在探针会把 `fgClass` 打印出来。
5. **菜单在屏幕边缘会翻折**，凭直觉猜点击偏移必然全错（第一版 5 个候选点全部落空）。
   要么按截图量出的几何去点，要么在屏幕中间做能力验证。
6. **测批处理菜单不能用 `spawnSync(..., { input })`**：stdin 立即 EOF，菜单会无限空转跑满一个核。

## 后果

- 宠物隐藏后唯一的入口是托盘；托盘创建失败会**只降级不致命**（日志明说"隐藏后将无入口可恢复"）。
- `--expose-actions` 是给探针的接缝（把动作表挂到 `globalThis`），仅探针使用。
- 遗留项（打包那一轮要复核）：注册表值名在开发态是 `electron.app.Electron`，打包后应为 productName；
  托盘图标与 `assets/` 目前不随构建产物拷贝，打包时要一起带上。
- 未做且**刻意不做**的：多宠物切换（单独一轮）、设置/宠物管理窗口、气泡与角标（属 ③，要改窗口尺寸）。
