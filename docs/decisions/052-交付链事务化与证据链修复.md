# ADR 052：交付链的事务性、证据链的修复，以及审计 P1 的批处理

- 日期：2026-09-29
- 状态：已采纳
- 相关：ADR 044（"打包成功"必须回读产物本身）、ADR 047（判据必须能自证新鲜）、
  ADR 048（入库证据是决策链）、ADR 049（换宠物）、ADR 051（单实例锁）、
  `docs/reviews/2026-09-28-全面代码复核.md`（P0-1 / P0-5 / P0-9 / P1-1~P1-20）

## 背景

用户 2026-09-29 的要求是"**把目前的所有 bug、探测和验证全部跑完**"，
并在此之前已授权：按我推荐的顺序推进，`12 条 P0` 收口优先。

审计剩两件事：**P0-1**（三份入库证据把"崩溃过"说成"通过"）与
**P0-5**（打包非事务性，失败会留下"看起来成功"的半成品）；另有一条 **P0-9**。
在此之上顺带处理了一批 P1。

## 决定

### 一、交付链事务化（P0-5 / P1-1 / P1-2 / P2-12）

`tools/make-portable.mjs` 原先是**零个 `try` 块**、全程直写最终路径。三个具体后果：

| 后果 | 修法 |
|---|---|
| `rcedit` 失败时 `OUT` 里已有改好名的 exe、但版本资源还是 Electron 的 ⇒ **自启值名会变成 `electron.app.Electron`**（正是脚本自己注释里要避开的坑），而那个目录能双击、看不出异常 | 所有写操作指向 `.staging-<pid>`，**全部成功后才原子换入** |
| 运行中打包：`rmSync(OUT)` 失败时**已经删掉一半旧包** | 换入时先把旧产物 `rename` 到 `.old-<pid>`（原子），失败则**旧产物分毫未动**并给出可读提示（"请先退出正在运行的桌宠"） |
| zip 只回读 4 字节魔数 ⇒ **截断包与完整包在它眼里一样** | 新增 `verifyZip()`：头签名 + **末尾 EOCD 签名** + 中央目录偏移自洽；zip 先写 `.tmp`、校验通过才换名，**换名后再回读最终文件本身** |

顺带（P1-2）：**发行包默认排除 `*.map`**。esbuild 的 sourcemap 内嵌 `sourcesContent`
⇒ 实测发行包里躺着约 **56 KB 完整 TypeScript 源码**（连注释里的设计决策一起）。
绿色版是任人转发的产物，"把内部实现随包发出去"不该是默认行为；确实要调试用 `--keep-maps` 显式要回来。

### 二、证据链修复（P0-1 / P0-9）

**重跑**了全部 Electron 探针，产出真实新证据覆盖被污染的那几份 ——
**并且给每份 `.out` 加了文件头指纹**：

```
// ran-at: 2026-09-29T20:38:59+00:00
// git-head: a8e6498df7fa1756827ad76e88f5f42e557c1372
// cmd: node spikes/m2-menu/run-tray.mjs
```

**为什么把指纹写进文件内容而不是靠 mtime**：ADR 047 已经用实测否掉了 mtime
（那批证据内容是 09-18 的、mtime 是 09-22 的，且 `git checkout` 会重写它）。
时间戳与 git hash 进内容之后，"这份证据属于哪一次"变成了**可 grep 的事实**。

### 四、顺带修掉的三个"判据自身的缺陷"（都不在审计清单里）

1. **`stripComments` 会吞掉代码**（单测的结构性检查工具）。
   原实现 `replace(/ 块注释 /g, '')` 跨行匹配，而本工程注释里会写出
   「`dist/` 紧跟两个星号」= 一个块注释开始符 ⇒ 它后面第一个 `*/` 之间的**几百行代码被整段删掉**。
   实测：改 `make-portable.mjs` 后 **9 条打包断言全部失败，根因是"被断言的那段代码本身被剥掉了"**。
   ⇒ 改为逐行处理（只删整行注释）。**这类失效不报错**，只是安静地找不到字符串，看起来像代码写错了。
2. **`spikes/m2-status/run-status-e2e.mjs` 用 `spawnSync` 调 hook** ⇒ 在本沙箱里进程根本没起来，
   六个步骤全判 `hook 调用失败：null` ⇒ **整条判据 FAIL，而它要测的东西从未被触发**。
   改成异步 `spawn`（与 `make-portable.mjs` 的 `rcedit` 同款处置）后 6/6 通过。
3. **两套状态探针的断言与 ADR 024 之后的设计不同步**：它们仍期望"过期的会话留在面板视图里、只是标了 expired"，
   而 ADR 024 修 #14 改的正是"过期项**同时从仲裁输出与面板视图退场**"。
   ⇒ 过期判据更新；同时把原意图换成更强的判据（**上游改口 running 时必须能回来**，防误杀）。

### 五、两份方案文档（不实现）

用户同时要了两份"方案/接口/可行性"，本轮只出文档，**不写实现**：

- `docs/design/pet-switching.md`：换宠物的接口设计。核心结论是
  **切换 = 记住选择 + 重启（`app.relaunch()`）**，而不是运行时热重建窗口 ——
  因为 ADR 035 / 038 / 042 / **051** 四个崩溃**全出在那条路上**，而启动路径已经跑过五套真实窗口回归。
- `docs/design/ui-theme.md`：主题令牌化 + 三套色板 + 分阶段落地。
  先纠正了一个前提：**现在没有"暗黑模式"，只有一处硬编码的深色**
  ⇒ 直接再写一份浅色 CSS 会得到两份互不知情的样式表，**那正是"风格不统一"的成因**。

## 可复用结论

1. **判据工具本身也会是缺陷源，而且它的失败方式最隐蔽**：
   `stripComments` 吞掉代码之后，断言不是报错，而是**安静地找不到字符串**。
   ⇒ 凡"读源码做结构性检查"的工具，都要有一条"它读到的内容与文件确实一致"的自证。
2. **重跑旧证据是性价比最高的一次投入**：本次由它翻出 ADR 051 那个退出崩溃 ——
   一个功能全对、退出时崩的缺陷，被污染证据藏了至少一周。
3. **同步起进程在这个环境不可靠，而判据不该被环境判红**（ADR 044 §2 的第三次复现）。
   凡是"跑一个外部命令并等结果"的判据，都要考虑 `spawnSync` 的失败面。
4. **文档里的"已经做过"必须能被核到具体文件**：本轮修掉的 4 处过期表述
   （`PLAN` §3 的唯一待办、§6 的字段白名单、`INDEX` 第 10 条的五条规则、`README` 的 446 项）
   全都是**同一类病**：改动落进了代码/证据，但叙述留在原地。
