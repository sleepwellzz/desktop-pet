# 002 · 不污染 pet.json，锚点采用行级固定

- **状态**：已接受
- **日期**：2026-09-15
- **依据**：方案文档 §7.5 / §8，技能 `codex-pet-pack`

## 决策

### A. 自研参数一律走 sidecar，绝不写入 `pet.json`

- `pet.json` 严格保持 Codex 原生格式（仅 `id` / `displayName` / `description` / `spritesheetPath`，V2 加 `spriteVersionNumber`）。
- 扩展参数承载于两个 sidecar：
  - `behavior-map.json` —— 行→状态→帧列映射、逐帧包围盒、语义别名。
  - `desktop-pet.json` —— 帧率、循环策略、锚点偏移、优先级、交互与行为参数。

### B. 锚点采用行级固定锚点，禁止逐帧基线锁定

- `groundY = 202`（全状态中最深的触地点，单元格坐标）。
- 各状态按 `offsetY = groundY - baselineY(state)` 补偿，使触地点落在同一条地平线上。
- **禁止逐帧做基线锁定。**

## 理由

**A**：写进 `pet.json` 后这份包再也不能被 ChatGPT/Codex 直接识别，而"资产可双向流通"是这套格式最大的价值。

**B**：精灵内容在单元格内横纵居中，但居中 ≠ 对齐。站立触地点在 y≈200，侧身跑动 y≈182，趴卧只在 y≈141。若按单元格底边贴地，切状态时会突然下沉或悬空。而逐帧锁定会抹平奔跑的步态起伏与跳跃的腾空弧线——那是动感来源，不是误差。

## 后果

- 换一只宠物只需重跑分析脚本，帧率与锚点由脚本自动生成，不手写。
- 渲染器必须读取两个 sidecar 才能正确播放，不可只依赖 `pet.json`。
- jumping 状态实测触地点帧间抖动 43px，属预期，不得"校准"。
