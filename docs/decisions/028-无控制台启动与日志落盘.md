# ADR 028：无控制台启动（宠物驻留托盘）+ 日志落盘

- 日期：2026-09-18
- 状态：已实施
- 触发：用户反馈"必须挂着命令窗口，一旦关闭宠物就退出；这不符合宠物软件驻留后台的形式"

## 1. 根因（实测，不是推断）

**不是宠物不支持后台，是启动方式选错了。**

| 事实 | 证据 |
|---|---|
| `electron.exe` 是 **GUI 子系统**，直接启动**不带**控制台 | 未隐藏窗口直接 spawn，`conhost.exe` 数量 **14 → 14 不变**（`spikes` 临时脚本实测） |
| 旧的 `启动桌宠.bat` 一定有控制台 | 它走 `npm start` → **`node.exe` 是 console 子系统** ⇒ 控制台是 node 带来的 |
| 控制台是宠物的**父进程** | 关掉窗口 ⇒ 子进程一起退出 —— 这就是用户看到的现象 |

推论：**开机自启天然无控制台**（注册表里写的是 `electron.exe <应用目录>`，不是 node），
这一项不用改。

## 2. 做了什么

1. **新增 `启动桌宠-后台.bat`**：先可见地构建（进度看得到），再用 `start "" electron.exe .`
   直接拉起宠物 ⇒ **没有任何常驻窗口**，宠物在托盘。构建完 bat 的窗口 3 秒后自己关掉。
   **不需要 PowerShell**（原本打算用 `Start-Process -WindowStyle Hidden`，实测证明多余）。
2. **日志落盘 `~/.desktop-pet/pet.log`**（`setupFileLog()`）：包装 `console.log/warn/error`，
   同时写一份到文件。**每次启动截断** —— 它是排查工具不是审计台账，真正的流水在 `events.jsonl`。
   渲染层的 `console` 本来就转发到主进程，所以**一并进文件**。
3. `docs/how-to-run.md` 补"两种启动方式"对照表。

保留原 `启动桌宠.bat` 不动：开发/排查时**实时看日志**仍然方便，且用户明确看重
"改完代码双击即生效"。

## 3. 我自己踩的坑（值得记）

**第一版脚本退出码 1，日志里出现 `'控制台' 不是内部或外部命令`** ——
我在 `.bat` 的注释里写了中文。cmd 按 **GBK** 读 `.bat`，中文注释会被解析成命令执行。

**这正是本项目自己的硬约束**（AGENTS.md：批处理必须保持纯 ASCII），而我在知道它的情况下违反了 ——
因为"只是加几行注释"看起来不像改代码。

修正后加了**可执行的校验**：统计非 ASCII 字节数（现为 0）。
建议以后改任何 `.bat` 都跑一次这个检查，别靠眼睛看。

## 4. 判据

- `启动桌宠-后台.bat` 全流程 **exit = 0**（构建 8 步全过 → `start` 启动 → 窗口自关）；
- `pet.log` 立即产出**完整启动日志**（宠物包 / 状态源 / 快捷键 / 托盘 / 气泡 / 控制条 / 行为层 / 状态推送）；
- `electron.exe` 进程存在；`conhost.exe` 数量不变（无新控制台）；
- `npm run typecheck` 0 错、`npm run build` 0 错。

## 5. 还没验证的部分（诚实标注）

**"关掉所有窗口后宠物是否长期驻留"我这边验证不了** —— 我的自动化环境在命令结束时
会清理整个进程树（实测：脚本退出后 `electron.exe` 归零）。
而用户从资源管理器双击 `.bat` 启动的进程不受此影响。
**这一步需要用户双击验证**，我在回复里写清了操作步骤。

## 6. 与打包的关系

现在"无控制台"是靠**直接启动 electron.exe** 拿到的；打包后（`electron-builder` 产出
`<产品名>.exe`）同样是 GUI 子系统，行为一致 —— **但注册表值名与托盘图标随包分发要在
打包那轮复核**（挂起 #13）。
