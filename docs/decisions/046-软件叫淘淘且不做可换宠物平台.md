# 046 · 软件叫「淘淘」，且不打算做成可换宠物的平台

- 状态：已采纳（2026-09-28，用户拍板）
- 关联：ADR 040（托盘显示宠物名）、ADR 041（版本号真源）、ADR 045（跳号规则）
- 取代：`desktop-pet.json` / `behavior-map.json` 里两份与 `pet.json` 不一致的 `displayName`

## 背景

仓库里宠物名有**三个来源**且不一致（这是 ADR 040 说的"收成一处"没做完）：

| 文件 | `displayName` | 运行时是否被读 |
|---|---|---|
| `pet.json` | `淘淘` | **是** —— 托盘悬停名走的就是它（`main/index.ts:197` 收成一处） |
| `desktop-pet.json` | `淘淘 New` | 否 —— `pack.ts:51` 只取它的渲染/行为参数 |
| `behavior-map.json` | `淘淘 New` | 否 —— `pack.ts:52` 同上 |

所以**托盘显示的名字本来就是对的**（`淘淘`），两份 `淘淘 New` 是没人读的重复字段。
审计 P0-11 记的就是这个。

## 决定

1. **宠物名就是「淘淘」**，三份配置统一到这一个字符串。已改（`4cae9a8` 同批）。
2. **软件叫「淘淘」**，对外介绍页标题、定位、措辞全部按"这是一个叫淘淘的软件"写。
3. **不打算做"换任意宠物包"的功能。** 内部继续读宠物包格式（那是素材来源决定的，
   改它要重做图集与状态映射，不划算），但**不对外把它当卖点，也不做多宠物切换**。

## 为什么没有把 exe / zip 也改名

用户说"软件名称就叫淘淘"。**这一条只做到了展示层，没有做到文件名层**，原因是硬的：

- `tools/make-portable.mjs:23` 硬编码 `EXE_NAME = 'desktop-pet.exe'`，zip 名由它派生
  （`desktop-pet-${VERSION}-win-x64.zip`），`rcedit` 的 `OriginalFilename` 也是它。
- 改 exe 名 ⇒ **已装用户（包括用户本人和他那位朋友）的开机自启必坏**：
  注册表 `HKCU\...\Run` 里存的是 exe 的**绝对路径**，换名后旧路径不存在了。
- 而且迁移逻辑接不住：`src/host/autostart.ts` 的遗留条目迁移只认
  `electron.app.Electron → electron.app.desktop-pet` 这一对；改 ProductName 会产生
  第三个值名，旧的那两个都不会被自动清掉。
- 按 ADR 045 自己的判据，**"弄坏承诺范围内的兼容性 ⇒ MAJOR"** ⇒ 这该是 `2.0.0`，
  且需要一条能迁移旧注册表条目的新逻辑 —— 不是顺手能带上的改动。

**结论**：真要让文件名也变，需要一次独立的 2.0.0 决策（含自启迁移 + 告知老用户重装），
不能在文档改动里夹带。届时 `package.json` 的 `name` 也应一并改
（它目前是**惰性字段** —— 用户数据目录全部硬编码为 `~/.desktop-pet/`，
见 `main/index.ts:75,91,305` 与 `host/prefs.ts:18`，所以改它不会让老数据变孤儿）。

## 保留不动的地方

- `pet.json` / 两份 sidecar 里的 `"id": "taotao-new"` **没改**。它是包标识符不是显示名，
  改它会牵动图集与状态映射的对应关系，收益仅是"字符串好看"，不值当。
- 仓库名、npm 包名仍叫 `desktop-pet`，同上理由。
