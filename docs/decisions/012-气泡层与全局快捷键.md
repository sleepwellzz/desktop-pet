# 012 · 气泡层（状态文案 + 多会话角标）与全局快捷键

- **状态**：已接受
- **日期**：2026-09-16
- **决策人**：用户 + agent
- **影响**：`src/host/{bubble-layer,hotkey}.ts`（新增）、`src/kernel/bubble-policy.ts`（新增）、
  `src/renderer/bubble.{html,ts}`、`src/main/preload-bubble.ts`、`src/main/index.ts`、
  `src/host/{prefs,pet-menu}.ts`、`desktop-pet.json`、`package.json`（构建链）
- **设计文档**：`docs/design/m2-hotkey-bubble.md`（用户确认三点后才动手）

## 背景

M2 ① 打通状态链路后，"是什么状态"只能从**动作**猜：宠物在过生日=运行中、趴着=受阻、举着手=需要输入
—— 而这只包的作者在第 7 行画的正是生日姿态，普通用户根本猜不出来。
`statusMap` 里的气泡文案早就配好了，一直没人画。本轮的取舍是"怎么画才不碰命中边界"。

## 决策

### 1. 气泡用**独立窗口**，不扩大宠物窗口（本轮最关键的取舍）

扩大宠物窗口意味着窗口矩形变化 ⇒ 命中判定的坐标系、边界、"整窗穿透/可交互"的切换全都要重新验证
—— 那是 ADR 008/009 用两轮真实点击实测换来的地盘。改为新增 `src/host/bubble-layer.ts`：

| 属性 | 值 |
|---|---|
| transparent / frame:false / hasShadow:false / skipTaskbar | 是（与宠物层一致） |
| `focusable: false` + `showInactive()` | 绝不抢焦点 |
| `alwaysOnTop('screen-saver')` | 与宠物层同层 |
| `setIgnoreMouseEvents(true)` | **常态、永不切换** —— 气泡不可点，不存在命中判定这回事 |
| 位置/尺寸 | 贴宠物上方居中（间距 10 DIP），拖动宠物时跟随；用 `setContentBounds`（ADR 008） |

**为什么风险最低**：气泡层永远不接收鼠标按钮事件，因此 ADR 009 那个
"`hide()`→`show()` 之后 Windows 不再路由按钮事件、只能靠重载渲染层恢复"的坑**与它无关** ——
全屏让位恢复时气泡层只需要 `show()`，**不需要 reload**。宠物窗口一行没动。

### 2. 气泡时长策略做成纯函数，参数进 sidecar

`src/kernel/bubble-policy.ts`（纯 TS、无 Electron、时钟由调用方传入）：
`nextBubbleState(prev, next, policy, now)` —— 这样才能用虚拟时钟钉住最容易写错的那条规则。

策略（写进 `desktop-pet.json` 的新 `bubble` 段，符合 ADR 002 的 sidecar 纪律）：

| 状态 | 时长 | 理由 |
|---|---|---|
| `needs-input` | **常驻** | 与粘滞语义一致（`attentionPulse`）——最需要被看见的一条 |
| `ready` | 6s | 未读提示，看过就够 |
| `blocked` | 4s | 需要知道，不必长期占屏 |
| `running` | 2s | 频繁出现，长期挂着会烦人 |
| `idle` | 0（立即隐藏） | 无文案 |

**关键规则：同一状态的重复推送不重置计时**（否则 hook 每次心跳都会把气泡重新刷出来；
收起之后的同状态心跳也不该让它再冒出来）。角标变化只更新角标、不动计时。

### 3. 角标与气泡同生共死

`+N`（`badgeCount ≥ 1`，多会话）显示在气泡右侧；气泡不可见时不单独露角标。
好处是"任何长期占屏的 UI"都由同一套策略管。

### 4. 气泡层用 DOM 渲染（不是 canvas）

文字排版、圆角、省略号交给浏览器；构建链新增两个入口（ADR 005 的顺序扩展为
`build:main → build:preload → build:preload-bubble → build:renderer → build:bubble → copy-assets`）。
气泡层有**单独的 preload**（`preload-bubble.ts`），只暴露 `onBubble` 一个通道 —— 最小权限。

### 5. 快捷键：**注册前必须把"人话"归一化成 Electron 的 accelerator**

宠物包里写的是 `Win+Alt+P`（人话），而 Electron 里 Windows 键叫 `Super`。
`src/host/hotkey.ts` 的 `normalizeAccelerator()` 负责这一步，并支持降级链：

- 首选 `Win+Alt+P` → 归一化 `Super+Alt+P`（**本机实测可用**）；
- 降级链 `Ctrl+Alt+P` / `Win+Alt+Space` / `Ctrl+Shift+Alt+P`（`Super+Shift+P` 实测**已被占用**，不进降级链）；
- 全部失败 → 日志 + 托盘菜单里那行"快捷键：不可用（请从托盘或右键操作）"，**不静默失败**；
- 自定义：`~/.desktop-pet/prefs.json` 的 `hotkey` 字段（本轮不做按键捕获 UI）；
- 本轮动作：**切换宠物显示/隐藏**（复用托盘的动作表）。下一轮控制条上线后再加"唤出控制条"。

## 实测证据

| 手段 | 结果 |
|---|---|
| `spikes/m2-hotkey/probe-keyinject.js`（分离实验） | 注入击键**能**触发 `globalShortcut`（裸注入 / 带扩展位 / 先按键三种变体各 1 次命中）——证明"注入无效"不是环境问题 |
| `spikes/m2-hotkey/probe-bubble-hotkey.js` | **PASS**：快捷键真实按下 → 宠物隐藏 → 再按 → 恢复；气泡「运行中」出现且 **2 秒后自动收起**；心跳不重置计时；`needs-input` 常驻 + 角标「+1」；拖动宠物时气泡跟随；**气泡工作期间宠物仍可点** |
| `tools/status-arbiter.test.mjs` | **81 项断言全过**（新增气泡策略 16 项 + 快捷键归一化 7 项） |
| `spikes/m2-hittest/run.mjs probe.js` | 命中图：**应穿透却被吃 0**、拖动前后完全一致（新增窗口没吃掉任何点击） |
| `spikes/m2-hittest/run.mjs probe-fs-verify.js` | 两轮全过：全屏让位恢复后单击与拖动正常 |
| `spikes/m2-menu/run-tray.mjs` | 托盘动作仍 **PASS**（隐藏/显示、缩放、自启、退出） |

## 负面结论（本轮踩到的坑）

1. **`Win+Alt+P` 这种"人话"写法会让快捷键静默失效**（本轮最大的坑）。
   `globalShortcut.register('Win+Alt+P')` **返回 true**，但真实按下永远不触发 —— 没有任何报错。
   Electron 的修饰键词汇表里 Windows 键是 `Super`。修法：注册前一律 `normalizeAccelerator()`。
   **教训：注册成功 ≠ 能触发。** 探针必须注入真实击键来验，不能只看 `register()` 的返回值。
2. **窗口标题由页面 `<title>` 决定**，`win.setTitle()` 会被文档标题覆盖。
   探针按 `'desktop-pet-bubble'` 找窗口时找不到（页面标题写的是 `bubble`）。
3. **下发 32 DIP 高度会读回 38**（本机实测，出现在隐藏窗口首次显示时；宽度不受影响）。
   不纠正那个 6 DIP（气泡层不接收点击，尺寸偏差只影响观感），但**定位一律用实测高度**，
   这样唯一要紧的观感指标（离宠物多远 = 10 DIP）保持精确。
4. 拖动物例里曾把窗口对象缓存在变量里，窗口被隐藏/重建后就变成 null ——
   探针里凡是跨阶段的窗口句柄都要**现查**。

## 后果

- 状态的"可读性"补齐：从托盘菜单与气泡两处都能读到当前状态与多会话数量。
- 气泡层的窗口与页面是新增的持久对象；全屏让位、隐藏宠物、缩放都会带上它一起处理。
- 未做且刻意不做：悬浮控制条窗口、快捷输入框（它需要一个"输入发去哪"的答案，agent 通道属 M3 ——
  **不做假输入框**）、按键捕获设置界面、多宠物切换。
