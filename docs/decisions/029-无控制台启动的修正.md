# ADR 029：无控制台启动的**修正** —— `start` 不行，改回 `Start-Process`

- 日期：2026-09-21
- 状态：已实施
- **修正 ADR 028**（它把 `start "" electron.exe .` 当成了正确答案，是错的）
- 触发：用户实测反馈"我用了后台启动的 BAT，关掉那个窗口后宠物仍然消失"

## 1. 结论

`启动桌宠-后台.bat` 的启动行**改回** `powershell -NoProfile -Command "Start-Process ..."`。

**ADR 028 的结论是错的**：它说"electron 是 GUI 子系统，直接 `start` 就不会带控制台，不需要 PowerShell"。
"不带控制台窗口"这一半对，但**"关窗后能存活"这一半是错的**。

## 2. 实测（三种方式各起 3 个进程，用 explorer 启动 bat 模拟双击，再 `taskkill /PID <cmd>` 不带 /F 关窗）

| 启动方式 | 关窗后 |
|---|---|
| `start "" electron.exe`（ADR 028 的写法） | ✗ **全部被带走** —— 完整复现用户现象 |
| `powershell Start-Process`（第一版写法） | ✓ **3/3 存活** |
| `node spawn(..., {detached:true})`（DETACHED_PROCESS） | ✓ **3/3 存活** |

被测对象是**空壳 Electron**（不加载宠物），对用户正在跑的实例零干扰；实验前后核对过原实例完好。

## 3. 我错在哪（比结论本身更值得记）

ADR 028 里我做的实测是：**直接启动 electron，`conhost.exe` 数量 14 → 14 不变**，
据此推断"它没有控制台 ⇒ 关窗不影响它"。

**两个命题不是一回事**：
- 我测的是 **"启动 electron 时会不会新建一个控制台"**（不会 —— GUI 子系统不建控制台）；
- 我要证明的是 **"它有没有附加到 cmd 已经存在的那个控制台"**（这次实测证明了：`start` 出来的会被带走）。

一个进程**不新建**控制台，完全可以**附加**到父进程已有的那个。我拿前者的证据去支持了后者的结论。

**这是本项目第三次栽在"判据不纯"上**（前两次：`probe-ack-revival` 情形 2b 量到限流窗格而非迟滞窗口；
M2 ④ 第一版探针没先把宠物挪离右下角）。
**共同点：判据能测出某个数字，但那个数字不支持我想下的结论。**

### 附带发现：我第一次尝试"精确判据"时又错了一次

我先想用 `AttachConsole(pid)` 判断"目标进程有没有控制台" —— 结果它对**每个**进程都返回失败，
我差点因此得出"三种方式都没有控制台"。真实原因：`AttachConsole` 要求调用者**先 `FreeConsole()`**，
否则一律失败。**判据工具自己没校准，就会稳定地给出错误答案。**

最后之所以能收口，是因为换成了**直接测要验证的命题**（关窗后是否存活），
而不是测一个"我认为能代表它的中间量"。

## 4. 修法

```bat
powershell -NoProfile -Command "Start-Process -FilePath '%~dp0node_modules\electron\dist\electron.exe' -ArgumentList '%CD%' -WorkingDirectory '%CD%'"
```

`-ArgumentList '%CD%'`：`cd /d "%~dp0"` 之后的工作目录就是工程根，与 `npm start` 的 `.` 等价。
路径含空格的坑（本项目栽过）由 PowerShell 单引号覆盖。

**同时保留的结论**（ADR 028 对的部分）：`start` 出来的确实没有**新**控制台窗口 ——
所以新 bat 仍然"无窗口"，只是进程关系上离不开那个 cmd。

## 5. 判据

- 三方式对比实测（见 §2）：`Start-Process` 与 `DETACHED_PROCESS` 存活、`start` 被带走；
- 端到端：explorer 双击修改后的真 bat ⇒ 宠物起来、bat 窗口 3 秒后**自己关掉**
  （新 bat 里是 `timeout /t 3` 后 `exit /b 0`，用户其实不会遇到"关窗"这个动作）；
- `typecheck` / `build` 0 错。

## 6. 补记：同一天内又修了第二次（**路径含空格**）

§4 写完的启动行是：

```bat
powershell -NoProfile -Command "Start-Process -FilePath '...' -ArgumentList '%CD%' -WorkingDirectory '%CD%'"
```

用户双击后报 **`Unable to find Electron app at <工程目录>`** ——
`-ArgumentList` 是**按空白拆分**的，而本工程路径 `<工程目录>`
**中间有空格** ⇒ electron 收到被截断的第一个 token。

**修法**：`-ArgumentList '.'` + `-WorkingDirectory '%CD%'`（让工作目录去解析应用位置，
`'.'` 本身没有空格，整类引号问题一次消失）。

### 我这次错在"判据的输入不覆盖生产"

验证启动方式时，我用的空壳应用在 `C:\Users\<用户名>\AppData\Local\Temp\pet-echo`
—— **不含空格**。而真实工程路径含空格，**这正是本项目记录在案的已知坑**
（`fileURLToPath` 那条、`.bat` 里 `%~dp0` 的引号那条）。三轮验证全过，但**没一轮碰过真实路径**。

**与 §3 那次是同一类错误的两个变体**：
- §3：判据测的量不支持结论（测"新建控制台"却要证明"未附加控制台"）；
- §7：判据的**输入**不代表生产（用无空格路径测有空格路径的场景）。

**共同点：判据与命题之间隔了一层我自己的假设。** 已把这条写进
`docs/constraints/build-probe.md` —— 验证路径 / 启动 / 引号类问题时，**必须用真实的含空格路径**。

### 这次的验证（判据直接覆盖命题）

含空格真实路径 + explorer 双击真 bat + `taskkill /PID <cmd>` 不带 /F 关窗：

- 宠物起来，`pet.log` 里加载的是完整路径 `<工程目录>`；
- **关窗后 2/2 存活** ⇒ 驻留成功；
- 实验实例已清理，未留残留进程。

## 7. 遗留

- **"关掉所有窗口后宠物长期驻留"这一段我仍然验证不了**：自动化环境在命令结束时清理整个进程树。
  但这次的判据（关窗后是否存活）已经**直接覆盖**了用户报的那个命题，不再依赖推断。
- 彻底解法仍是**打包成 GUI exe**（挂起 #13）：由 explorer 直接启动，不存在"父控制台"这回事。
