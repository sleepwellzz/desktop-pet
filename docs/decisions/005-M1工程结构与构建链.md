# 005 · M1 工程结构与构建链

- **状态**：已接受
- **日期**：2026-09-15
- **决策人**：用户 + agent
- **影响**：`src/` 目录结构、`npm run build` 流程、主进程 ↔ 渲染层的握手协议

## 背景

M1 把 spike 里的窗口经验落成正式工程。三个约束同时成立时出现了一个构建问题：

1. 内核（`src/kernel`）要被**主进程**（CJS）和**渲染层**（浏览器环境）两边复用；
2. Electron 20+ 默认 `sandbox: true`，**preload 里 `require` 本地模块会被拒**（实测报
   `module not found: ../shared/ipc`）；
3. tsc 对渲染层输出 CJS 的话，浏览器里没有 `require`，直接 `exports is not defined`。

## 决策

1. **目录分层**（对应 ADR 001 的"内核不碰宿主"）：

   ```
   src/
   ├── kernel/    宠物内核：类型契约、包加载与校验、状态机播放器、图片头嗅探 —— 禁止 import electron
   ├── host/      宿主适配层：覆盖窗口、全屏检测 —— 唯一允许碰 Electron / koffi 的地方
   ├── main/      Electron 入口与 preload
   ├── renderer/  渲染层：canvas 播帧、拖拽、点击
   └── shared/    IPC 通道名与载荷类型（两边共用的单一事实来源）
   ```

2. **构建链**：主进程与内核走 `tsc`（CJS → `dist/`）；**渲染层与 preload 用 esbuild 打包**
   （renderer → IIFE 单文件；preload → CJS、`--external:electron`）。`npm run build` 固定顺序
   `build:main → build:preload → build:renderer → copy-assets`，esbuild 的输出覆盖 tsc 对
   `renderer.ts` 的产物，因此顺序不可调换。

3. **init 握手协议**：渲染层脚本就绪后主动发 `pet:ready`，主进程收到才下发宠物包载荷
   （`pet:init`）。`ready-to-show` 时页面脚本往往还没执行，过早 send 会**静默丢消息**
   （实测表现：宠物不显示、渲染层无日志）。渲染层对 init 做幂等保护。

4. **精灵图走 data URL** 下发，不用 `file://`：避免污染 canvas 导致 `getImageData` 抛安全异常。
   渲染层加 CSP（`script-src 'self'; img-src data:`），本应用没有任何远程内容。

5. **自检开关**：`electron . --screenshot=<前缀>` 在 init 后抓两帧 PNG 存盘再退出，
   用于自动化验证"动画确实在播"（两帧应不同）与画面干净（无滚动条、无杂散像素）。

## 实测结果

- `npm run build` 通过；冒烟运行加载宠物包成功（淘淘 New · 1536x1872 · 9 状态）；
- 自检截图两帧姿态不同 → idle 动画在播；画面无滚动条、背景全透明。

## 后果

- 新增 esbuild 依赖（约 10 MB），换来渲染层/preload 的可靠打包与秒级构建。
- 渲染层保留在主 tsconfig 里做类型检查，其产物被 esbuild 覆盖——改构建脚本时别破坏这个顺序。
- 内核"不 import electron"目前靠约定维护，M2 若引入 lint 应加一条 `no-restricted-imports` 规则兜底。
