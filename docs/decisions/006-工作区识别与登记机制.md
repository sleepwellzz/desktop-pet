# 006 · WorkBuddy 工作区识别与登记机制

- **状态**：已接受（实测结论，含对既有判断的更正）
- **日期**：2026-09-15
- **决策人**：用户 + agent
- **影响**：`PLAN.md` §1 开工流程、`AGENTS.md` 会话协议、用户级 `~/.workbuddy/MEMORY.md` 的环境事实

## 背景

用户反馈两个现象：

1. `desktop-pet` 目录不出现在 WorkBuddy「选择工作空间」列表里；
2. 每次新建对话都会落进一个带时间戳的新目录（如 `...\WorkBuddy\2026-09-15-19-53-31`），
   即使使用过浏览/添加入口。

本工程 journal 早前记录的处置方式是：手工创建索引目录
`~/.workbuddy/projects/<项目键>` 与标记目录 `desktop-pet/.workbuddy/`。
**该方式未能解决问题**。本次重新定位根因。

默认路径与时间戳目录的生成逻辑：

```js
/** 在默认根目录下生成带时间戳的唯一子目录。 */
async generate() {
  const root = await this.providers.resolveDefaultRoot();
  await ensureRootDirReady(root);
  const now = new Date();
  for (let attempt = 0; attempt < GENERATE_MAX_ATTEMPTS; attempt += 1) {
    const candidate = path.join(root, formatTimestamp(new Date(now.getTime() + attempt * 1e3)));
    try {
      await fs.mkdir(candidate);
      await Promise.resolve(this.providers.recordWorkspace?.(candidate)).catch(() => void 0);
      return { path: candidate };
    } catch (error) { if (error.code !== "EEXIST") throw error; }
  }
  throw new Error(`[WorkspaceDomain] Failed to generate unique cwd under ${root}`);
}

function resolveDefaultWorkspaceRootUncached() {
  if (configServiceRef) try {
    const stored = configServiceRef.get(DEFAULT_WORKSPACE_PATH_CONFIG_KEY);
    const validation = validateDefaultWorkspaceRoot(stored);
    if (validation.ok) return validation.root;
    clearConfiguredDefaultWorkspacePath(stored, validation.reason);
  } catch {}
  const fallback = getSystemDefaultWorkspaceRoot();
  const validation = validateDefaultWorkspaceRoot(fallback);
  if (validation.ok) return validation.root;
  return fallback;
}
```

## 结论

1. **工作区列表的数据源 = `workspaces` 表 ∪ 会话历史中保存的工作区路径。**
   `~/.workbuddy/projects/` 只是**会话记录的存储位置**，由会话 cwd 派生，**不是**列表数据源。
   → 更正 journal `2026-09-15-M1渲染闭环.md`「补：工作区注册」一节的判断。

2. **带时间戳目录来自 `WorkspaceDomain.generate()`**：新建对话未明确指定工作区时，
   在「默认根目录」下创建时间戳子目录并把它登记为工作区。
   当前默认根目录 = `<工作区>`（`~/.workbuddy/app/app-config.json`
   的 `defaultWorkspacePath`）。

3. **登记时机**：只有目录**真的被用作会话 cwd** 时才会 UPSERT 进 `workspaces` 表。
   浏览/选中目录本身不写入 —— 这解释了"浏览或添加过却没成为永久索引"的体感。

4. **`desktop-pet` 的登记已经成立**（`last_opened_at` 即本次会话创建时刻，
   本次会话 cwd 为 `...\desktop-pet`，`projectId = p_91303fc5598047e790a76914c242412c`）。
   在此之前它确实不在表中，所以用户此前看不到它。

## 决策

1. **不搬家。** 工程目录保持 `<工程目录>`。
   登记已生效，搬迁只会引入路径漂移、git 历史与 tdrive 项目绑定的额外成本。
2. **不改 `defaultWorkspacePath`**（保持父目录 `...\WorkBuddy`）。理由：`generate()` 的语义是
   "在 root 之下建时间戳子目录"，把 root 指向工程目录会生成 `desktop-pet\2026-xx-xx-...`
   嵌套目录，比现状更糟。
3. **进入本工程的正确操作**：新建对话时在「选择工作空间」列表里选择 `desktop-pet` 条目，
   而不要走"新建默认工作区"。选中的工作区会成为该会话的 cwd。
4. 历史 5 个时间戳目录保留只读（各自含已完成会话），不再新增。
