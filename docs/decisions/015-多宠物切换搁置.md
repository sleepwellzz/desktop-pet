# ADR 015 · 多宠物切换搁置（等素材规格）

- **状态**：✅ 已定（用户拍板，2026-09-17）
- **日期**：2026-09-17
- **影响范围**：PLAN §3 状态表、§4 开工顺序第 5 条、下一步的选定

## 背景

M2 ⑤ 原计划：扫 `~/.codex/pets/*` → 列包 → 校验 → **热切换整个 pack**
（窗口尺寸、状态表、sheet、托盘图标全量重建）→ 失败回退。在 M2 ④ 收尾后它被排为下一步。

## 决定

**搁置，不做。** 不排进任何一轮，直到素材侧的前置条件满足（见下）。

## 理由（用户，2026-09-17）

> 切换毕竟还是要有可以支撑切换的素材存在，但是我现在根本就没有这些素材，
> 甚至咱们都没有设计说有一套素材的整个导入或者是规格要求之类的这种标准。

拆成工程判断：

1. **现在手里只有一套素材**（工程内 `pet.json` + `spritesheet.webp`，即那只 demo 包）。没有第二套，
   就没有"切到哪儿去"这个对象。
2. **"多宠物"这一档真正缺的不是代码，是素材侧的标准。** 现在若动工，必须同时发明三样东西：
   ① 一批合法宠物包（≥2 套，且要覆盖不同行语义 / 尺寸 / 可选字段缺失的情况）；
   ② 一套**导入流程**（包放哪、怎么被扫到、校验失败怎么向用户交代）；
   ③ 一份**规格基线**（尺寸、行数、锚点、必填/可选项）。
   这三样是 ⑤ 的**前置产物**，不是它的伴随产物。把"造素材 + 定标准 + 写切换"压进同一轮，
   等于一轮里做三件互相牵扯的事，出了问题无法定位是哪一层的。
3. 用 `demo-pet` 复制成两份冒充"多套素材"是**假验证** —— 它只能证明代码没崩，
   证明不了"换一套真实创作出来的包还能不能跑"，而后者才是 ⑤ 的风险所在。

## 不做什么（负面结论）

- 不写"半套"切换（只做枚举与菜单、不做热切换重建）。
- 不做藏在角落的开发者开关来"先留个口子"—— 没有素材它永远跑不到，等于死代码。
- 不在本轮顺手扩 `codex-pet-pack` 技能去补规格：那是 ⑤ 的前置工作，
  该在明确"要做 ⑤ 了"之后的单独一轮里做（并且它的产物是**规格文档 + 示例包**，不是运行时代码）。

## 何时可以重启这一项

满足任一条即可重新评估：

1. 用户手里出现了**第二套真实宠物包**（自己做的或从外部拿到的），且愿意用它试切换；
2. 用户明确要"素材导入 + 规格校验"这条产品线，同意先做前置的规格与示例包；
3. 出现了"因为不能换宠物而卡住别的功能"的具体场景（目前没有）。

## 影响

- PLAN §3 状态表：⑤ 标记为 **⏸ 搁置（等素材规格）**，不再是"下一步"。
- PLAN §4 开工顺序第 5 条同样标注，并写明重启条件（避免下个会话重新提议或重新论证）。
- **下一步改为：M2 ④ 的人工复验与缺陷修复**（④ 已实现、探针与回归全绿，但用户的复验尚未走完，
  且上轮修复需要确认手感）。
