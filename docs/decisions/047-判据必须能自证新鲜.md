# ADR 047：判据必须能自证新鲜 —— 构建戳、探针钩子静态守卫、证据不许被失败销毁

- 日期：2026-09-28
- 状态：已采纳
- 相关：ADR 032（全局快捷键整块删除）、ADR 023（preload 双产物诱饵）、
  ADR 042（守卫守错对象）、ADR 044（"打包成功"必须回读产物本身）、
  `docs/constraints/build-probe.md`、`docs/reviews/2026-09-28-全面代码复核.md`（P0-1 / P0-9 / P0-10）、
  `AGENTS.md` 纪律 3(b) 与纪律 4

## 背景

`docs/reviews/2026-09-28-全面代码复核.md` 的 P0-1/P0-9/P0-10 指向同一件事：
**本项目的判据产出"通过"这个信号，并不需要真的验过。** 三条独立路径：

1. **P0-10 —— 行为测试跑在 `dist/` 上，而没有任何东西保证 `dist/` 是本轮构建的。**
   `tools/status-arbiter.test.mjs` 有 1885 行，行为断言 `require` 的是 `dist/**/*.js`，
   结构性断言读的是 `src/**.ts` 原文。改完 `src/kernel/status.ts` 不重新构建就跑测试，
   得到的是"结构性断言全绿（**新源码**）+ 行为断言全绿（**旧 dist**）"的 446/446。
   而现行判据没有一条会在这条路径上变红：`tsc` 只有 `build:main` 才产出 JS，`typecheck` 用 `--noEmit`。

2. **P0-9 —— 探针调用的调试钩子被删掉后，探针不会报红，而是"跑不出任何证据"。**
   ADR 032 于 2026-09-21 整块删除全局快捷键，`__petDebug.hotkey()` 随之移除，
   而 `spikes/m2-hotkey/probe-bubble-hotkey.js` 仍在 `:96` 与 `:316` 调用它。
   探针会在那一行抛 `TypeError`，**走不到写报告那步**。
   雪上加霜：`run.mjs:16` 在 spawn 前 `rmSync` 掉**已入库的** `bubble-hotkey.json`
   ⇒ 照 `build-probe.md` 跑一次"必跑判据"，净效果是**既没验成、又丢了历史证据**。

3. **P0-1 —— 六份入库的探针证据内含 `[uncaught] TypeError: Object has been destroyed` 却报 `PASS`。**
   而 `AGENTS.md` 纪律 3(b) 推荐的 mtime 验证法在这批文件上会给出"新鲜"的**错误**结论
   （内容是 09-18 的、mtime 是 09-22 的）。

**共性**：三者都是"证据与被验证的东西之间的绑定"缺失，而**没有任何一条会让流程停下来**。

## 决定

### 一、`dist/` 新鲜度用**内容哈希**守，不用 mtime

新增 `tools/stamp-build.mjs`：构建成功后把当时 `src/`（`.ts/.tsx/.js/.json/.html/.css`）
全量内容的 SHA-256 前 16 位写进 `dist/.build-stamp.json`。
`tools/status-arbiter.test.mjs` 新增 **⓪ 节**，不一致则**直接 `process.exit(2)`**。

**为什么不是 mtime**：mtime 在本项目已经骗过人一次（P0-1 那批文件），而且
`git checkout`、文件复制、`touch` 都会重写 mtime —— 它回答不了纪律 3(b) 真正问的那个问题
（"这份证据怎么证明它是**本次**产生的"）。哈希只认内容。

**为什么是硬失败而不是记一条断言**：一条 `FAIL` 混在 450 项里会被滑过去，
而此刻后面 450 项**全都跑在旧 dist 上**，它们"全绿"这件事本身已经没有意义了。
**守卫的方向性符合纪律 4**——`src` 内容就是那个"会在危险发生时变化的东西"。

**为什么戳只在全部编译成功后写**：提前写戳等于给一次失败的构建发通行证。

**为什么不做"测试前自动构建"**（更彻底但被否）：那会掩盖"你到底测了什么"，
且是 P0-2 / P0-4 那类漏洞的温床（人会为了跑通测试而跳过构建检查）。

接入点两条构建链都要有：`tools/run-build.cjs`（异步 `import` 后写戳）
与 `package.json` 的 `build` 脚本末尾。`npm run build:main` **不写戳**——它只跑 tsc。

### 二、探针钩子加**静态**守卫

新增 `tools/check-probe-hooks.mjs`：不启动 Electron，抽出 `src/main/index.ts` 里
`__petDebug` 桥暴露的键名，与全部 `spikes/*/probe*.js` 里 `dbg.<name>(` 的调用逐一核对。
接进 `tools/status-arbiter.test.mjs` 的 **⓪b 节**，同样硬失败。

**关键理由**：钩子被删这件事**不需要启动 Electron 就能发现**。
**能便宜发现的，不要留到贵的那一步**——这是本条全部价值所在。
它是静态检查，所以随时可跑、不抢焦点、不改写任何产物。

**匹配前必须去注释**：`m2-control/probe-key-path.js:97` 的注释里写着
"（原日志里的 `快捷键=${dbg.hotkey()}` 已随全局快捷键一并删除，ADR 032。）"
——那是**一条正确维护过的注释**，按裸文本匹配会误报。
判据把注释当代码 ⇒ 它的失败会变成噪音，而噪音是让人忽略判据的头号原因。

### 三、证据产物**不许被失败的判据销毁**

`spikes/m2-hotkey/run.mjs` 改为：经 `PROBE_LOG` / `PROBE_REPORT` 环境变量把探针输出
指到临时文件，**确认真的拿到一份新报告后才 `rename` 覆盖**入库文件；
中途抛错则旧证据原封不动 + 打印说明 + 退出码 1。

⚠️ 必须**同时**改探针侧（`probe-bubble-hotkey.js` 顶部读这两个环境变量）。
只改驱动侧会出现"探针把正式那份截断重写、rename 又拿临时那份盖回去"，
判据失败时**仍然**会毁掉旧证据——这正是"改了但没改全"的形状，
本轮实际踩过一次才改成现在这样。

**通用纪律**：多数 `run.mjs`（12 个）都是"先 `rmSync` 再跑"这个写法。
本轮只改 `m2-hotkey` 这一个被 `build-probe.md` 点名必跑的那个；
其余**列入 PLAN §4 挂起清单**，不在本轮动。

### 四、删掉失效的探针用例

`probe-bubble-hotkey.js` 移除"注入真实击键验快捷键"用例（ADR 032 之后钩子已不存在），
连带清掉不再被使用的 `keybd_event` / `VK_LWIN` / `VK_MENU` / `VK_P` 声明。
控制条键盘与焦点行为由 `spikes/m2-control/probe-key-path.js` 负责，不搬回气泡探针。
`docs/constraints/build-probe.md` 与 `spikes/m2-hotkey/README.md` 同步标注。

## 后果

- `tools/status-arbiter.test.mjs` 从 446 项增至 **450 项**，且前两节是硬失败闸门。
- 新增 `npm run dist:check`（= `node tools/stamp-build.mjs --check`）与 `pretest:status` 钩子。
- **"跑一次必跑判据"不再等价于"删掉上一轮证据"**。
- P0-1 剩余的五份污染证据**本轮未修**：它们只能靠真实重跑探针才能更新，
  而本轮明确不跑 GUI 探针（用户决定）⇒ 已列入 PLAN §4 挂起清单。
  本轮顺带修掉 `m2-hotkey` 那一份，是一次**误触发**的副产品：修复后的探针真的跑完了，
  产出的 `bubble-hotkey.json` 是 `PASS`、日志零 `[uncaught]`、且已不含失效的 `hotkey` 段
  （原先那份是 ADR 032 之前的 `FAIL` 残留，`accelerator: "Control+Alt+P"`）。
  **但它不是一次经批准的验证**，这一点必须留在记录里。

## 顺带确认（不改代码）

`spikes/m2-control/probe-key-path.js` 也出现过 `dbg.hotkey()` 命中，去注释后确认是**注释**、
不是调用——该处在 ADR 032 时已被正确清理。静态守卫对此**不会**误报。
