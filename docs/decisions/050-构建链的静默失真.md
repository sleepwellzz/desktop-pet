# ADR 050：构建链的三处「静默失真」—— 类型检查入链、renderer 不许被 tsc 碰、打包前校验 dist

- 日期：2026-09-29
- 状态：已采纳
- 相关：ADR 023（preload 双产物诱饵）、ADR 047（判据必须能自证新鲜）、
  ADR 044（"打包成功"必须回读产物本身）、ADR 042（守卫守错对象）、
  `docs/reviews/2026-09-28-全面代码复核.md`（P0-2 / P0-3 / P0-4 / P0-8）

## 背景

审计报告的四条 P0 是同一种病：**构建链会产出"看起来成功"的东西，而它其实是坏的。**

| 编号 | 病 | 表现 |
|---|---|---|
| P0-2 | `build` 链**完全不跑 preload 类型检查** | 通道名拼错照样产出"成功"的 dist，只在用户点开控制条时"按钮没反应" |
| P0-3 | `watch` 用 tsc 覆盖 renderer 的 IIFE 产物 | 浏览器里 `require`/`exports` 未定义 ⇒ **宠物窗口白屏**，而 watch 还在"正常运行" |
| P0-4 | 打包不校验 `dist/` 新鲜度 | 改完 `src` 直接打包 ⇒ **"1.0.2 版装着 1.0.1 代码"**，且属性页/zip 名/日志/托盘四处自洽显示 1.0.2 |
| P0-8 | `acceptance.md` 硬写版本号 | 实际已跳号 ⇒ **照单验收必然判红**（假故障），可能反过来诱人去改代码 |

## 决定

### 一、类型检查进构建链（P0-2）

`package.json` 加 `prebuild: npm run typecheck:preload && npm run typecheck:renderer`；
`tools/run-build.cjs` 在**最前面**加两步 noEmit 类型检查。

**为什么放最前面**：类型不过就不该产生任何产物 ——
半成品 `dist/` 存在会污染 dist 新鲜度判据（ADR 047），让后续判断更难。

**为什么 npm 用 `prebuild` 钩子**：`npm run build` 是另一条入口，它不经过 `run-build.cjs`。
**两条链都要有**，这是 ADR 023 那次的教训（只修一条等于没修）。

### 二、renderer 从 tsc 的 include 里摘出来（P0-3）

`tsconfig.json` 原为 `include: ["src/**/*.ts"]` —— **覆盖了 `src/renderer`**，
于是 tsc 把 renderer 编成 **CommonJS** 并**同名覆盖** esbuild 的 **IIFE** 产物。

**为什么正式 build 一直没出事**：`build:main`（tsc）先跑、`build:renderer`（esbuild）后跑，
顺序救了它。**这是运气，不是机制** —— 一旦只跑 tsc 或跑 `tsc --watch` 就暴露。
本轮**实测复现**：写 `watch` 时跑出 `Object.defineProperty(exports, "__esModule", …)`。

修法与 ADR 023 对 preload 的处理**完全同构**：
- `tsconfig.json` 的 `exclude` 加 `src/renderer`；
- 新增 `tsconfig.renderer.json`（`noEmit: true`，`exclude: []` 清空继承）承担类型检查。

⚠️ `exclude` 必须写 `"src/renderer"` 而不是逐个文件 ——
**新增一个 renderer 源文件时不会有人记得去改 exclude**，
而目录级排除天然覆盖将来新增的文件。

### 三、`watch` 重写为 `tools/watch.mjs`（P0-3）

原 `"watch": "tsc -p tsconfig.json --watch"` 有两个独立的坑：
① 覆盖 renderer（见上）；② preload 被主配置排除 ⇒ **preload 改动纹丝不动**，
而开发者以为在监听。

新实现用**与正式构建完全相同的步骤**做监听：
tsc(main, emit) + tsc(preload, noEmit) + tsc(renderer, noEmit)
+ 6 个 esbuild 目标（**esbuild 的 watch API，不是轮询**）+ copy-assets + 构建戳。

**顺带补上一个原来漏掉的**：`src/renderer/*.html` 是静态资源，
tsc 与 esbuild 都不碰它们 ⇒ 用 `fs.watch` 单独监听并重跑 `copy-assets`。
漏掉它就会出现"改了 HTML 界面，以为 watch 覆盖了"——**同一种"以为在监听其实没监听"**。

新增 `watch:start`（监听 + 首次构建成功后启动 electron）。

### 四、打包前校验 dist 与 src 同步（P0-4）

`tools/make-portable.mjs` 原先只判 `dist/main/index.js` **存在**，不看它新不新。
现在调 `stamp-build.mjs` 的 `verifyDist()`：比对构建戳里的 **`src/` 内容哈希**（ADR 047），
不一致则 `die` 并打印修复命令。

**不比较 mtime** —— 那个方法在本项目骗过人一次（ADR 047 记的那批探针证据：内容是 09-18 的、
mtime 是 09-22 的），且 `git checkout` 会重写它。

### 五、验收清单不许硬写版本号（P0-8）

`docs/acceptance.md` 的四处版本号改为 `<版本号>`，并写明**唯一真源是 `package.json` 的 `version`**。
同时在主单测加一条断言：扫 `acceptance.md` 里的 `\d+\.\d+\.\d+` 串，
**凡与 `package.json` 版本不一致就报红** ⇒ 一劳永逸挡住这类漂移。

（审计原文建议的就是这个做法。加断言而不是只改数字，
是因为**只改数字下次跳号还会漂**。）

## 后果

- **主单测 456 → 457 项**（新增验收版本一致性断言）。
- `npm run typecheck` 现在跑**三份** tsconfig；`npm run build` 前置两步类型检查。
- **`npm run build:main` 单独跑不再破坏 renderer** ——
  这是本轮最实质的改变：原先它会静默把 renderer 打成 CommonJS，直到下一次 `build:renderer` 才恢复。
- 未做：**P0-5（打包非事务性）与 P0-6（无单实例锁）**。
  两条都要动主流程且需一轮完整实测，已留在 PLAN §4。

## 判据记录（本轮实跑）

- `run-build.cjs` 第一步即 preload 类型检查；**非真空**：往 `preload.ts` 注入
  `const __bad: number = "x"` ⇒ `[FAIL] tsc (preload typecheck)` + `BUILD FAILED`，退出码 1；撤销后恢复。
- `tsc -p tsconfig.json` **单独跑之后** `dist/renderer/renderer.js` **仍是 IIFE**
  （修复前会变成 CommonJS）。
- 类型检查未被放弃：往 `src/renderer/bubble.ts` 注入类型错误 ⇒
  `tsc -p tsconfig.renderer.json` 报 `error TS2322`，退出码 2。
- `watch` 实跑：改 `src/main/preload.ts` ⇒ 产物 md5 变化、标记进入产物
  （**注**：验证时要用**真实代码改动**，不能用注释 —— esbuild 会剥离注释，用注释会得出"没生效"的错误结论）。
- 打包非真空：改 `src` 不 rebuild ⇒ `dist/ 与 src/ 不同步，拒绝打包`，退出码 1。
- 验收版本断言非真空：把 `<版本号>` 改成 `9.9.9` ⇒ 精确报出 `发现 9.9.9`。
