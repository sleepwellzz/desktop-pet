# ADR 036：开机自启的注册表值名 = `electron.app.` + exe 版本资源的 ProductName

- 日期：2026-09-22
- 触发：挂起 #15 —— 用户在便携版勾选开机自启后，注册表的**值名**不是桌宠
- 结论：三条候选逐个实测，只有**改 exe 版本资源**有效；顺带修正了"目标值名应该是多少"

---

## 1. 症状（承接 ADR 034）

用户勾选开机自启后，`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里是：

```
electron.app.Electron : "E:\...\dist-win\desktop-pet\desktop-pet.exe"
```

**要说清楚的是**：命令形态是对的，`isPackaged=true` ⇒ 走无参分支，**自启完全能用，也能关。**
坏的只是它在系统启动列表里叫这个名字 —— 用户认不出这是桌宠，也得承担与别的便携 Electron 应用
互相覆盖的风险。所以它是 🟡 Minor，不是故障。

## 2. 三条候选，逐个实测（不猜）

| 候选 | 做法 | 实测结果 |
|---|---|---|
| A | app 的 `package.json` 里加 `productName` | ❌ 不起作用（`resources/app/package.json` 的 `name: "desktop-pet"` 一直都在，值名照样是 Electron）—— ADR 034 已推翻 |
| B | `app.setName('desktop-pet')` | ❌ **`app.getName()` 确实变成了 `desktop-pet`，值名纹丝不动** |
| C | 用 rcedit 改 **exe 版本资源的 ProductName** | ✅ 有效 |

**B 这一轮推翻了我上一轮的推理**（不是结论，结论恰好一致）：
ADR 034 里我写"B 大概率无效"，理由是 Electron 文档说 setName「does not affect the name that the OS uses」。
**这个理由站不住** —— 注册表值名不是 OS 决定的，是 Electron 自己写的。
真实原因是 Electron 写值名取的是**别的东西**（exe 的版本资源），跟 `GetName()` 无关。
⇒ **歪打正着的结论也是没验证的结论**，这条照写不误：还是得跑一遍才知道。

## 3. 顺带修正目标：应该叫 `electron.app.desktop-pet`，不是 `desktop-pet`

改完 ProductName 后实测写出的值名是：

```
electron.app.desktop-pet : "E:\...\desktop-pet.exe"
```

`electron.app.` 是 Electron 固定的前缀，我们能改的只有后半截。对照组佐证：
机器上的 Obsidian 也是 `electron.app.Obsidian`。

⇒ ADR 034 里写的判据"值名应为 `desktop-pet`"**是错的判据**，按它验收会永远判失败。此处更正。

## 4. 落地

**打包期**（`tools/make-portable.mjs`）：复制完运行时、改完 exe 名字之后多一步 rcedit。

```js
rcedit <exe> --set-version-string ProductName  desktop-pet
             --set-version-string FileDescription desktop-pet desktop pet
```

两个细节：
- rcedit 给的是**原生 exe**（`node_modules/rcedit/bin/rcedit.exe`，不是 JS 模块），
  要用 `spawnSync(exe, args, { shell: false })` —— 含空格的路径走 shell 会被截断；
- **值一律用 ASCII**：中文写进版本资源，读出来是乱码（本轮实测 `FileDescription` 显示成一串问号），
  跟 `.bat` 必须纯 ASCII 是同一类坑。

附加收益：顺手把这枚 exe 在**任务管理器里的显示名**也变成了 `desktop-pet` ——
排错时不再需要从一堆 Electron 里认人。

**运行期**（`src/host/autostart.ts`）：旧条目的迁移 `migrateLegacyAutoStart()`，三条原则：

1. **只动指向本应用的条目** —— 那个值名可能属于机器上任何别的便携 Electron 应用，
   误删别人的自启是不可接受的 ⇒ 先读值，含 `desktop-pet` 才处理；
2. **保住用户已勾选的意图** —— 他是勾过的，升级一次包不该让自启悄悄变回关 ⇒ 删旧的同时写新；
3. **幂等** —— 删完之后查不到，再跑一次自然什么都不做。

为什么**用 PowerShell 而不是 reg.exe**：
- reg.exe 在受限环境会被安全策略拦住（本工程直接撞上，且不绕过），PowerShell 始终可用；
- 读单个值时要**直接取属性**（`(Get-ItemProperty ...).'名称'`）—— `Get-ItemProperty` 的
  **表格输出会把长值折行**，解析出来的是断了的残缺内容（本轮踩过，症状是"看起来注册表没变"）。

## 5. 判据（端到端实测，非推断）

在真实便携版 + 真实 HKCU 上跑：

| 步骤 | 观测 | 结果 |
|---|---|---|
| exe 版本资源 | `ProductName=desktop-pet` | ✅ rcedit 确实写进去了 |
| 启动**之前** | `electron.app.Electron = "...\dist-win\desktop-pet\desktop-pet.exe"` | （用户勾的旧条目） |
| 启动**之后** | `electron.app.desktop-pet = "...\dist-win\desktop-pet\desktop-pet.exe"` | ✅ 迁移成功，旧条目消失 |
| 再启一次 | 与上一步完全相同 | ✅ 幂等 |
| 运行日志 | `isPackaged=true`、窗口显示、精灵图就绪、状态通道正常 | ✅ 便携版本身没问题 |
| 用户的自启状态 | 迁移后仍是**开启** | ✅ 不需要用户重勾 |

另外：静态检查 ✅、单测 **313/313**、托盘探针 PASS 且日志零 uncaught。

## 6. 记录一次判断上的反复

`#15` 这件事前后花了两轮，值得留一句：

- 上一轮我做的是**推断**（"打包后会变成 productName"），并且把推断写进了代码注释；
- 注释会误导下一轮 —— 下一个会话很可能顺着它直接跳去"改个 productName 试试"；
- 这一轮的三条候选**每一条都用同一套对照实验实测**，包括那条我自认为"大概率无效"的 B。

⇒ **对一个开打磨完的领域（桌面接入），推断的命中率不足以省掉一次实验。**
这次的全部成本是三串命令，而它的收益是结论能写进 ADR 当事实用。
