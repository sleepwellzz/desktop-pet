# ADR 032 · 删除全局快捷键（Win+Alt+P）

**日期**：2026-09-21
**状态**：已执行
**关联**：ADR 012（气泡层与全局快捷键）｜ADR 014（控制条）｜ADR 016（交互模型修订）｜ADR 031（判据 9）｜挂起 #13

---

## 1. 决策

**整块删除全局快捷键功能**（`Win+Alt+P` 及其降级链），不是"默认关掉"，是**删除**。
控制条只剩两条唤出路径：**右键宠物** / **托盘菜单「控制条」**。
隐藏宠物后的快捷入口只剩 **托盘左键单击**（`tray.ts` 默认的 `toggleVisibility`）。

## 2. 起因

判据 9 的第四问（`Win+Alt+P` 有没有误触）用户答的是 **"没用过快捷键"**。
ADR 031 已认定这一问**未取得数据** —— "没用过"回答的是使用频率，不是误触率。

把这条摆到打包那轮前面讨论时，用户的处置是：**直接删掉，不需要快捷键了，单击托盘就可以隐藏显示。**

## 3. 为什么"删除"而不是"保留但默认关"

四条理由，每一条都独立成立：

1. **它是一条从未被真实走过的路径。** 注册 → 归一化 → 唤出控制条，在真实使用里一次都没发生过。
   留着就是留一个**未验证的面**。
2. **它是静默失败面。** `Win` 在 Electron 里必须写成 `Super`；直接拿 `Win+Alt+P` 去注册，
   `register()` **返回 true 但永不触发**（ADR 012 负面结论 1，当年用分离实验才定位到）。
   一个"看起来成功、实际不通"的开关，比没有更糟。
3. **它是风险表里的一项。** PLAN §6「被误判为流氓软件」的缓解清单里包含"不写服务/计划任务"；
   全局热键注册是同类观感项。删掉就直接消除，不用在打包那轮再去解释。
4. **两条替代路径都已存在且够用。** 控制条：右键宠物 / 托盘菜单；显示隐藏：**托盘左键单击**。
   删除不减少任何能力，只减少入口数量。

> 顺带印证了用户前提的正确性：`tray.ts` 的 `tray.on('click')` 默认就是
> `opts.actions.toggleVisibility`，所以"单击托盘就可以隐藏显示"**本来就是现状**，不用新写代码。

## 4. 改了什么

**删除**：`src/host/hotkey.ts` 整个模块（含 `normalizeAccelerator()` / `registerHotkey()` /
`unregisterHotkeys()`）；`prefs.hotkey` 字段；`PetMenuView.hotkey` 与菜单里那行只读的
「快捷键：…」；`BarView.hotkey`（渲染层从未渲染过这个字段，它只是随视图下发）；
`__petDebug.hotkey`（探针用）；`desktop-pet.json` 的 `interaction.hideShortcut` 默认值与降级链。

**保留但置空**：`desktop-pet.json` 里 `interaction.hideShortcut` 置为 **`null`** 并附注记 ——
让"这里曾经有过一个开关、曾经的默认值与降级链是什么"留在契约里，将来真要加回时看得见（见 ADR 012）。
同理 `Prefs` 里留注释说明旧 `prefs.json` 的 `hotkey` 字段会被自然忽略（不迁移、不报错）。

**测试**：`tools/status-arbiter.test.mjs` 原第 ⑩ 节（快捷键写法归一化，7 条断言）随被测代码一起删除，
**断言总数 319 → 312**。这 7 条不是"被跳过的测试"，是随功能消失。
分节编号**不重排**（后面 ⑪–⑯ 共 9 节），只在原处留注记 —— 重排只会让历史日志与引用对不上号。

**探针**：`spikes/m2-control/probe-key-path.js` 原来用 `pressHotkey()`（注入 Win+Alt+P）做
"收起 → 再唤出"的往返。改用**右键宠物**（它本来就是 toggle）。
**命题没有变** —— 这个探针要验的是 ADR 009 那个坑在**键盘路径**上是否复现
（hide→show 往返后键盘还进不进得来），换哪条路径都不影响结论。
删掉 `pressHotkey()` 与 `VK_LWIN/VK_MENU/VK_P` 常量，明确说明为什么。

## 5. 判据（全部实测，非推断）

| 判据 | 结果 |
|---|---|
| 完整构建 | **BUILD OK**（tsc 0 错 + 7 个 esbuild/copy 步骤） |
| 状态层单测 | **312 / 312 通过**（319 − 7 条随删除项） |
| hook 单测 | **70 / 70 通过** |
| `spikes/m2-control`（key-path + control） | **全部 PASS**：悬停唤出=false（应 false）｜右键唤出抢焦点=true｜**键盘增量 右键唤出=1、往返后=1**｜Esc 收起且不复现 |
| `spikes/m2-menu/run-tray.mjs` | **PASS**：自启写前 false → 回读 true → 撤销 false；`quit()` 后进程消失 |
| `spikes/m2-hittest`（全屏让位） | **PASS**：两轮"全屏后单击=OK 拖动=OK" |

关键的一条：**往返后键盘增量仍为 1** —— 证明删掉快捷键之后，
"hide→show 往返后键盘照常投递"这条 ADR 009 的键盘路径结论**依然成立**，没有被这次删除破坏。

## 6. 遗留

- 判据 9 第四问的"未取得数据"**随之消失** —— 功能没了，问题也就不存在了。
  判据 9 现在是三项通过、无遗留项。
- `spikes/m2-hotkey/` 整个 spike 只服务于已删除的功能，**不再进必跑清单**；
  保留目录是因为里面记录了"注册成功但永不触发"的定位过程（ADR 012 的证据来源）。
- 打包那轮（#13）不再需要复核快捷键，只需复核注册表值名与托盘图标分发。
