# ADR 033 · 打包形态 = 免安装绿色目录（挂起 #13）

**日期**：2026-09-21
**状态**：已产出可用成品，**待用户双击实测**最后一项（无控制台 + 关窗存活）
**关联**：ADR 028/029（无控制台启动）｜ADR 032（删除快捷键）｜挂起 #13

---

## 1. 决策

用户从四个选项里选了 **免安装绿色目录**：复制 Electron 官方运行时 + 应用以
**`resources/app/` 目录形态**放入 + `electron.exe` 改名 ⇒ 双击即用，**不引入任何打包器**。

产物：`dist-win/desktop-pet/`（**373 MB**），由 `node tools/make-portable.mjs` 一键生成。

## 2. 为什么不装 electron-builder

四条实测事实摆在选型前（都是本轮实测，不是印象）：

| 事实 | 影响 |
|---|---|
| 打包工具链**一个都没装**（builder / packager / forge 均无），npm 10.9.7 可用 | 装 builder 要新增依赖；它首次构建还要联网下载 nsis / winCodeSign，受限网络下常见失败 |
| koffi 的原生二进制在 `@koromix/koffi-win32-x64/win32_x64/koffi.node`，**`.node` 不能从 asar 内加载** | 走 asar 就必须配 `asarUnpack`；**目录形态天然绕开** |
| `electron.exe` 的 PE 子系统 = **2（GUI）** | 它从不自建控制台 —— ADR 028/029 的"关窗宠物消失"根因是**继承启动者的控制台**，打包后由 explorer 双击就不存在父控制台 |
| Electron 运行时 **368 MB** | 无论哪种形态都是 370MB 量级；免安装 = 打 zip 即可分发，没有安装器能把它变小 |

**代价（如实记）**：没有安装/卸载入口、没有开始菜单快捷方式；开机自启要靠托盘菜单（写注册表 Run 键）
或自己放快捷方式。这些对"自用"不成立问题，对"分发给别人"才算缺点。

## 3. 布局

```
dist-win/desktop-pet/
├── desktop-pet.exe        ← 由 electron.exe 改名（Electron 按 exe 同级找 resources/，改名是官方支持做法）
├── *.dll / *.pak / locales/ ...   ← Electron 运行时（368 MB）
├── 说明.txt
└── resources/
    ├── default_app.asar   ← Electron 自带的空壳，未被使用（它不叫 app.asar）
    └── app/               ← 应用本体，**目录形态，故意不打 asar**
        ├── package.json（main = dist/main/index.js）
        ├── dist/          ← 构建产物
        ├── assets/        ← tray.ico
        ├── pet.json / spritesheet.webp / desktop-pet.json / behavior-map.json
        └── node_modules/  ← **只带 koffi 与 @koromix**，不带整个 node_modules
```

**为什么能直接放 `resources/app/`**：`resolvePackDir()` 是 `resolve(__dirname, '..', '..')`，
而 `__dirname` = `dist/main`，上两级正好是应用根 —— 打包后就是 `resources/app`。
托盘图标 `join(__dirname,'..','..','assets','tray.ico')` 同理。**这是实测确认的，不是推断**（见 §4）。

**为什么 exe 名用 ASCII**：ADR 029 的教训 —— 含空格/非 ASCII 的路径在这台机器上反复出问题。

## 4. 判据（全实测）

用 `cmd /c start "" <exe>`（模拟双击）启动打包产物，等 18 秒读 `~/.desktop-pet/pet.log`：

```

[pet] 加载宠物包：...\resources\app
[pet] 淘淘 · 1536x1872 · 8x9 @ 192x208 · 9 个状态
[pet] 托盘已创建：...\resources\app\assets\tray.ico
[pet] 气泡层已创建 …／控制条已创建 …／行为层：启用 …

```

五条结论：**Electron 认 `resources/app/` 目录** ✅｜**koffi 加载正常**（无报错）✅｜
**托盘图标随包分发** ✅｜**状态源与渲染层全链路正常** ✅｜**`isPackaged=true`** ✅。

为拿到最后一条，给 `boot()` 加了一行启动日志（打包态诊断）。
**动机**：`app.isPackaged` 决定开机自启写进注册表的命令形态（未打包要带应用路径参数、
已打包不能带），它**只从真实运行里才看得到** —— 猜它的取值会直接写错注册表。

## 5. #13 的两项复核到什么程度

- **托盘图标随包分发** —— ✅ **已复核**：日志显示从 `resources/app/assets/tray.ico` 读出并创建成功。
- **注册表值名复核** —— ⚠️ **复核了一半**：`isPackaged=true` 已实测 ⇒ `loginItem()` 走
  `{ path: process.execPath, args: [] }`（正确的已打包分支，不会再出现开发态那种
  `electron.exe <应用目录>` 的形态）。值名由 `app.getName()` 决定，即 package.json 的
  `name` = **`desktop-pet`**（开发态是 `electron.app.Electron`）。
  **字面值未实测**：`reg.exe` 被沙箱策略拦截（不可绕过，也不该绕），
  需要用户在托盘菜单里勾一次「开机自启」后读一次注册表确认 —— 一次点击的事，非阻塞。
