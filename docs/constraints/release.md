# 约束：打包、发布与版本号

> 本文件是 `AGENTS.md` 路由表指向的硬约束之一（审计 P1-16 指出：发布这一整块此前**只散落在 ADR 里**，
> 而它恰好是最近几轮改动最频繁的部分）。**只写"必须怎么做"，理由见对应 ADR。**

---

## 1. 版本号

- **唯一真源 = `package.json` 的 `version`。** 任何地方都不许出现第二份手写的版本号
  （`tools/make-portable.mjs` 里那句 `JSON.parse(readFileSync(...)).version` 是对的写法）。
- **四处派生值必须一起验**（改完版本号只验一处等于没改）：

  | # | 派生值 | 怎么验 |
  |---|---|---|
  | 1 | exe 的版本资源（数值版 + 字符串版**都要**） | `rcedit` 写入；实测属性页显示的是**字符串版** |
  | 2 | 启动日志横幅 `==== 启动 v<版本> · … ====` | 看 `~/.desktop-pet/pet.log` **本次**的横幅 |
  | 3 | 托盘右键菜单里那一行只读小字 | 菜单模板单测（⑱ 节） |
  | 4 | 分发 zip 名 | `dist-win/desktop-pet-<版本>-win-x64.zip` |

  ⚠️ **README 不是派生值**（含"README"的旧表述已改正）：它不写版本号。
  **托盘的悬停提示也不要版本号**（用户明确，保持「淘淘 · 状态」），版本号只在菜单里。

- **什么时候跳号（ADR 045）**：
  - 触发点是**打包交付**（= 用户会拿到新构建），**不是 commit**；
  - 一次交付里攒了多件事 ⇒ **按最高的那类跳一次**；
  - **修 bug → PATCH**｜**加用户可见的新东西 → MINOR**｜
    **弄坏 ADR 041 承诺范围内的兼容性 → MAJOR**｜
    **文档 / 注释 / 单测 / 探针 / 内部重构 / 打包工具 → 不跳**；
  - **Agent 主动定并说明理由**，用户不需要记、也不需要提醒。

- **已发出去的版本号不能回收。** `1.0.0` 永远代表"含『减少动态效果会冻结动画』缺陷的那一版"。
  **"两个内容不同却同名的包"比版本号跳错更糟** —— 版本号存在的意义正是消灭它。

## 2. tag 与推送

- 每次交付给当前 HEAD 打 **`v<版本号>`** 的**轻量 tag**（**名字不带斜杠**）并推上去。
  否则事后无法回答"`1.0.0` 到底是哪份源码"。
- ⚠️ 本机 git 有一个坑：`git push` / `git fetch` 有时**报成功但 ref 不落盘**。
  **推送后必须回读核实**（`git rev-parse origin/main` 或走 GitHub API）。
- 提交身份是 **noreply**（`sleepwellzz <…@users.noreply.github.com>`，仓库级）。
  **提交前确认 `git config --local user.email` 没被改回真实邮箱。**
- **`backup-pre-author-rewrite` 分支禁止推送**（它带真实邮箱，从未推送过）。

## 3. 打包（`tools/make-portable.mjs`）

- **步骤（顺序不能颠倒）**：
  1. `node tools/run-build.cjs`（**打包脚本自己不构建**，它只复制 `dist/`）；
  2. `node tools/make-portable.mjs --zip`。
- **打包前先关掉正在运行的桌宠**：只按 `desktop-pet.exe` 杀，**绝不碰 `electron.exe`**
  （宿主 WorkBuddy 本身也是 Electron）。不关的话旧产物移不开，脚本会给出可读提示并
  **保持旧产物分毫未动**（ADR 052）。
- **`dist/` 与 `src/` 不同步时脚本拒绝打包**（比内容哈希，不是 mtime —— ADR 047 / 050）。
- **事务性**（ADR 052）：所有写操作先到 `.staging-<pid>`，全部成功后才原子换入最终路径；
  zip 先写 `.tmp`、`verifyZip()` 通过（头签名 + 末尾 EOCD + 中央目录自洽）才换名，
  **换名后再回读最终文件本身**。
- **分发形态**：单位是**整个目录**，对外压成**一个 zip**。
  - **目录名不带版本**（自启注册表记的是绝对路径，改名会让老用户的条目失效）；
  - **zip 名带版本**；
  - **进 zip 的文件名必须 ASCII**（非 ASCII 会被写坏）；
  - **`desktop-pet.exe` 不能单独发人** —— 只发 exe，对方双击**毫无反应且无报错**。
- **发行包默认排除 `*.map`**（ADR 052）：esbuild 的 sourcemap 内嵌完整 TS 源码。
  确实要调试时用 `--keep-maps`。
- **`README.txt` 与 exe 版本资源里的值一律 ASCII**（中文写进去在部分读取路径上会变乱码）。

## 4. 自启（与打包耦合，容易漏）

- 注册表值名 = `electron.app.` + **exe 版本资源的 `ProductName`**
  （不是 app `package.json` 的 `name`，也不是 `app.setName()` —— 三种都实测过，ADR 036）。
- ⇒ **改 `ProductName` 就是改用户的注册表值名**，属于 MAJOR 级影响（ADR 046 / 041）。
- 旧值名条目由应用启动时**自动迁移**（幂等、只动指向自己的）。

## 5. 打包后的核验（ADR 044 的纪律）

**"打包成功"必须回读产物本身** —— 体积 / 退出码 / 日志文案都会说谎：

- 至少做一次**独立解压**（Windows 用 `Expand-Archive`，或 7-Zip / `tar -tf`）并与源目录做
  全量 SHA-256 比对；
- **不要用 `tar -a -c -f x.zip`**：实测它**静默产出过一个 tar**（exit 0、还打印"zip 完成"）。
