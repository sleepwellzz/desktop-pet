# 约束 · 窗口、命中、控制条、定时器

> 2026-09-18 从 `AGENTS.md`「硬性约束」按主题拆出（内容未改，只搬位置）。
> 触发：改窗口创建/显示/隐藏/移动/缩放、命中判定、控制条、定时器、指针事件时读这份。
> **本主题的三条回归探针必跑**（见文末）。

- **点击命中由渲染层按当前帧精灵 alpha 判定**，窗口常态整窗穿透；不要回退到"让系统按窗口矩形命中的
  做法"，也不要再用 `setIgnoreMouseEvents(..., { forward: true })`（ADR 008）。
- **渲染层的指针事件别按 `e.button === 0` 过滤 `pointermove`**：`pointermove` 的 `button` 是 **−1**，
  这样写会静默吃掉整段拖动（计数正常、窗口不动，ADR 011 负面结论）。
- **凡是"位置类参数"都要显式传入，不许让下游自己猜**（ADR 021）：
  `bubble-layer.ts` 的 `show()` 曾在从未 `followPet()` 过时执行
  `if (!lastPetBounds) lastPetBounds = win.getContentBounds()` ——
  **把气泡窗口自己的矩形当成了宠物矩形**，于是气泡跑到屏幕正中。
  **与 ADR 017 那条"没有 `ts` 不等于刚刚"是同一类错误：兜底值取了一个"看起来像但不等于"的东西。**
  纪律：**拿不到就"不显示"，而不是显示在错的地方**。

## 显示 / 隐藏 / 焦点

- **`hide()` 之后要重新显示，宠物窗口只能走 `resumePet()`**（show + reload 渲染层）。任何地方单独写
  `win.show()` 都会留下"看着正常但点不动"的窗口（ADR 009）。
  **注意适用范围**：实测该现象**只影响鼠标按钮事件、不影响键盘**，且只对"会接收按钮事件"的窗口成立 ——
  气泡层与控制条都不需要 reload（ADR 014 负面结论 1）。
- **新增或修改可聚焦窗口时记住两条**（ADR 014 负面结论）：
  ① 不要用 `win.isVisible()` 判断"要不要 show"—— `show()` 后同一 tick 内它可能仍返回 false，
  会导致抢焦点的路径重复 `show()` 一次（第二次是 `showInactive`，正好把焦点让出去）；用 `show`/`hide` 事件记账。
  ② 要排除出 Alt+Tab 必须**显式设 `WS_EX_TOOLWINDOW`** —— `skipTaskbar: true` 不加这个样式位。

## 控制条

- **控制条的唤出只有两条显式路径：右键宠物 / 托盘菜单「控制条」，一律抢焦点；
  不要加回悬停唤出**（2026-09-17 用户拍板删除，ADR 016）——桌宠常驻角落、光标是顺便掠过的，
  自动弹出必然变成"我没叫它它自己冒出来"，而且会与"左键单击播动作"争夺同一个瞄准动作的语义。
  **第三条「全局快捷键 `Win+Alt+P`」已于 2026-09-21 整块删除（ADR 032）** —— 用户不用，
  且它从未被真实按过一次；`desktop-pet.json` 里 `interaction.hideShortcut` 现为 `null`（保留键位与注记）。
  **两处右键分工不同**：宠物右键 = 控制条；托盘右键 = 完整菜单（面板「⋯」也是这份）。
  **隐藏宠物后唯一的快捷入口是托盘左键单击**（`tray.ts` 的默认 `toggleVisibility`）——
  删掉快捷键之后这条是唯一兜底，不要动它。
  面板动作排里显示的是**宠物名**（`pet.json` 的 `displayName`），没有缩放控件（那在菜单里）。
- **面板高度算式是四段，不是三段**（2026-09-22 加动作排，ADR 038）：
  `headerHeight + 会话行数 × rowHeight + 动作排行数 × actionRowHeight + footerHeight`，
  其中动作排行数 = `ceil(动作个数 / actionColumns)`。两个新参数
  **随 `BarView` 下发**（渲染层不写死，连 CSS 里一行 `grid-auto-rows` 都不许有）——
  主进程按它们算窗口高度再 `setContentBounds`，两边各写一份就是"面板比窗口矮一截、底部被切"。
  改这两条只改 `desktop-pet.json → controlBar`。
- **手动把玩（面板动作排）的按钮走 `play-action` 命令**，`arg` = 状态 id，主进程校验它真的在宠物包里
  （与 `ack-session` 同一条白名单纪律）。**它不碰仲裁器** —— 手动把玩走动画覆盖通道，
  所以**不产生气泡**（这是"手动 = 陪它玩 / agent = 有事告诉你"的实现方式，不是靠 if 判断）。
- **位移类手动动作会把面板收起来、走完再还回来**（ADR 039）。三条不许动的：
  ① **判据是"这一下真的会移动窗口"**（`targetX !== null`），不是"是不是位移姿态" ——
  贴边降级成原地演时宠物不动，没有理由收走面板；
  ② 这份"待恢复"（`BarState.restoreAfterWalk`）**住在 `kernel/bar-policy.ts`**，
  不许搬进主进程当布尔 —— 它决定"面板会不会自己冒出来"，必须能单测（ADR 016 的地盘）；
  ③ 三条不变量（**只有 `walk-hide` 能置位且仅当可见 / 可见即作废 / `pet-hidden`+Esc+× 也作废**）
  缺一条就有真实缺陷：**少了第三条，走路期间宠物被隐藏时走完会把面板开到半空**。
- **控制条的面板按钮此前从未被「真实鼠标」点过**（探针一律用 `b.click()` 合成事件，
  **绕过 Windows 的输入路由**）。2026-09-22 补上用例 ⑫c 实测：**面板自己 hide→show 之后，
  真实鼠标点击仍然有效 ⇒ ADR 009 不适用于控制条，不需要 reload**。
  **改这块时别把那条真实点击的用例删了** —— 它是这个面唯一的证据。

## 定时器

- **新增周期性定时器必须挂进 `main/index.ts` 的 `timers` 记账**（ADR 023）：33ms 行为 tick 与 16ms
  光标轮询由 `show`/`hide` 事件驱动 `startTimers()`/`stopTimers()` —— 宠物隐藏时它们会真的停下。
  **裸写 `setInterval` 就等于"宠物藏起来还在空转"**，而且退出时会撞上 `Object has been destroyed`。
  **250ms 的仲裁器 tick 是例外，故意常开** —— 隐藏期间托盘状态与面板仍要更新。
  若要加"隐藏时不该跑"的定时器，登记进去；若要加"隐藏时也要跑"的，在注释里写清理由。
