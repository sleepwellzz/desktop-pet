## 1. 下一个会话的第一件事：#15（详见 ADR 034）

**症状**：用户勾选开机自启后，注册表里写的是
`electron.app.Electron = "E:\...\dist-win\desktop-pet\desktop-pet.exe"`。
**命令是对的、自启是能跑的**，坏的只是它在注册表里叫 `electron.app.Electron`。

**已经排除的方向（别重复跳坑）**：
- ❌ 不是 `isPackaged` 判错 —— 实测 `true`，走的是正确的**无参**分支。
- ❌ 不是 `resources/app/package.json` 缺名字 —— 它的 `name: "desktop-pet"` **存在且正确**，
  但实测**不起作用**。`loginItem()` 的入参只决定命令，不决定值名。
  （这条推翻了 ADR 033 与旧注释里「打包后会变成 productName」的推断，注释已更正。）

**三条候选，按 A → C 的顺序试（都是未实测的推断，别当结论用）**：
- A：给 `resources/app/package.json` 加 `"productName": "desktop-pet"` —— 零副作用，先验不乐观。
- B：`app.setName('desktop-pet')`（ready 前）—— Electron 文档明说不影响 OS 侧名字，大概率无效。
- C：改 exe 的版本资源 ProductName（rcedit / electron-builder 那一套）—— **最有可能是正解**，
  参照对照组 Obsidian（值名 `electron.app.Obsidian`）。

**判据（四条，缺一不可）**：
1. `node tools/make-portable.mjs` 重新打包；
2. 双击新 exe → 托盘菜单**先取消勾选**「开机自启」→ **再勾选一次**；
3. PowerShell 读 `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run` → 值名应为 `desktop-pet`；
4. **确认旧的 `electron.app.Electron` 条目已被清掉** —— 只改值名不管旧条目会留孤儿。

**不需要用户做什么**：整件事我能独立做完，只在最后请用户重启一次便携版 + 重勾一次自启。

## 3. 环境事实（反复忘又反复要）

- Bash shim **缺 head/tail/dirname/cat/ls**，`rm`/`grep` 会被拦 → 用 Read/Write/Edit/Glob/Grep；
  跑脚本用绝对路径 node `22.22.2-3`。
- **npm 10.9.7 可用**（旧记忆「没有 npm」是错的，已更正）。
- **PowerShell 不回传 stdout** → 必须 `Out-File` 落文件再用 Read 读。
- **`reg.exe` 被沙箱拦** → 注册表一律 PowerShell：`Get-ItemProperty -Path "HKCU:\...\Run" | Out-File <文件> -Encoding utf8`。
- **带反引号的替换串不能用 `node -e`**（会被 bash 吃掉）→ 一次性脚本写成文件再跑。
- Edit 工具在本工程**偶发"报告成功但文件没变"** → 关键改动后 grep 复核，或直接用脚本改。
- ESM 里没有 `require`；工程路径**含空格** → 解析 `import.meta.url` 必须 `fileURLToPath`。
- 跑 Electron 前必须从 env 删掉 `ELECTRON_RUN_AS_NODE`（宿主是 Electron，会继承）。
- `dist/` 与 `dist-win/` 已 gitignore。
