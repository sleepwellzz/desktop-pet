## 1. 为什么现在最该做气泡

当前状态下，"是什么状态"只能从**动作**猜：宠物在过生日 = 运行中、趴着 = 受阻、举着手 = 需要输入。
可这只包的作者在第 7 行画的是生日姿态，普通用户根本猜不出来。**气泡是把状态"说清楚"的唯一手段**，
它比控制条更接近产品的核心价值（"把 agent 的活动状态可视化"）。
`desktop-pet.json` 的 `statusMap` 里文案早就配好了（运行中 / 需要输入 / 已受阻 / 就绪（未读）），
一直没画 —— 本轮把它补上。

## 3. 关键决定：气泡用**独立窗口**，不动宠物窗口

**不用"把宠物窗口扩大，在边上画气泡"**：那会改窗口矩形 ⇒ 命中判定的坐标系、边界、
"整窗穿透 vs 可交互"的切换全都要重新验证 —— 正是 ADR 008/009 用两轮真实点击实测换来的地盘。

改为新增一个**气泡层窗口**（`src/host/bubble-layer.ts`）：

| 属性 | 值 | 理由 |
|---|---|---|
| transparent / frame:false / skipTaskbar | 是 | 与宠物层一致 |
| `focusable: false` | 是 | 绝不抢焦点（硬性约束） |
| `alwaysOnTop('screen-saver')` | 是 | 与宠物同层 |
| `setIgnoreMouseEvents(true)` | **常态、永不切换** | 气泡不可点 ⇒ 不存在"命中判定"这回事 |
| 位置 | 贴宠物上方居中；宠物被拖动时同步跟随 | 在 `overlay.moveBy()` 里顺带跟随 |
| 尺寸 | 按内容自适应（文本长度 + 角标宽度），有最小值 | 用 `setContentBounds`（ADR 008） |

**为什么这个方案风险最低**：它**永远不接收按钮事件**，所以 ADR 009 那个
"`hide()`→`show()` 之后 Windows 不再路由鼠标按钮事件、必须 reload 才能恢复"的坑**与它无关** ——
气泡层从不需要 reload，也不参与命中判定。宠物窗口一行代码不动。

全屏让位时气泡与宠物一起隐藏（直接 `hide()`，恢复时 `show()` 即可，不需要 reload）。

## 4. 气泡的显示策略（真值仍来自仲裁器）

文案取 `arbiter.state.bubble`（来自 `statusMap`，idle 为 `null`），显示时长按状态分级：

| 状态 | 建议 | 理由 |
|---|---|---|
| `needs-input` | **常驻**，直到 ack 或状态变化 | `attentionPulse: true`，与粘滞语义一致；这是用户最需要看见的一条 |
| `ready` | 显示 6 秒后淡出 | "未读结果"提示，看过就够 |
| `blocked` | 显示 4 秒后隐藏 | 需要知道但不必长期占屏 |
| `running` | 显示 2 秒后隐藏 | 频繁出现，长期挂着一行字会烦人 |
| `idle` | 立即隐藏 | — |

两条细节：
- **同一状态重复推送不重置计时**（否则 hook 每次心跳都会把气泡刷新出来）；
- 时长写进 `desktop-pet.json` 的新 `bubble` 段（sidecar 纪律：自研参数不写进 `pet.json`，ADR 002），
  代码里给同样的默认值。

角标 `+N`（`badgeCount ≥ 1`，多会话）：**与气泡同生共死**，显示在气泡右侧。
好处是任何长期占屏的 UI 都由同一套策略管；代价是"空闲但有其他会话在跑"时不会单独露出角标
（那种情况气泡本来就不会显示）。→ 这条列入 §8 待确认。

## 5. 气泡层怎么画

- 新增 `src/renderer/bubble.html` + `src/renderer/bubble.ts`：**用 DOM 渲染，不用 canvas**
  （文字排版/圆角/自适应交给浏览器，省事且清晰）；
- 构建链要加一个入口（ADR 005 的顺序：`build:main → build:preload → build:renderer → build:bubble → copy-assets`）；
- 新增 IPC `pet:bubble`（主进程 → 气泡层）：`{ text: string | null, badge: number }`。
  `text === null` 表示隐藏自己（窗口与内容一起收）；
- 主进程侧的策略调度（"显示多久"）放在 `src/main/index.ts` 的一个小状态机里，
  输入是 `arbiter.state`，输出是"发什么给气泡层"。

## 6. 全局快捷键

模块 `src/host/hotkey.ts`：

```ts
export function registerHotkey(accel: string, cb: () => void): boolean;
export function pickHotkey(preferred: string, fallbacks: string[]): { accel: string; ok: boolean; tried: string[] };
export function unregisterAll(): void;
```

- 注册失败按**备选列表**依次降级；全部失败则**明确提示**（日志 + 托盘 tooltip），
  并如实告诉用户"快捷键不可用，请从托盘或右键菜单操作"（不静默失败）；
- **本机实测（本轮已跑探针，`spikes/m2-hotkey/`）**：
  `Super+Alt+P`（规格默认）✅ 可用；`Super+Shift+P` ❌ **已被占用**；
  `Ctrl+Alt+P` / `Super+Alt+Space` / `Ctrl+Shift+Alt+P` / `Ctrl+Alt+B` ✅ 可用。
  所以默认值可用，降级链仍按要求实现；
- 自定义：`prefs.json` 的 `hotkey` 字段（本轮不做按键捕获 UI）；
- 本轮动作：**切换宠物显示/隐藏**（复用托盘的动作表）。下一轮控制条上线后再加"唤出控制条"。

## 8. 需要确认的三点

1. **本轮范围**：只做"气泡 + 角标 + 快捷键"（建议，控制条下一轮），还是连控制条一起做？
2. **气泡时长策略**：按 §4 的分级（needs-input 常驻、其余短显）／全部常驻／全部短显？

## 9. 本设计不做的事

- 不改宠物窗口的任何尺寸/位置/命中逻辑（这是本方案的核心取舍）；
- 不做控制条与快捷输入（下一轮）；
- 不做按键捕获设置界面；
- 不引入新的状态源通道。
