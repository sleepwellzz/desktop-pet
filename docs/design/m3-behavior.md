# M3 · 行为层（自主漫游 / 微动作 / 打盹 / 任务中踱步）

- **状态**：已落地（本文档按"先设计后写码"的格式记，实际是**与实现同期**写的 —— 见文末"实现回写"）
- **决策**：全部落在 **ADR 018**
- **代码**：`src/kernel/behavior.ts`（策略，纯函数）｜`src/main/index.ts`（接线）｜
  `src/renderer/renderer.ts`（动画覆盖）｜`src/shared/ipc.ts`（三个契约）｜`desktop-pet.json`（参数）
- **判据**：`tools/status-arbiter.test.mjs` ⑭ 段（22 项）＋ `spikes/m3-behavior/run.mjs`（真实窗口 7 条）

## 1. 目标与边界

让宠物在**没人用它**的时候像个活物：会自己走两步、偶尔做个小动作、长时间没任务就趴下打盹。
参数早在第一版 sidecar 里写好了（`desktop-pet.json → behavior`），但一行没实现 —— 本轮把它做出来。

**边界（这轮明确不做）**：

- **有任务时只做小动作**：主状态不是 `idle` 就切到"踱步模式" —— 低频、短距离、锚在进入任务状态
  时的位置附近（ADR 019）。**不会**在 `running` 期间满屏乱跑。
- **不打搅用户**：拖动中、宠物被隐藏、全屏让位、控制条打开、"减少动态效果"下都不动。
- **不跨屏**：只在当前窗口所在显示器的工作区内活动 ⇒ 把宠物拖到哪块屏，它就在哪块屏活动。
  这是**锁定的范围**（2026-09-18 用户明确暂不考虑多屏），不是"暂时不做"：
  真要做跨屏，得先把"穿越过程中窗口矩形算哪一屏"与"多屏工作区并集"定义清楚。
- **不做"表现忙碌"的动作**：早先记的那条"运行中看起来像在忙"已作废 —— 用户不认这个动机
  （不记得当初为何记它）。取而代之的是下面这条更小的要求：**可以离开原位，但不超过几百像素**。
  名字也不再叫"忙碌动作"。

### 1b. 任务进行中的踱步（ADR 019，2026-09-18 追加）

| 点 | 结论 |
|---|---|
| 能不能离开原位 | **能**，但上限 300px（用户说"三四百像素"） |
| 方向 | 朝**工作区中心**那一侧。宠物默认在右下角 ⇒ 表现为"往左走几步"；固定朝左在贴左边缘时会永久失效 |
| 频率 | 每 **60–180 秒**一次，刻意比空闲漫游更稀疏 —— 它是点缀，不是主要活动方式 |
| 目标怎么算 | **由锚点算，不由当前位置算**（`anchorX ± distancePx`）。按当前位置累加会越踱越远，"不超过几百像素"会在几分钟后悄悄失效且无任何报错 |
| 锚点什么时候重记 | 进入任务状态时；每次抑制（拖动/隐藏/全屏/控制条）结束后 |
| 打盹 | 有任务时**不计**（`idleSinceAt` 恒为 null）—— 打盹是"没人理它"，正在干活不该趴下 |
| 演什么 | 走路期间画位移行（第 1/2 行），到达后交回业务状态动画。见 ADR 019 负面结论 1 |

## 2. 分层（延续既有架构，不新开一条路）

| 层 | 文件 | 职责 | 不做什么 |
|---|---|---|---|
| 策略 | `kernel/behavior.ts` | 纯函数：**什么时候走、走到哪、演什么、什么时候打盹**；时钟与随机数可注入 | 不碰窗口、不碰 IPC、不读文件 |
| 接线 | `main/index.ts` | 攒输入（窗口矩形/工作区/缩放/主状态/抑制原因）→ 调 tick → 落命令 | 不做判断 |
| 渲染 | `renderer/renderer.ts` | 接住动画覆盖，期间不再把播放器收敛回主状态 | 不自己决定演什么 |

**为什么策略必须是纯函数**：这套规则全是"到点才发生"的，25 秒还是 28 秒后开始走在屏幕上
完全看不出对错；而它偏偏又是最容易把宠物弄坏的一块（与用户拖动抢方向盘、走出屏幕、运动时点不动）。
与 `bubble-policy` / `bar-policy` 同一个理由、同一套做法。

## 3. 决策点（D1–D6）

| 编号 | 问题 | 结论 |
|---|---|---|
| D1 | 有任务时动不动？ | **只踱步**（ADR 019 修订了 018 的"完全不动"）：低频、短距离、锚在进入任务状态时的位置附近；方向朝工作区中心侧 |
| D2 | 位移速度的单位与缩放关系？ | `speed = baseline × 当前缩放 / 默认缩放`（默认缩放 0.7 时 96 px/s），保证大小不同时"每秒几个身位"的观感一致。踱步沿用同一基线 |
| D3 | 走到屏幕边缘怎么办？ | 目标点**夹进工作区**；够不到就换方向；两头都够不到就放弃这次并重排程 |
| D4 | 打盹计时被漫游重置吗？ | **不重置**。只在"主状态离开 idle"或"用户碰了它"时重置 —— 否则 25–90 秒走一次会把 5 分钟推后成永远睡不着。有任务时压根不计（`idleSinceAt` 恒为 null） |
| D5 | 拖动/隐藏/面板开着时？ | 不动、不改相、保留排程（松手接着走），但**交回动画**（别举着"正在跑"的腿被抓住）；踱步模式下顺带**清掉锚点**（恢复后在新位置重新锚定） |
| D6 | 位移姿态与微动作候选从哪来？ | 位移姿态按 `role`（`locomotion-left/right`）推导，候选过滤掉包里不存在的状态 —— **不硬编码状态名**，换宠物包还能跑 |
| D7 | 踱步目标从哪算？ | **从锚点算**（`anchorX ± distancePx`），不从当前位置算 —— 后者会越踱越远，让"不超过几百像素"在几分钟后悄悄失效（ADR 019） |

## 4. 状态机（`kernel/behavior.ts`）

相位：`idle` / `roaming` / `acting` / `sleeping` / `pacing`。每 tick 的优先级：

```
0. 未启用                     → 归零，交回仲裁器（play: null，边沿只发一次）
1. 主状态 ≠ idle               → 踱步模式（tickBusy）：锚定 / 抑制 / 到点走一小步
2. 刚从踱步模式回空闲          → 清踱步记账、重新排程（不会立刻乱跑）
3. suppressed                 → 不动、不改相、保留排程；交回动画
4. 空闲 ≥ sleepAfterMs         → 打盹（播 sleepState，循环）——但不打断正在走的这一程
5. 微动作到点                  → 播一个候选（一次性），clipMs 之后回 idle
6. 漫游到点                    → 挑目标、按朝向播位移姿态、按 speed×dt 逐 tick 推进
                               → 到达则贴上去、停下、重排程
```

**命令是三态的**（`play` 字段）：缺省 = 不变 / `null` = 交回仲裁器 / 对象 = 按它演。
三态而不是两态，是因为"没有新指令"和"撤销覆盖"在窗口上的效果完全不同 ——
混成一个 `null` 会让渲染层每 tick 被重置一次（走路会被每秒压回去 30 次）。

## 5. 参数（`desktop-pet.json → behavior`）

| 字段 | 值 | 说明 |
|---|---|---|
| `enabled` | true | **总开关**（false = 只会原地发呆） |
| `idleRoam.everySec` | [25, 90] | 两次漫游的间隔区间 |
| `idleRoam.distancePx` | [80, 320] | 一次走的距离区间 |
| `idleRoam.speedPxPerSec` | 96 | 默认缩放下的速度 |
| `idleMicroActions.candidates` | waving / jumping | 偶尔做的小动作 |
| `idleMicroActions.everySec` | [40, 150] | 小动作间隔 |
| `busyPace.everySec` | [60, 180] | 任务进行中的踱步间隔（比漫游更稀疏） |
| `busyPace.distancePx` | [60, 300] | 每一步离**锚点**多远；上限同时就是"最多离开锚点多远" |
| `busyPace.speedPxPerSec` | 96 | 与漫游同基线（位移速度是照着位移行步频校过的，另取一值会滑步） |
| `sleepAfterIdleSec` / `sleepState` | 300 / failed | 打盹阈值与姿态（复用趴卧帧，不需要新美术） |

## 6. 判据（怎么知道它是对的）

**离线（秒级、虚拟时钟、固定随机种子）**：`tools/status-arbiter.test.mjs` ⑭ 段（219 项）——
启动不立刻乱跑、到点才走、速度按缩放归一化、目标夹进工作区、贴边换方向、抑制期间不动、
有任务时交回动画并进入踱步模式、**踱几十次不漂出锚点**、**默认节奏下 10 秒一次都不踱**、
**换到另一块屏时目标夹在新工作区内**、打盹与醒来、微动作只在候选里挑、边沿命令不重发、总开关。

**真实窗口**：`spikes/m3-behavior/run.mjs` —— 用**临时宠物包**（只改行为参数：2–3 秒走一次、
3–5 秒踱一次、20 秒打盹）验 7 条：真的在走 / 只沿地平线走 / 不越出工作区 / **行号与方向一致** /
抓住时一步不动且松手恢复 / 控制条开着不动 / **running 期间在动但离锚点不超过上限** /
打盹画到第 5 行且单击能醒。

## 7. 实现回写（值得记的几处）

1. **`play` 从两态改成三态**（见 §4）。第一版是 `play: {...} | null`，结果"没有新指令"和
   "撤销覆盖"在调用方看来一样 —— 只能每 tick 都发一次 `null`，等于把渲染层按住。
2. **打盹计时不能被漫游重置**（D4）。第一版在"开始漫游/到达/微动作结束"三处都重置了
   `idleSinceAt`，于是"每 25–90 秒走一次"把 5 分钟无限推后 —— **它永远睡不着**，
   而屏幕上只会表现为"它就是不打盹"，没有任何报错。已用单测钉住（"走完这一程就打盹"）。
3. **单位写进字段名**：`roamEveryMs` / `microEveryMs` 必须真是毫秒。第一版把秒留在字段里、
   到用的时候再 `× 1000`，单测里按名字写 `{min:100,max:100}` 期望"100 毫秒后动"，
   实际变成 100 秒 —— 红了才发现。这类"名字与单位不一致"的坑不值得留给下一个人。
4. **回归探针需要 `--no-behavior` 接缝**：宠物会自己走，位置类断言（命中图、控制条贴边、
   托盘点击坐标）全都变脆 —— 探针读一次窗口位置、再按它算点击坐标，中间宠物走掉了就点空。
   给主进程加了这个开关（与 `--no-status-source` 同一套路），既有探针全部带上它。
5. **注入点击不能打窗口中心**：命中判定是渲染层按当前帧 alpha 给的（ADR 008），
   而趴卧姿态的精灵贴在单元格底部 ⇒ 窗口中心是透明的 ⇒ 那时窗口整窗穿透，按下根本到不了
   渲染层。探针改成先用 `dbg.petInteractive()` **扫出一个真的落在精灵上的点**再点。
   这是"探针第一版假红两条"的直接原因。
6. **锚点必须由锚点算，不能由当前位置算**（ADR 019）：漫游可以按"当前位置 ± 距离"累加
   （它本来就是随机游走），但踱步被明确要求"不超过几百像素"。按当前位置累加会让这条要求
   在几分钟后失效，而屏幕上只表现为"它怎么跑那么远"。这也是本轮唯一一个
   **"看起来只是参数问题、实际是结构性要求"**的点。
7. **从踱步模式切回空闲必须显式清相**（`tickBehavior` 规则 2）：`idleSinceAt` 在踱步模式下
   恒为 null，回到空闲正是靠它变回 now 才触发首次排程。若不清 `phase`，宠物会带着 `pacing`
   相停在半路 —— 表现是"停在那儿不动，也不漫游"，同样没有任何报错。
8. **测试里"交回动画"只在真有覆盖可交时才会发生**：本轮单测第一版断言"关掉踱步后仍交回一次"，
   但初始状态本来就是干净的（`sentPlay === null`），于是它正确地什么都没发 —— 是我断言写错了。
   修法是把用例的初态设成"带着位移覆盖"，而不是放宽断言。
