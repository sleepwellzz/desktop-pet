# 设计：换宠物（接口、可行性、落地路径）

> 状态：**方案（未实现）**。ADR 049 把"可换宠物"定为正式目标，并明确
> **"先建判据，不先建界面"**。本文回答的是它留下的那个问题：**界面怎么做、接口长什么样**。
>
> 用户 2026-09-29 的要求原话是"**搭建一个方案，或者构思一个接口，或者提供可行性的方式**" ——
> 本文就是那三样，**不含实现**。

---

## 0. 一句话结论

**能做，而且不难 —— 但"运行时热切换"是这条路上唯一真正危险的部分。**
建议的做法是：**切换 = 记住选择 + 重启**（`app.relaunch()`）。
它把全部风险挡在"启动路径"之外，而启动路径正是本项目已经跑了五套真实窗口回归的那条。

预计实现量：**目录约定 + 一个 prefs 字段 + 一个子菜单 + 重启**，约 80 行；
判据（`check-pet-swap` 已有，补一条"选择被记住"）已大半就位。

---

## 2. 缺的三件东西

1. **一个"哪里有宠物"的约定** —— 现在只能靠命令行传绝对路径。
2. **记住用户选了哪一只** —— `prefs.json` 里没有这个字段。
3. **一个让用户选的地方** —— 目前没有任何 UI 入口。

---

## 3. 接口设计

### 3.1 目录约定（新增，向后兼容）

```
<工程根>/pets/                 ← 新增，可选
├── taotao/                    ← 现工程根的三份配置 + 图集（= 现在这只）
└── <其他包>/
```

**兼容规则（重要，不能破）**：
- 工程根本身**仍然是一个合法的宠物包**（现状不变，`pets/` 不存在也照常工作）；
- 解析顺序：`--pet=` 命令行 → `prefs.petDir` → 工程根。
- `pets/` 下每个子目录都要能过 `check-pet-swap`；**不过的不进列表**（而不是进了列表再报错）。

> 为什么不强制搬家到 `pets/`：自启注册表与用户习惯都锚在工程根（ADR 041 承诺的分发结构）。
> 迁移是**破坏性**的，而收益只是"目录好看"。

### 3.2 `prefs.json` 新增字段

```jsonc
{
  "scale": 0.7,
  "petDir": "pets/shiba",      // 相对工程根的路径，或绝对路径；缺省 = 工程根
  "theme": "auto"              // 见 docs/design/ui-theme.md
}
```

**为什么存路径而不是 id**：id 会撞（两个包都叫 `taotao`），路径不会。
**为什么要能是绝对路径**：用户可能把包放在别处（比如共享盘）；
`--pet=` 已经支持绝对路径，prefs 与它保持一致才不会有"命令行能跑、菜单选了不认"的怪事。

> ⚠️ **ADR 041 的兼容承诺**涵盖 `prefs.json` 的字段 ⇒ 这是**加字段**（向后兼容），
> 不是改语义。老用户的 `prefs.json` 没有这个键，读出来是 `undefined` ⇒ 回落工程根，行为不变。

### 3.3 主进程接口（新增）

```ts
/** 列出可切换的宠物包（含工程根自己）。不启动任何窗口，纯文件扫描 + 体检。 */
function listAvailablePets(): Array<{
  dir: string;        // 绝对路径
  label: string;      // pet.json 的 displayName ?? id
  ok: boolean;        // 是否通过 check-pet-swap 的等价体检
  problems: string[]; // 不过的原因（面板上要显示给用户看）
}>;

/** 切换宠物：写 prefs + 重启。**不重建窗口** —— 见第 5 节。 */
function switchPet(dir: string): void;
```

**`switchPet` 的实现是本文最核心的一行决定**：

```ts
function switchPet(dir: string): void {
  savePrefs({ ...loadPrefs(), petDir: relative(ROOT, dir) });
  app.relaunch();          // 用同一份命令行重启
  app.exit(0);
}
```

### 3.4 菜单与面板入口

- 托盘右键 → **新增子菜单「换宠物」**，列出 `listAvailablePets()`；
  当前那只打勾（`type: 'radio'`）；不适用的项置灰并把 `problems[0]` 放进 tooltip。
- 控制条面板：**本轮不加按钮**。面板已经很挤（状态行 + 会话行 + 9 个动作 + 动作排），
  而换宠物是**低频**动作 —— 低频动作不该占常驻面板的位置。

## 4. 为什么不走「运行时热切换」（重要）

"不重启就换掉宠物"看起来更爽，但它是这条路上唯一真正危险的部分：

1. **它要销毁并重建 `BrowserWindow`**，而 ADR 009 实测过：该窗口 `hide()`→`show()` 之后
   Windows 不再把**鼠标按钮事件**路由给它，唯一可靠的恢复手段是重载渲染层 ——
   重建窗口是这条链上更激进的版本。
2. **本项目三个崩溃全出在这条路上**：ADR 035（定时器越过已销毁窗口）、
   ADR 038（面板收尾没执行）、ADR 042（菜单回调守错对象），
   以及本轮刚修掉的第四个（`tickBehaviorLayer` 撞已销毁窗口）。
3. 切换要重建的东西不止窗口：托盘（图标要换成新宠物的脸）、气泡层、控制条、
   仲裁器（`statusMap` 换了）、行为层策略、手动把玩动作表、命中阈值……
   **每一个都是"换完还是旧的"这类静默失败的候选**。

**成本对照**：

| 方案 | 工作量 | 风险 | 用户感知 |
|---|---|---|---|
| **重启式**（推荐） | ~80 行 | 低（走的是已回归过的启动路径） | 宠物消失约 1 秒后换脸回来 |
| 热重建 | ~400 行 + 五套窗口回归 | 高（见上） | 无缝 |

⇒ **先做重启式**。等 `pets/` 下真有 ≥2 只常用宠物、且热切换的必要性被真实抱怨过，
再考虑热重建 —— 那时要补的是**每条重建路径的回归判据**，不是先写代码。

## 5. 判据（这套接口的验收标准）

| 判据 | 怎么验 | 现在能不能跑 |
|---|---|---|
| 包合规 | `node tools/check-pet-swap.mjs <包目录>` | ✅ 已有（ADR 049） |
| 工程根自己仍然合法 | 主单测 ⓪d 节每次跑 | ✅ 已有 |
| 启动参数优先级 | `--pet=` > `prefs.petDir` > 工程根 | ❌ **待补**（纯函数，可单测） |
| 选择被记住 | 写 prefs 后重启，`resolvePackDir()` 返回新目录 | ❌ 待补（`resolvePackDir` 可注入 prefs 变成纯函数） |
| 非法包不进列表 | `listAvailablePets()` 过滤掉体检不通过的 | ❌ 待补 |
| 换包后托盘图标跟着换 | 包内 `tray.ico` 的读回路径 = 新包目录 | ❌ 待补（探针可查，不启动 Electron：直接读解析函数） |

> **建议顺序（ADR 049 已定，这里细化）**：
> ① 把 `resolvePackDir` 拆成"纯函数 + 注入 prefs" ⇒ ② 补上面三条判据 ⇒
> ③ 造**第二个真实宠物包**放进 `pets/` ⇒ ④ 最后才加菜单项。
> 理由：前两步让"选择逻辑"在没有任何 UI 的情况下就可验证；
> 第三步让 `check-pet-swap` 有第二个真实使用者（**判据只有一个使用者时，它的设计对不对无从检验**）；
> 第四步才是"让用户看见"。

## 6. 与本项目既有决策的关系

| 决策 | 关系 |
|---|---|
| ADR 046 后半句「不打算做成可换宠物的平台」 | **已被 ADR 049 推翻**（本文在它的延长线上） |
| ADR 046 前半句「对外定位是叫淘淘的软件」 | **保留** —— 所以"换宠物"是**能力**，不是卖点；菜单文案不要写成"宠物市场" |
| ADR 041 的分发结构承诺 | **不破**：目录名与入口名不变，`pets/` 是新增的可选子目录 |
| ADR 049「运行时切换 UI 排后」 | 本文把它具体化为"**重启式优先，热重建押后**" |
| ADR 015（M2 ⑤ 多宠物切换搁置） | 搁置的是**并发多只**（同时显示多只宠物），与"换一只"是两件事 |

**明确不做**（避免下一轮重新讨论）：
- **同时显示多只宠物** —— 窗口数量、命中判定、托盘图标、状态归属全都要重新定义，收益不明。
- **在线下载宠物包** —— 引入网络入口与信任问题（本工程至今零网络入口，这是"不被误判为流氓软件"风险表的一项）。
