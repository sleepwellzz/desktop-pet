   M3 只需给 `BarCommandId` 加一个成员，窗口层不用改。

   **验收步骤见 §1 的"人工验收怎么做"**；探针与回归结果见 `spikes/m2-control/README.md`。
   **2026-09-17 修订**：悬停唤出删除、状态机缩小、面板显示宠物名 —— 见 ADR 016（§4 与
   `docs/design/m2-control-bar.md` §14 都被它取代）。
5. ⏸ **切换宠物（多宠物）—— 已搁置（ADR 015，2026-09-17 用户拍板）**：原计划扫
   `~/.codex/pets/*` → 列包 → 校验 → 热切换整个 pack（窗口尺寸、状态表、sheet、托盘图标
   全量重建）→ 失败回退。**搁置的理由不是代码难，而是手里没有"可切换的素材"，也没有素材
   导入流程与规格标准** —— 造素材、定标准、写切换是互相牵扯的三件事，不该压进同一轮；
   而拿 `demo-pet` 复制成两份冒充"多套素材"是假验证（只能证明没崩，证明不了换一套真实
   创作出来的包还能跑）。**重启条件**（满足任一条再评估）：① 手里出现第二套真实宠物包；
   ② 明确要做"素材导入 + 规格校验"这条产品线、同意先做前置的规格与示例包；③ 出现"因为
   不能换宠物而卡住别的功能"的具体场景。**下个会话不要再提议它，也不要重新论证它。**
