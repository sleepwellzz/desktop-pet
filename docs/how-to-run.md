# 怎么跑起来、怎么操作

> 2026-09-18 从 `PLAN.md` §1「运行与构建」 整段迁出（内容未改，只搬位置）。
> 给人和给 agent 看的操作手册：启动、构建、喂状态、托盘/右键、气泡、控制条、行为层、快捷键。

---

**运行与构建**：

## 两种启动方式（2026-09-18 新增）

| 脚本 | 控制台窗口 | 适合 |
|---|---|---|
| `启动桌宠.bat` | **有**（关掉它宠物就退出） | 开发 / 排查：需要实时看日志 |
| `启动桌宠-后台.bat` | **无** | **日常使用**：宠物驻留托盘，关掉所有窗口它还在 |

**为什么原来那个必须挂窗口**：它走 `npm start` → `node.exe`，而 node 是 **console 子系统**
⇒ 必然带一个控制台；关掉窗口，作为子进程的宠物跟着退出。
**实测（2026-09-18）**：`electron.exe` 本身是 **GUI 子系统** —— 不隐藏窗口直接启动，
`conhost.exe` 数量 14 → 14 **纹丝不动**。所以后台脚本直接 `start electron.exe .` 即可，
不需要 PowerShell 隐藏，也不依赖执行策略。

**后台模式下日志去哪**：`%USERPROFILE%\.desktop-pet\pet.log`（每次启动**截断**，只留本次运行；
真正的事件流水在 `events.jsonl`，只增不删）。渲染层的 `console` 也会转发进去。

**怎么退出**：托盘图标**右键** → 「退出」（左键单击是收起 / 放出宠物）。

**开机自启**：菜单里的「开机自启」写的是 `electron.exe <应用目录>`，同样是 GUI 子系统，
**开机不会弹控制台窗口**（打包那轮要复核注册表值名与托盘图标，见挂起 #13）。

- 给不熟悉命令行的操作者：双击工程根目录 `启动桌宠.bat`（自动构建并启动）。
  那个窗口**不要关** —— 它既是桌宠本体，也是日志窗口（状态推送与渲染层日志都打在这里）。
- 命令行：`npm run build && npm start`。
- **这个环境的 Bash shim 没有 npm**，用 `node tools/npm-run.mjs build`（或 `typecheck` / `start`）代替。
- 批处理必须保持纯 ASCII（`cmd` 按 GBK 读 `.bat`），且必须 `call npm.cmd`。
- **喂状态给宠物**（没有真实 agent 时，也是人工验收的入口）：
  - 图形方式：双击工程根目录 `喂状态.bat`。它是**循环菜单**：按数字喂一次 → 退回菜单 → 继续按，
    按 Q 才退出（不要反复重开窗口）。1 running / 2 ready / 3 blocked / 4 needs-input /
    5 running 再喂一次 / 6 idle / 7 clear default / **8 第二会话 b=running / 9 清掉会话 b** / L 看文件。
  - **怎么看 `+N` 角标**：角标统计的是"主状态之外的其它活动会话"，所以**一个会话永远得不出 +1**。
    按 `4`（default 需要输入，进入粘滞）再按 `8`（第二会话 b 在运行）→ 气泡右侧出现 `+1`；
    按 `9` 角标消失。2026-09-16 用户踩过这个坑：开两个终端分别按 1 和 4 是**没用的** ——
    两个终端写的都是同一个会话 `default`，角标自然恒为 0。
  - 命令方式：`node tools/pet-hook.mjs <状态> [--session=<id>] [--title="…"]`。
  - 状态文件默认在 `C:\Users\<用户名>\.desktop-pet\status.json`（hook 不需要知道工程路径）。
- **托盘与右键菜单**：托盘图标左键单击 = 收起/放出宠物；完整菜单（托盘右键 / 面板里的「⋯」）
  当前是：状态行、隐藏宠物 / 显示宠物、控制条、宠物大小（0.5–1.5）、重置大小、
  清空状态会话、开机自启、退出。**宠物上右键不是这份菜单** —— 它唤出控制条（ADR 016）。
  缩放偏好存 `~/.desktop-pet/prefs.json`（不写进工程的 sidecar，避免版本库 churn）。
  （菜单文字与这一行以 `src/host/pet-menu.ts` 为准。）
- **气泡**：状态文案 + 多会话 `+N` 角标，画在宠物上方（独立透明层，不可点）。
  `needs-input` 常驻，`ready`/`blocked`/`running` 分别显示 6/4/2 秒后自动收起；时长在
  `desktop-pet.json` 的 `bubble` 段。
- **控制条**（M2 ④ 新增，本项目第一个可聚焦窗口）：**唤出方式只有两条，全是显式动作** ——
  **右键宠物**（`toggle`）、托盘菜单「控制条」；**一律抢焦点**，关闭：Esc / × /
  再唤出一次 / 点到别处（失焦 200ms）/ 宠物被隐藏。
  （原第三条「全局快捷键 `Win+Alt+P`」已于 2026-09-21 **整块删除**，ADR 032；
  隐藏宠物后唯一的快捷入口是**托盘左键单击**。）
  **没有悬停唤出**（2026-09-17 用户拍板删除，ADR 016）：桌宠常驻角落、光标是顺便掠过的，
  自动弹出必然变成"我没叫它它自己冒出来"；且左键单击要播动作，"停在宠物身上"不该带第二个含义。
  贴在宠物**下方** 8 DIP，宠物贴屏幕底边时自动翻到上方。面板**四段**结构：状态摘要 + 多会话明细
  （可点「确认」解除粘滞）+ **手动把玩动作排** + 底部动作排（隐藏宠物 / **宠物名** / ⋯ 弹同一份原生菜单）。
  参数在 `desktop-pet.json` 的 `controlBar` 段。
  **不出现于任务栏与 Alt+Tab**（显式设了 `WS_EX_TOOLWINDOW`，见 ADR 014 负面结论 2）。
  **它是框架性功能**（用户定位）：结构 + 白名单命令通道已冻结，以后加功能只加按钮/命令。
  —— 动作排就是这条定位第一次兑现（ADR 038）。
- **手动把玩（控制条上的动作排，2026-09-22，ADR 038）**：9 个动作按钮 = 图集的 9 行姿态，
  **与 agent 现在是什么状态无关**，点一下宠物就演一次。点同一个按钮第二下 = 停止。
  **面板长什么样见 `docs/panel-actions-shelf.png`。**
  - **手动触发不产生气泡**（走动画覆盖通道，不经过仲裁器）——"手动 = 陪它玩，agent = 有事告诉你"。
  - 循环动作（待机 / 趴下 / 等一等 / 过生日 / 炒菜…）演 **6 秒**后自动回到 agent 状态；
    一次性动作（拜一拜 / 跳一下）按自身片长播完即回。
  - **左右走是真的走**（窗口位移 180–300px，速度与自主漫游同一套换算，所以不滑步）；
    贴着屏幕边缘走不动时降级为原地演一遍。
    **点左右走时面板会先收起来、等它走完再自己回来**（2026-09-22，ADR 039）——
    面板锚在宠物身上，不收起就会被拖着一起飘。其它动作面板不消失。
  - 优先级：**手动把玩 > 自主行为层 > 仲裁器状态**；手动把玩期间 agent 状态变化不打断它
    （时长有界，最多 6 秒）。
  - 名字写在 `desktop-pet.json → actions.list`（`label` 只影响按钮文字，**不动 `pet.json`**）；
    省略 `list` 时回落到"按行号取全部状态"。`--no-behavior` **不影响**手动把玩。
- **托盘悬停提示 = 宠物名 + 状态**（如 `淘淘 · 空闲`），不再是 `desktop-pet`（ADR 040，
  取自 `pet.json` 的 `displayName`）。**宠物窗口的标题仍是 `desktop-pet`** ——
  探针靠它找窗口，别顺手一起改。
- **两处右键分工不同**（2026-09-17 起，ADR 016）：**宠物右键 = 控制条**；
  **托盘右键 = 完整菜单**（面板里的「⋯」也弹这份）。
- **左键单击宠物** = 播一次「拜一下」（第 3 行 `waving`，见 `docs/status-reference.png`）
  兼作对 `needs-input` 的确认（ADR 010）；**不唤出任何面板**。
- **行为层（M3，ADR 018 + ADR 019）**：空闲（主状态 = `idle`）时做**大动作** ——
  沿地平线走两步（第 1、2 行位移姿态，速度 96px/s @默认缩放，按缩放线性换算）、
  偶尔做个小动作（挥手 / 跳跃）、**空闲满 5 分钟趴下打盹**（复用第 5 行趴卧帧，不需要新素材）；
  有任务在跑时只做**小动作** —— 每 60–180 秒走 60–300px，**锚在进入任务状态时的位置附近**
  （目标由锚点算，不由当前位置算，否则会越踱越远；见 ADR 019）。
  拖动中、宠物被隐藏、全屏让位、控制条打开、系统「减少动态效果」下**都不动**；
  实测"抓住它 3 秒它一步都没动"。
  参数在 `desktop-pet.json` 的 `behavior` 段，**`enabled: false` 是一键总开关**
  （`idleRoam` / `busyPace` / `idleMicroActions` 各自还能单独关）。
  **不跨屏**（锁定范围，ADR 019）—— 拖到哪块屏就在哪块屏活动。
  **回归探针要带 `--no-behavior`**（宠物自己走会把位置类断言搅乱）。
- **全局快捷键：已整块删除**（2026-09-21，ADR 032）。原默认值 `Win+Alt+P` = 唤出/收起控制条，
  但用户从未真实按过一次，而它同时是静默失败面（`Win` 在 Electron 里必须写成 `Super`，
  直接注册会返回 true 但永不触发）与"被误判为流氓软件"风险表的一项。
  `desktop-pet.json → interaction.hideShortcut` 保留为 `null` + 注记（**不要抹掉历史**）。
  隐藏宠物后要叫回来：**托盘左键单击**（或托盘右键菜单的「显示/隐藏」）。
- **动作外观查 `docs/status-reference.png`**（`python tools/make-status-reference.py` 生成）：
  业务状态 → 动画状态 → 精灵图行 → 屏幕上实际长什么样。**不要凭状态名猜外观** ——
  这只包的 `running`（运行中）落在第 7 行，而作者在那里画的是**生日姿态**，真正的跑动在第 1、2 行
  （当前无业务状态映射过去）。换宠物包后要重新生成这张图。
