## 一、本轮做完了什么

起因是用户问「这套开发过程需不需要引入 GitHub 上的 AI vibe coding 规范」
并观察到「仓库从外行人的角度看杂乱、缺乏结构感」。

**核实后的判断与用户预期不同**：缺的不是工程约束，而是**让现有判据可信**。
项目已有 46 条 ADR、6 份分主题约束、33 篇 journal、PLAN 路由表 ——
对照 GitHub 典型 vibe coding 规范（规则文件 / 阶段门禁 / TDD / 小 diff 纪律）**全都已有**，
且是被真实事故打出来的。**再叠一层通用规范只会让"文档说的"与"实际跑的"差距更大**
（审计已显示 `Win+Alt+P` 在五份文档里有五种状态）。

所以本轮**没有引入任何外部规范包**，改为修三件具体的事。

### ① 判据可信度（ADR 047）—— 主单测 446 → **452 项**

| 改动 | 文件 | 效果 |
|---|---|---|
| 构建戳 | `tools/stamp-build.mjs`（新） | 构建成功把 `src/` 内容哈希写进 `dist/.build-stamp.json` |
| 接入构建链 | `tools/run-build.cjs`、`package.json` | 两条构建链都写戳；**只有全部编译成功才写** |
| **⓪ 硬失败** | `tools/status-arbiter.test.mjs` | 改完 `src` 不重建 ⇒ **拒绝运行（退出码 2）**，不给假全绿 |
| 探针钩子静态守卫 | `tools/check-probe-hooks.mjs`（新） | **不启动 Electron**，比对探针用到的 `dbg.*` 是否还在 `__petDebug` 桥上 |
| **⓪b 硬失败** | 同上文件 | 钩子被删 ⇒ 探针必然抛 `TypeError` 跑不出证据，现在静态就能发现 |

**为什么用内容哈希而不是 mtime**：mtime 在本项目骗过人一次
（`docs/reviews/2026-09-28-全面代码复核.md` P0-1：那批证据内容是 09-18 的、mtime 是 09-22 的，
"比 src 新"成立而"是这次跑的"不成立），而 `git checkout`、文件复制、`touch` 都会重写 mtime。

**为什么 ⓪/⓪b 硬失败而 ⓪c 不阻断**：见 ② 与 ADR 048。

## 二、必须知道的一件事：我误跑了一次 GUI 探针

**如实记录，不美化。**

我想检查 `spikes/m2-hotkey/run.mjs` 的语法，用的是
`node -e "import('./spikes/m2-hotkey/run.mjs')"`。
但它**不是纯导入** —— 它 spawn 了 `electron.exe`，**探针真的跑起来了**。
而 `docs/reviews/2026-09-28-全面代码复核.md` 明确写着这类操作"需用户确认能否在这台机器上跑"。

已 `taskkill` 清理，无残留进程。副作用：

| 文件 | 变化 |
|---|---|
| `spikes/m2-hotkey/bubble-hotkey.json` | 被覆盖。新内容 `PASS`、日志零 `[uncaught]`、已不含失效的 `hotkey` 段 |
| `bubble-hotkey.log` / `probe-events.jsonl` | 被改写为本次真实运行记录 |

**原内容是 ADR 032 之前的 `FAIL` 残留**（`accelerator: "Control+Alt+P"`、
失败原因"快捷键没有唤出/收起控制条"）⇒ 新内容在信息上**更准确**。
用户已确认：**保留这次结果**。

⚠️ 但它**不是一次经批准的验证**，这一点必须留在记录里。
**教训（已写进 ② 的纪律）**：验证一个驱动脚本能否正确解析，
不能靠 `import` 它 —— `run.mjs` 顶层就有副作用。**用 `node --check`。**

## 五、不要重复踩的坑

- **想验证 `run.mjs` / 任何有顶层副作用的脚本能不能解析，用 `node --check`，不要 `import` 它。**
  本轮就是这么误跑了 Electron 探针。
- **别删 `spikes/` 里的产物**。ADR 008/014/023/035/038/039 直接引用它们。
  先读 ADR 048。
- **别把 `spikes/**/*.json`/`*.out`/`*.log` 加进 `.gitignore`** ——
  那些是决策链的一环。已经 gitignore 的是**整屏截图**（会拍进桌面与账号信息，
  曾误提交并在公开仓库挂了 12 天，commit `8f682f5`）与可重跑的原始时序 payload。
- **`m2-hotkey/probe-key-path.js` 里的 `dbg.hotkey()` 是注释不是调用** ——
  静态守卫匹配前会去注释，不会误报。
- **本轮新增的三个检查里，只有 `⓪` 与 `⓪b` 会让主单测硬失败**；
  `⓪c` 只 warn。看到 warn 堆着不代表测试坏了。
