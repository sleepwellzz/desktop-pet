## 二、本轮（ADR 022）到底做了什么

用户报两件事 + 提一个功能，并要求做工程级审查。三件事都有结论：

### ① 启动耗时 —— 瓶颈不在应用代码

| 阶段 | 耗时 | 占比 |
|---|---|---|
| `启动桌宠.bat` 每次无条件全量构建 | **29,941 ms** | **93%** |
| `npm start` 的 npm 引导 | 1,232 ms | 4% |
| Electron → 窗口可见 | 871 ms | 3% |
| **合计** | **≈ 32 s** | 100% |

`boot()` 内部只花 **322 ms**（283ms app ready → 605ms boot 返回）。
有效构建其实只有 ≈5.3s ⇒ **29.9 秒里约 24.6 秒是 npm 自身的加载开销**。

新增 `--trace-boot` 接缝与 `spikes/m3-startup/` 两个计时器。**优化方案写了但没实施 —— 等用户拍板。**

### ② `ready` 消不掉 —— 查出是两个独立成因

症状在屏幕上完全一样（"状态挂着消不掉"），但两个成因层次不同，**只修一个不够**：

- **渲染层**：`renderer/control-bar.ts` 的 `needsAck` 旧版只认 `needs-input`，
  而内核 `ack()` 的 `want()` 早就同时覆盖 `ready` ⇒ **`ready` 在面板上连按钮都没有、行也不可点**。
- **内核**：双通道交替（hook 报 `running` / 文件源每 15–60 秒重报 `needs-input`）
  **反复清用户的确认位**。这是"点了十几秒它又举手"的真正机制。
  生产证据在 `~/.desktop-pet/events.jsonl`：357 条绝大多数是同一会话的 `needs-input`、`origin: "file"`。

修法：新增 `reAskMinIntervalMs`（默认 60s，可配）把确认锚定在**求助的实例**上。
复刻探针 **revivals 3 → 0**。

### ③ 控制条「已确认」按钮

`ack-all` 命令，走 `arbiter.ack()` 不带参 —— 与"单击宠物"**同一条路径**，不引入新机制。

### ④ 工程级审查

`docs/reviews/2026-09-18-工程级审查.md`，五维度 + 四级分级。
**无 Critical、无安全漏洞，7.5/10。** 三条 Major、四条 Minor、五条 Nit。

## 三、挂起问题清单（13 项）

### 🔴 需要用户拍板才能动（不要擅自推进）

**1. 启动优化**（🟠 Major）— `启动桌宠.bat` 每次全量构建，占启动 93%
- 方案三步：① 构建改按需（比对 mtime 与 `dist/.build-stamp`）② 去掉 npm 引导（直接调 `node_modules\.bin\electron.cmd`）
  ③ 开头打一行 `echo 正在启动…` 消除"双击后毫无反应"的错觉。
- **预期 32s → 2s 以内。**
- **为什么卡住**：无条件构建换来的是"改完代码双击即生效"。改成按需就变成"需先构建" ——
  **这是取舍不是改进，要用户自己决定。** 已明确告知。

**2. `ready` 落点口径**（ADR 021 遗留）
- 用户早前拍板写的是"`ready` 落到第 7 行生日（当等你验收）"，但第 7 行已是 `running` 的落点，真改过去**两者撞行**，
  与同轮的"确保 running 和 ready 不一样"矛盾。实施取"保持第 8 行 `review` + 叠加 60 秒出口"。
- 用户若坚持第 7 行，改 `desktop-pet.json` 的 `statusMap.ready.then` **一行**即可。

**3. 双通道机制级互斥**（🟠 Major）
- 当前 ADR 020 的"一个 agent 只由一条通道负责"**只有文档约束，代码里没有任何检查**。
- 本轮的迟滞窗口是**症状级**修补：把误报从"随时"压到"60 秒一次"，但双通道本身仍并存。
  **上游重报节奏一变（例如改成 90 秒），误报就以 90 秒周期回来。**
- 三步收口方案：① 文件源按 `origin` 逐出已由 hook 负责的会话；② `ingest()` 检测同会话 10 秒内两个 `origin` 时告警；
  ③ 补双通道探针。**②不需要出设计，可以直接做。**

## 四、之后那么做：硬规则（踩过坑换来的）

开工前必读 `AGENTS.md`。这里只列**最容易踩、且症状安静**的几条：

1. **`hide()` → `show()` 之后，宠物窗口只能走 `resumePet()`**（show + reload 渲染层）。
   任何地方单独写 `win.show()` 都会留下"看着正常但点不动"的窗口。
   **注意适用范围**：该现象只影响鼠标按钮事件、不影响键盘；气泡层与控制条都不需要 reload。
2. **命中判定不能靠系统** —— 生效命中区域 = 整个窗口矩形，与像素 alpha 无关。
   渲染层按当前帧 alpha 判定；**别用 `setIgnoreMouseEvents(..., {forward:true})`**（转发实测不生效）。
3. **状态层的唯一真值是主进程的 `StatusArbiter`**，下游（托盘/气泡/控制条）一律现读，不许各算一份。
4. **改了确认/消解语义必跑** `node spikes/m3-ready-ack/probe-ack-revival.mjs`（13/13）。
   特别要看情形 2b「迟滞窗口**之外**仍应重新举手」—— 那是防误杀的反向用例。
5. **内核 `ack()` 的 `want()` 与渲染层 `needsAck` 必须保持一致** —— 本轮就是只改了一处而失配。
6. **探针的两次输入之间必须显式推进时钟 / 改变前置状态**，否则量到的是别的机制。
   本项目已栽两次（本轮情形 2b 与 M2 ④ 第一版），属**同一类判据不纯**。
7. **改 renderer/preload 只跑 `tsc` 不够** —— preload 是 esbuild 打包的。
   而且 `dist/` 里有诱饵文件（见挂起问题 #7）。
8. **跑既有位置类回归探针要带 `--no-behavior`** —— 宠物会自己走。
   （行为层自己的探针 `spikes/m3-behavior/run.mjs` **不能带**。）
9. **平台行为一律探针实测，不要推断** —— 本项目已**五次**被推翻。
10. **收工四件事**：更新 `PLAN.md` §3/§9 → 新增 ADR → 追加 `journal/` → `git commit`。

## 五、环境事实（换个会话会重新踩的坑）

- **Bash shim 缺 `head`/`tail`/`dirname`/`cat`/`ls`**，且 `rm/cat/grep` 会被 shim 拦截报错。
  用专用工具（Read/Write/Edit/Glob/Grep），跑脚本用绝对路径 node：
  `"C:/Users/<用户名>/.workbuddy/binaries/node/versions/22.22.2-3/node.exe"`。
- **Bash 环境没有 npm**：构建用 `node tools/npm-run.mjs build`（或 `node tools/run-build.cjs`）。
- **PowerShell 工具不回传 stdout**：要结果就写进文件再 Read。
- **本工程路径含空格**：解析 `import.meta.url` 必须用 `fileURLToPath`，字符串替换会留下 `%20`。
- **EBADENGINE / ESM**：`.mjs` 里没有 `require`，要 `import { spawn } from 'node:child_process'`。
- **`.bat` 必须纯 ASCII**（cmd 按 GBK 读），且必须 `call npm.cmd`。
- **`dist/` 与产物 JSON 已 gitignore**，别担心误提交。
