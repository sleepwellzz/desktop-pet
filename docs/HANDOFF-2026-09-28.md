## 3. README 介绍页重做了什么

**诊断出的问题**（不是"感觉乱"，是逐条查的）：

1. **没有下载入口** —— GitHub 无 Release（`No releases published`）、`dist-win/` 被 gitignore。
   陌生人看完不知道能不能用、怎么用。**这是最实际的死路。**
2. **没有主视觉** —— 首图放的是控制条面板（高级功能）；全仓**没有一张"宠物在桌面上"的图**。
3. 前 5 行三段散文，没有一句话能让人 5 秒抓到"这是什么、怎么装"。
4. 无徽章（license / 版本 / 平台 / 仅 Windows）。
5. 术语噪音 —— `WS_EX_NOACTIVATE`、逐像素 alpha 命中判定、`HKCU\...\Run` 对访客是纯噪音却占首屏。
6. **测试项数写 413，实际 446**（已实跑）。
7. 访客与贡献者混在一页 —— "文档密度比一般项目高"对访客是负担，对贡献者才是卖点。
8. 视觉全裸，无分层无导航。

**改法**：六层结构，开发者区折叠下沉，首图用三张**真实运行截图**横向排布
（宠物 / 气泡 / 控制条），并新增"它不做什么"边界段。

**两处诚实性修正**：

- Node 版本原写 `22+`，但仓库无 `engines` 字段、无任何文档记录过最低版本 ——
  按本项目「平台行为一律实测、不推断」，改为只写实测版本 `22.13.1` 并明说更低版本未验证。
- 分发状态如实写"目前无公开发布包"并给出原因，**不写不存在的下载链接**。

### ④ ⚠️ 用户会直接在 GitHub 网页上改 README（推送被拒时必读）

**2026-09-28 发生过一次**：我 push 时被拒，远端多了一个 `5393537 Update README.md`

**正确处理**：`git pull --rebase origin main`，**不要** force push、**不要** reset 掉远端提交。

**教训**：推送被拒时**先跑 `git log main..origin/main` 看对方改了什么**再决定怎么合。
