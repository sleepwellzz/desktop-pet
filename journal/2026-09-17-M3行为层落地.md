# 2026-09-17 · M3 第一块：行为层（自主漫游 / 微动作 / 打盹）+ 两个小改动

本轮三件事：① `pet.json` 的 displayName 改为「淘淘」；② 待机动画放慢到 0.8 倍（8 → 6.4 fps）；
③ **M3 第一块：行为层落地**（这是本轮的主体）。

## 一、两个小改动（用户要求）

- `pet.json`：`displayName: "淘淘 New"` → **`"淘淘"`**。面板、托盘提示、日志都跟着变
  （控制条探针断言"面板显示的名字 == pet.json 的 displayName"，所以判据不需要改）。
- `desktop-pet.json → states.idle.fps`：**8 → 6.4**（0.8 倍，每帧 156.25ms），并加了 `note` 说明来由。
  只动这一行：其余状态（跑动/挥手/跳跃/受阻/等待/运行/审阅）的帧率与全部锚点都没碰。
  `pack.ts` 的校验只要求 `fps > 0`，小数没问题（播放器算的是 `1000/fps`）。
  **注意**：AGENTS.md 那条"帧率与锚点由脚本自动生成，不要手写"里的 fps 不在任何 tools 脚本的产物里
  （`anchor-report.*` 里没有 fps），所以改这里是安全的；这条纪律的本意是别手写**锚点**。

## 二、行为层（ADR 018 / `docs/design/m3-behavior.md`）

**做了什么**：宠物从"站在角落里循环待机"变成"没人用它时像个活物"。

- **自主漫游**：每 25–90 秒沿**地平线**走 80–320px（速度 96px/s @默认缩放，按缩放线性换算）；
  目标点夹进工作区，贴边就换方向；
- **微动作**：每 40–150 秒挑一个候选（挥手 / 跳跃）播一次；
- **打盹**：空闲满 5 分钟落 `failed`（复用趴卧帧），**单击或拖动即醒**并重新计时；
- **四条抑制**：拖动中 / 宠物被隐藏 / 全屏让位 / 控制条打开 → 一步都不动；
  系统「减少动态效果」下不漫游不做微动作（打盹这种静态姿态仍然允许）。

**分层**（沿用既有架构）：规则 = 纯函数 `kernel/behavior.ts`（时钟与随机数可注入）｜
接线 = `main/index.ts`（33ms tick：攒输入 → 调 tick → 落命令）｜渲染层 = 哑渲染层
（新通道 `CH.behavior` 接动画覆盖；覆盖期间**不把播放器收敛回主状态**，否则每帧被拉回去走不动）。

**新增的三个契约**：`CH.behavior`（主进程→渲染层，动画覆盖，**三态**：缺省不变 / `null` 交回 /
对象按它演）、`CH.dragState`（渲染层→主进程，拖动的**显式边沿**）、`ready({reducedMotion})`
（系统「减少动态效果」只有渲染层读得到）。另给 `overlay` 加了 `moveTo()`（绝对定位，
避免"每步增量四舍五入"把 96px/s 走成 90px/s）。

## 三、判据

**离线（`tools/status-arbiter.test.mjs` ⑭ 段，22 项；总数 138 → 191）**：
启动不立刻乱跑 / 到点才走且朝向与方向一致 / 速度按缩放归一化（0.7→≈96px、1.4→≈192px）/
目标夹进工作区 / 贴边换方向 / 抑制期间一步不动且保留目标 / running 期间不动且交回动画 /
打盹与醒来 / **漫游不重置打盹计时** / 微动作只在候选里挑且播完交回 / 减少动态效果下不动但打盹照常 /
交回是边沿不重发 / 总开关。

**真实窗口（新增 `spikes/m3-behavior/run.mjs`，7 条全过）**：真的在走（38 次位移）/
只沿地平线走（出现过的 y 只有一个值）/ 不越界（0 次采样）/ **位移行号与方向一致（右 3、左 5、不一致 0）** /
抓住 3 秒一步不动且松手恢复 / 控制条开着不动 / running 期间不动 / 打盹画到第 5 行且单击能醒。

**回归（全绿）**：单测 **191**、命中图**误吃 0**、全屏两轮 OK、托盘 PASS、控制条两探针 PASS、
状态端到端 PASS、气泡与快捷键 PASS、陈旧会话哨兵 22/22。

## 四、四条只有实测才发现的教训

1. **打盹计时若被漫游重置，"每 25–90 秒走一次"会让它永远睡不着**（屏幕上只表现为"它就是不打盹"，
   没有任何报错）。只在"状态离开 idle"与"用户碰它"时重置 —— 单测钉住"走完这一程就打盹"。
2. **自主行走会让既有的位置类断言集体变脆**：探针都是"读一次窗口位置、再按它算点击坐标"，
   中间宠物走掉了就点空。给主进程加了 `--no-behavior` 接缝（与 `--no-status-source` 同一套路），
   **7 个既有探针全部带上它**；行为层自己的探针当然不带。
3. **`CH.behavior` 的命令必须是三态**。第一版是两态（对象 / `null`），"没有新指令"与"撤销覆盖"
   在调用方看来一样 —— 只能每 tick 都发一次 `null`，等于把渲染层按住（走路会被每秒压回去 30 次）。
4. **注入点击不能打窗口中心**：趴卧姿态的精灵贴在图集底部 ⇒ 窗口中心是透明的 ⇒ 那时窗口整窗穿透，
   按下根本到不了渲染层。探针改成先用 `dbg.petInteractive()` **扫出一个真的落在精灵上的点**。
   第一版就是因此报了两条假失败（"拖动没生效""单击没唤醒"），真因与它们无关。

另有一条"名字与单位不一致"的负债：`roamEveryMs` 第一版里装的是**秒**、用时才 `× 1000`，
单测按名字写 100 毫秒却变成 100 秒。已把 parse 时就换成毫秒。

## 五、没做的事（留给下一轮，需要用户拍板）

- **行为层的"忙碌动作"**（兑现早先那条"运行中看起来像在忙"）：它与"只在 idle 时活动"直接冲突，
  动手前必须先回答**任务进行中宠物能不能离开原位**（原地踱步 vs 允许走开）。这是产品决定，
  不该由实现顺手拍 —— 已写进 ADR 018 负面结论与 PLAN §4 第 7 条。
- **跨屏漫游**：先把"穿越过程中窗口矩形"与"多屏工作区并集"定义清楚再说；本轮范围写在
  sidecar 的 `edgePolicyScope`。
