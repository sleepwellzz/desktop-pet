# 2026-09-29 · 换宠物成为正式目标 + 构建链的三处静默失真

## 这一轮的起点

用户提了两件事：

1. 「从你的角度来看，我们接下来还需要做什么？我现在有大把的时间/令牌可以挥霍。
   我想把这个工程或仓库变得非常完备且具有可塑性。」
2. 「如何确保以后更换宠物时过程非常流畅？我需要一个能够更换宠物的接口或指引，
   不仅可以在软件里切换到其他宠物，还需要制定其他宠物的制作要求。」

我问他优先做哪些，他选了：**先做完备（收口 12 条 P0）** + **换宠物三件（判据 → 规范 → 托盘图标）**。

## 先说一件必须先说的事：换宠物被关闭过两次

- **ADR 015**（M2 ⑤）：多宠物切换，**搁置**
- **ADR 046**：「不打算做成可换宠物的平台」

⇒ 我不能直接动手做，否则仓库里会同时存在"不做"和"要做"两套说法，
新 agent 无从判断（这正是 `AGENTS.md` 说"已决策的事看 INDEX，不要再讨论"要防的情况）。
**走新 ADR 取代**，并把 ADR 046 的前后半句拆开处理：前半句（对外定位）保留，后半句推翻。

**改判的理由写进了 ADR 049**：ADR 046 回答的是"对外定位是什么"，
而用户现在问的是"这个工程将来能不能长出我没想到的东西"。
**可塑性服务的是维护者，不是访客** —— 换不了宠物的工程，
每一处实现都只能是"这只宠物专用"，美术规格与锚点一锁死就长不出新东西。

我原以为"可换宠物"是件大工程。查完代码发现**已经有一大半**：

## ADR 049：判据优先于界面

新增 `tools/check-pet-swap.mjs`。它的定位不是"把 `loadPack` 的校验再抄一遍"
（那是 ADR 044 §2 明令禁止的：**判据不该被它测以外的东西判红**），
而是堵 `loadPack` **只 warn 就放过**的四个洞：

| 洞 | 后果 |
|---|---|
| `pack.ts:87` 对"behavior-map 有、runtime 没有"的状态只 `warnings.push` 后 `continue` | **宠物静默少一个动作** |
| 只强制要求 `idle`，而 5 个业务状态 + 9 个面板动作靠 `statusMap`/`actions` 指过去 | 该状态永不出现、面板少按钮，**无报错** |
| `statusMap` 指向不存在的动画 | agent 进入该状态时无动作可演 |
| 锚点不自洽 | 脚会离地 |

**判据体检工程根自己**，理由是"自己过不了的判据没资格要求别人过"。
三个案例都做了非真空验证（少配状态 / 锚点不自洽 / statusMap 悬空，均精确捕获）。

还写了 `docs/pet-pack-guide.md`：把散在 `pet-spec.html`、`codex-pet-pack` 技能、
ADR 002/013/021 里的规格合成**可执行的操作路径**。
刻意不重复 `pet-spec.html`——那份是"为什么"的权威，这份是"怎么做"。

## ADR 050：构建链的三处静默失真

做完换宠物后转去收口 12 条 P0。盘了一下，**5 条已经在早前解决**（P0-7/9/10/11/12），
剩下里最值得做的是这四条**同一种病**：*构建链会产出"看起来成功"的东西，而它其实是坏的。*

### P0-2：`build` 完全不跑 preload 类型检查

preload 是渲染层与主进程**唯一**的那道门。通道名拼错 ⇒ 构建期无任何提示，
照样产出"成功"的 dist 并打进发行包，只在用户点开控制条时表现为"按钮没反应"。
而 `tsconfig.json` 的注释里**自己写着**"类型检查没有因此丢掉"——它与实际行为矛盾。

### P0-3：tsc 把 renderer 编成 CommonJS 覆盖 esbuild 的 IIFE

这条是我**实测复现**的，不是照抄报告。写 `watch` 时跑出
`Object.defineProperty(exports, "__esModule", …)` ——浏览器里 `require`/`exports` 未定义
⇒ **宠物窗口白屏**。正式 build 一直是靠"tsc 先跑、esbuild 后跑"的**顺序侥幸掩盖**。

修法与 ADR 023 对 preload 的处理**完全同构**：从 `exclude` 掉 + 单独的 `tsconfig.renderer.json`
承担类型检查。**`exclude` 写目录而不是逐个文件** ——
将来新增一个 renderer 源文件时**没人会记得**去改 exclude。

### P0-4：打包不校验 dist 新鲜度

原先只判 `dist/main/index.js` **存在**，不看它新不新。
后果具体到可复现：改完 `src` 直接打包，产出"**1.0.2 版装着 1.0.1 代码**"的包 ——
而它在属性页 / zip 名 / 日志横幅 / 托盘菜单**四处全都自洽地显示 1.0.2，没有一处会露馅**。

修法直接复用两天前做好的构建戳（ADR 047）：比 **`src/` 内容哈希**。
**不比较 mtime** —— 那个方法在本项目已经骗过人一次。

### P0-8：验收文档硬写版本号

`acceptance.md` 里四处写 `1.0.0` 而实际是 `1.0.1` ⇒ 照单验收**必然判红**。
而这是**判据本身过期**，不是产品坏了 —— 更坏的可能是有 agent 为了"让判据变绿"去改代码。

改成 `<版本号>` 并指向唯一真源，**同时加断言**扫 `acceptance.md` 的版本串与 `package.json` 比对。
**只改数字的话，下次跳号还会漂。**

## 判据（本轮实跑）

- 主单测 **452 → 457 项全过**。
- `run-build.cjs` 第一步即 preload 类型检查；注入 `const __bad: number = "x"`
  ⇒ `[FAIL] tsc (preload typecheck)` + `BUILD FAILED`，退出码 1。

- 打包非真空：改 `src` 不 rebuild ⇒ `dist/ 与 src/ 不同步，拒绝打包`，退出码 1。
- 验收版本断言非真空：改成 `9.9.9` ⇒ 精确报出。
- `check-pet-swap` 三案例均精确捕获。

## 一次验证失误（如实记录）

验证 `watch` 时，我先往 `preload.ts` 追了一行**注释**，然后检查产物里有没有它 ——
结论是"没生效"。但**结论是错的**：esbuild 会**剥离注释**，用注释验证必然看不到。
换成真实代码改动（一个字符串常量）后立刻验证成功。

**顺带暴露一个操作习惯问题**：那次命令用了 `grep -c ... && cp 还原`，
而 `grep -c` 无匹配时返回 0 ⇒ **`&&` 链中断，源文件没有被还原**。
我第二次检查时才发现文件还是脏的。

⇒ 两条要记住的：**验证要用会出现在产物里的东西**；
**"检查 + 还原"不能串在 `&&` 链里**（检查失败时还原不会执行）。
