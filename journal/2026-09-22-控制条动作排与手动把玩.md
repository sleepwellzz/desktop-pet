## 用户要什么（原话要点）

1. 「我需要在悬浮条中添加相应的动作按钮……这个宠物有很多动作吧？我不管现在的 agent 状态是什么，
   我可以像逗宠物一样，**把玩它的所有状态**。」
2. 「当我右键这个悬浮条时，里面应该有一些小 UI 按钮供我选择并触发它的某些动作。」
   （举例：往左走、往右走、过生日、厨师炒菜……）
3. 「既能由 agent 自动触发，也能在闲时手动把玩它。」
4. 「**手动触发时，它上面不会显示文字气泡；只有 agent 触发时，才会显示文字气泡。**」

术语确认：用户说的"悬浮条" = 本项目的**控制条**（右键宠物唤出的那个面板）。

## 四个产品决策（我出选项 + 推荐，用户全选推荐）

| 问题 | 用户拍板 |
|---|---|
| 动作按钮的形态 | **文字按钮，2 行 × 5 列**（待机/左走/右走/拜一拜/跳一下/趴下/等一等/过生日/炒菜） |
| 点「往左走/往右走」时 | **真的走过去**（不原地播腿 —— 那样会滑步） |
| 循环动作演多久 | **约 6 秒后自动回到 agent 状态** |
| 动作排是否常驻 | **常驻一行**（右键唤出即可直接点） |

## 做了什么

### 关键设计：手动把玩走**动画覆盖通道**，不经过仲裁器

这一条决定了"手动不出气泡"是**通道划分天然成立**的，不是靠 if 判断：

| | 手动把玩 | agent 状态 |
|---|---|---|
| 通道 | `CH.behavior` 覆盖 | `CH.status` → 仲裁器 |
| 气泡 | **永远没有** | 有（`statusMap[].bubble`） |
| 面板会话行 / 托盘状态行 | 不动 | 动 |

若把手动动作塞进 `CH.status`，托盘、气泡、面板会开始显示一些**并不存在的 agent 状态** ——
仲裁器是"全应用唯一真值"，不能被这种语义污染。

### 三级优先级：手动 > 自主行为层 > 仲裁器

两者对"面板开着"的要求正好相反（行为层必须静止，手动把玩必须生效），所以没有塞进同一个状态机，
而是独立成 `kernel/manual-play.ts`。主进程里两条守卫 + 一条**反直觉的"不许省"**：

1. `behaviorSuppressed()` 含 `manualPlay !== null`；
2. `applyBehaviorCommand()` 顶部 `if (manualPlay) return;` —— 行为层命令一律丢弃
   （面板打开时它本就在抑制态、每 tick 都下发"交回仲裁器"，不挡的话手动动作被每秒冲掉 30 次）；
3. **但行为层仍要每 tick 推进**，且**必须先推它、再落手动命令** ——
   抑制态会让它清掉自己的 `sentPlay`；省掉这一步，把玩结束后它仍记着"我在走"
   ⇒ 窗口移动而腿停在待机姿态（**滑着走**），屏幕上只表现为"它怎么飘着"。

### 其余落地

- `desktop-pet.json` 新增 `actions` 段（9 个动作的中文名 + `dwellMs: 6000` + `walkDistancePx: [180,300]`）
  与 `controlBar.actionRowHeight / actionColumns`。**`pet.json` 一个字段没动**
  （"过生日 / 炒菜"是画面语义，写进 sidecar 的 label 即可；原生语义仍是 working / review）。
- 面板高度算式 **三段 → 四段**（空闲 72 → 132 DIP）。两个新参数**随 `BarView` 下发**，
  渲染层不写死 —— 顺手消掉了会话行当年那个"CSS 里写 28px + sidecar 里写 rowHeight"的双份隐患。
- 时长：循环动作 `dwellMs`；**一次性动作按自身片长 + 250ms**（用 `dwellMs` 会**冻在末帧**摆 6 秒）；
  位移类走到位即止，另有 `min(12s, 路程×2+1.5s)` 兜底。
- 位移类**真的走**（180–300px，夹进工作区，速度用**与自主漫游同一个函数** ⇒ 不滑步）；
  贴着屏幕边缘走不动时降级为原地演，**不假装走了**。
- 再点同一个按钮 = 停止；高亮当前动作。
- 挂在既有 33ms tick 上 ⇒ **不新增定时器**（继承"宠物隐藏时一起停"），`--no-behavior` 不影响手动把玩。

## 本轮抓到并修掉一个真缺陷 —— 而它差点溜过去

**症状**：动作演完了，面板上那个按钮**一直亮着**（要到下一次状态推送才被清掉）。

**根因**：`tickBehaviorLayer` 里先写 `manualPlay = mp.play`（结束那一 tick 它已经是 `null`），
再调收尾函数 `endManualPlay`，而它开头是 `if (!manualPlay) return;` ⇒ **收尾直接返回**，
`refreshBar()` 从未执行。

**怎么发现的 —— 这一条最值得记**：核对探针报告时看到 `releasedToArbiter: true` 但 `endLogged: false`
（两条本该同生同灭的日志只来了一条），而探针的 `verdict` 当时是 **PASS**。
因为我的断言只查了"点下去有没有开始演"，**没查"演完了面板还说不说它在演"**。

**处置**：
1. 顺序改成"先落地这一 tick 的命令 → 再交给收尾函数去清状态"；
2. 补三条断言（`endLogged` / `highlightCleared` / `已停止`）；
3. **把缺陷临时打回 `dist` 再跑一次探针，确认断言会红**，证明它们不是真空的
   （红在恰好那两条：`结束日志=false`、`面板高亮已清=false`）。

⇒ 升级为 `AGENTS.md` 的**第三条通用纪律**：**"发生了"不等于"表现对了"**。
与 ADR 035 的"**进程消失 ≠ 退出干净**"是同一个形状 —— 拿代替指标顶替了用户真正看到的那个量。
自检句：**"我要断言的这个量，用户真的会看到它吗？"**

## 踩到的坑（都有记录，还是踩了）

- **带反引号的字符串不能用 `node -e` 拼** —— 被 bash 吃掉，报 `Unterminated template`。
  记忆里已有这条（"批量替换写一次性 node 脚本"），本次又踩一次。
  正确做法：**先写临时文件，再让 node 读它 append**。
- **探针脚本改名/新增变量要先查重名**：第一版 ⑫b 里声明了 `const tail`，与第 ④ 节重名 ⇒
  整个脚本 `SyntaxError`，electron **秒退且不写日志**，而驱动只看到"报告未生成"。
  教训：**探针脚本先 `node --check`，再看 electron 的 stderr** —— 只看"报告没出来"没法定位。
- **自己写的断言期望值要跟着前置条件走**：第一版拿"2 条会话时的 188"去比"⑫ 已清空会话后的高度"，
  探针报了一条假失败。改成"拿点击前的高度当基准"（要钉的不变量是"高亮不改变布局"，与会话数无关）。
