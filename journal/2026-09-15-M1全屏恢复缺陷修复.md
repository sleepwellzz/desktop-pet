# 2026-09-15 · 全屏让位后"宠物点不动/拖不动"（ADR 009）+ 阶段收尾

## 现象

Justin 复验（M1 命中区域修复之后）：启动一切正常，**只要全屏一次，宠物让位回来后就再也无法拖动**，
多次复现、不复原。命中区域与缩放这两轮的成果他都确认满意（"点击的不可用区域变得很小"）。

## 定位：先造判据，再动手

最小复现只需要 `hide()` + `showInactive()`（不必真全屏）。症状的精确描述是**移动事件能进渲染层、
按钮事件进不去**。据此做了 8 步排查（全部实测）：

1. 坐标映射 → 偏差 0，排除；
2. 页面可见性 → 全程 visible，排除；
3. 窗口几何 → 隐藏前后一致，排除；
4. 应用自己的状态机（`WS_EX_TRANSPARENT` 随光标精确切换）→ 正常，排除；
5. **`SendMessage(WM_LBUTTONDOWN)` 直接发顶层 HWND → 渲染层能收到 pointerdown**
   → 窗口能收事件，坏的是 Windows 对真实输入的路由；
6. 补救动作矩阵（9 个动作：EnableWindow / focus / alwaysOnTop / opacity / blur / invalidate /
   再 hide-show / 再 showInactive / setBounds 原值）→ **全部无效**；
7. 位置或尺寸 nudge → 某些时机有效、换个实验又失败 → **不可靠**；
8. `webContents.reload()` → **稳定有效**。

期间踩了一个自己的坑：探针在应用运行中直接调 `setIgnoreMouseEvents` 会打乱应用记账，
导致 A/B/C/D 一组结论全部失真。重做了一次"全程不碰 setIgnoreMouseEvents"的干净实验才拿到可信数据。

## 改了什么

- `src/host/overlay-window.ts`：新增 `reload()`（重载渲染层）与 `resetToIgnore()`；
  去掉 `setIgnoreMouseEvents` 的 `forward`（实测转发不生效，且会多带 `WS_EX_LAYERED`）；
  创建后与每次显示后都用 `setContentBounds` 归一化（顺带消除了 4 DIP 的 view/窗口错位）。
- `src/main/index.ts`：全屏恢复分支改为 `show()` + `reload()`；`CH.ready` 处理里
  `resetToIgnore()` + `pushPointerHint(true)`（强制渲染层重报命中状态）；自检只跑一次。
- `src/shared/ipc.ts`：`PointerHint.force`。
- `src/renderer/renderer.ts`：`setInteractive/evaluateHit` 支持 force；补 `pointercancel`。

## 验证

`probe-fs-verify.js`（外部进程做全屏应用，走真实让位路径）两轮：
**全屏前后单击与拖动全部 ✅**，无累积劣化；日志可见恢复时渲染层重新取到精灵图。
回归：命中区域 误吃 0 / 漏吃 2 不变；自检截图 216×234、宠物 152×219 物理像素、两帧姿态不同。

## 已知代价

每次全屏恢复重载一次渲染层（约 100~300ms 空白后宠物重现，用户刚从全屏退出，不可感知）。
未查明 Chromium/Windows 内部是哪一层缓存了输入路由——用可靠动作绕过，写在 ADR 009 §6。

## 阶段收尾

本轮把 M1 的两轮缺陷（ADR 007 全屏判据、ADR 008 命中区域与窗口漂移）与这一轮的输入通路缺陷
（ADR 009）全部修完并通过自动化验证。剩下的只有人工确认；M2 可以开工。
