## 状态源的方向性（回答"连哪个 agent"）

工程里其实有**两个方向**，容易混为一谈：

- **入方向（agent → 宠物）**：已实现的唯一通道是**状态文件** `~/.desktop-pet/status.json`
  （`src/source/status-file.ts` 监听目录 + 1000ms 轮询兜底）。任何东西都能往里写：
  真实的 agent hook、脚本、或人。写入入口是 `tools/pet-hook.mjs`
  （`node tools/pet-hook.mjs running --session=<id> --title="..."`），
  它是**同一个状态文件的 CLI 封装**，不绑定任何应用。
- **出方向（宠物 → agent）**：**尚不存在**，属 M3（"宠物发消息 / 开对话"就是这条）。
  本轮控制条不渲染输入框，正是因为这条通道还没定。

所以"连哪个 agent"的答案是：**宠物不连接任何 agent，它只读一个本地状态文件。**
换 agent 不需要改宠物本体，只需要把该 agent 的 hook 点接上 `pet-hook.mjs`（或写一个适配器
把该 agent 的事件翻译成对它的调用）。`StatusSource` 接口（`src/source/types.ts`，
`start`/`stop`/`describe`）就是为将来加 HTTP / stdin 等第二种源留的位置。

**未验证的部分**（PLAN §8 风险表里标着）：这条链路目前只用 CLI 手工验证过，
**还没有在真实 Codex / Claude Code 上配过一遍 hook**。这是"状态源生态"（M3）的活。

## 两条文档漏掉的机制（实现时才暴露）

1. **`BarState.armed`**：设计文档 §4 只写了"pet-hidden 时清空全部计时"，但那实现不了
   "宠物让位回来不自动重现"，也实现不了"快捷键收起不被悬停弹回" —— 这两条发生时
   **光标往往还停在原地**，下一个 tick 的 `hover(true)` 会被当成"刚刚进入"。
   `armed` 置真的唯一时机是 `hover(false)`：光标**真的离开过一次**。
   这是整套规则里唯一无法从"当前光标在哪"推导出来的信息。
2. **到点收起不能顺手撤销 `armed`**：`hideAt` 只由 `hover(false)` / `focus(false)` 设置，
   而 `hover(false)` 只在 over 真正翻转时发出 —— 在 tick 里撤销它，就再也没有事件能解开，
   表现为**悬停唤出永久失效**（且只有读代码能看出来）。单测里有专门的断言。

## 实测结论（推翻了两条推断）

1. **ADR 009 在键盘路径上不复现**（设计文档 §3.3 特意留的两个分支，取"更简单"的那个）。
   `hide()` → `show()` 往返之后，键盘事件照常投递 ⇒ **控制条不需要 reload**。
   ADR 009 那个坑是**鼠标按钮事件**的路由问题，键盘走"焦点 → 消息队列"，另一条路径。
2. **`skipTaskbar: true` 不会给窗口加 `WS_EX_TOOLWINDOW`**（本项目第五例"推断被实测推翻"）。
   探针读回扩展样式 `0x108`，没有 `0x80`；Alt+Tab 仍可能列出来。
   修法：koffi 显式 `SetWindowLongPtrW` + `SetWindowPos(SWP_FRAMECHANGED)`，修后读回 `0x188` ✓。
   这条对工程里所有带 `skipTaskbar: true` 的窗口都成立。
3. **`win.isVisible()` 不能做显示记账**：`show()` 之后同一 tick 内它可能仍返回 `false`，
   而紧跟其后的 `focus` 事件（`show()` 会激活窗口）会让调用方以为"还没显示"而**再 show 一次** ——
   第二次是 `showInactive()`，在抢焦点的路径上正好把刚拿到的焦点又让出去。
   日志证据：一次快捷键唤出打出两条"控制条显示"，第二条写着"不抢焦点"。
   改为由窗口的 `show`/`hide` 事件记账，修后只剩一条。

## 方法论教训

**测"位置类规则"之前必须先摆位。** 第一版 `probe-control.js` 直接量默认位置，报出
"下间距 -228、水平偏差 39"两条假失败 —— 真相是宠物默认就贴工作区右下角（margin 24 DIP），
那里下方只剩 24 DIP、260 宽的面板在右侧还会被夹进工作区，位置算式于是（正确地）翻到上方并夹取。
量到的是**别的规则**的结果。教训与 ADR 013 的"要量渲染结果就量渲染本身"同源：
**判据必须只让被测的那条规则生效。**

另：`PLAN.md` 里那条全屏回归命令此前漏了第二个参数（产出文件名），照抄会白等 5 分钟超时，
本次一并修正。
