## 调研：三个决定性的实测发现

### ① WorkBuddy 自带完整的 Claude 系 hook 引擎（初稿完全没料到）

扫内嵌 agent CLI（`resources/app.asar.unpacked/cli/dist/codebuddy.js`，23MB）发现：
14 个事件的字面量数组（含 `PermissionRequest` / `Notification` / `PostToolUseFailure` / `WorktreeCreate`）、
`hook_event_name`×49、`executeHook`×32、`permissionDecision`×56、`disableAllHooks`；
hook 是**真的 spawn 子进程**。配置位置 = `.codebuddy/settings.json`。

### ② 闸门跑通：桌面确实走内嵌 CLI，工程级配置确实生效（YES）

- **进程树**：`WorkBuddy.exe → daemon-app-server-entry.js --stdio → sidecar-entry.js
  → cli/bin/codebuddy --serve --session-id ab2f75f8-…`。该 session-id 与
  `~/.workbuddy/sessions/203516.json` 的 `sessionId` **完全一致**。
- **设置作用域**：CLI 里 `DEFAULT_SCOPES = [USER, PROJECT, PROJECT_LOCAL]`，
  而跑 agent 的进程**没带** `--setting-sources`（只有一条 prewarm 进程带 `--setting-sources user`）。

### ③ Proma 没有 hook 面，但有很好的被动源

`app.asar` 里 `PreToolUse` / `hook_event_name` / `disableAllHooks` 全 0；
`SessionStart` 那 25 处**逐条看过上下文**，全是编辑器内部变量，不是 agent hook。
**但** `~/.proma/agent-sessions.json` 有 218 条会话（含 `title` 与 `updatedAt`），
`agent-sessions/<uuid>.jsonl` 末尾有 `type:"result"` + `terminal_reason:"completed"`。
顺带实证了用户说的 SDK 迁移：`legacyTranscript.sourceRuntime` = **claude 38 / Pi 180**。

## 架构决策（详见 ADR 020）

- **两条通道**：A 事件驱动 hook（WorkBuddy / 将来的 Claude Code / Codex —— **同一套事件名与契约**，
  所以是"1 份映射 + N 个配置路径"，不是 N 份适配器）；B 被动会话源（Proma）。
- **一个 agent 只由一条通道负责，互斥** —— 这是本轮新增的硬规则。两个**不同** agent 天然不冲突
  （仲裁器本来就是多会话形状）；会打架的是**同一个 agent 被两条通道同时盯**（来回刷且无报错）。
- **`sessionId` 带来源前缀**（`wb:` / `proma:`）+ **标题带来源名**。
  副产品：用户"只想连某一个 agent"变成一次按前缀过滤，不是新机制。

## 施工顺序被实测推翻了一次

初稿把"先做通道 B（读文件）"当作零风险的先赢。**采样探针（151s @1Hz）推翻了这个排序** ——
WorkBuddy 的被动源**只能给"存在性"，给不了"活动性"**：

- `sessions/*.json` 心跳 151 秒里**只刷新 5 次 ⇒ 粒度约 30 秒**，且与"在不在干活"无关；
- `tasks/*/N.json`、`file-history/`、`changes-index/`、`plans/` 窗口内 **0 次变更**；
- `projects/` 4 次、`artifact-index/` 2 次（太少）；
- `logs/` 105 次写入，但内容是 `vendor-extract.log`、`weixinpay/*.xlog` 这类**应用级日志** ⇒ 噪声。

⇒ 通道 A 才是 WorkBuddy 的主路径，B 降为可选。

## 一条自我更正

我先前在设计文档里写"`sessions/<pid>.json` 心跳**秒级新鲜**"，**是错的**。
那是**只看了一次文件的当前年龄**（"它现在很新"），而不是**看它的更新频率**（"它多久更新一次"）。
两者完全不同：前者能推出"刚刚有人写过"，推不出"它一直在写"。已更正回文档。
