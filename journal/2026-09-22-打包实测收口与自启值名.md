# 2026-09-22 · 打包成品用户实测收口（#13 结项 / 拆出 #15）

## 起因

上一轮（ADR 033）产出便携版 `dist-win/desktop-pet/`，#13 只剩最后一步**只能由用户做**的事：
双击实测「无控制台 + 关窗存活」。这两件事是 ADR 028/029 折腾两轮没解决的历史遗留，
理论判断是「打包成 GUI exe 后由 explorer 启动，不存在父控制台」，但一直没有真实运行坐实。

## 用户反馈（原文）

> 已经启动了这个 EXE 文件，但它确实不弹窗口，也没有需要关闭的窗口。而且宠物仍然在系统托盘，
> 我已经勾选了开机自启。

**三件事一次性给全了**：无控制台 ✅、关窗存活 ✅、自启已勾（让值名复核有了真实数据）。

## 实测结论

| 项 | 结果 | 证据 |
|---|---|---|
| 无控制台 | ✅ | 用户实测；机理补刀：`electron.exe` PE 子系统 = 2（GUI） |
| 关窗存活 | ✅ | 用户实测「宠物仍在系统托盘」 |
| 自启命令形态 | ✅ | `isPackaged=true` ⇒ 无参分支，指向便携版 exe，回读 `true` |
| **自启值名** | ❌ | PowerShell 读到 `electron.app.Electron` |

⇒ **#13 结项**；值名拆为 **#15**（🟡 Minor，不紧急）。

## 本轮最有价值的一条：推翻了一条推断

ADR 033 和 `autostart.ts` 的注释都写着「值名里的 Electron 是未打包时的 app 名，
**打包后会变成 productName**」。实测不成立：

- `resources/app/package.json` 里 `name: "desktop-pet"` **存在且正确**；
- 而值名仍是 `electron.app.Electron`。

⇒ **`loginItem()` 的 `{path, args}` 只决定命令，不决定值名。**

这已经是本项目第 N 次「推断被实测推翻」。处置相同：把推翻连同反证写进 ADR，
并且**当场改掉那句会误导下一轮的注释** —— 否则下个会话会顺着它直接跳到
「那就改个 productName 试试」，忽略已有证据。已在 `autostart.ts` 把旧注释换成
「已被实测推翻 + 指向 ADR 034」。

## 顺手查清的（下一轮不用重查）

- 全仓 `src/` **无任何** `getPath`/`userData`/`setName` 调用 —— prefs 手写在
  `~/.desktop-pet/prefs.json` ⇒ 即便采用最激进的 `app.setName()` 方案，
  **也不会把用户偏好甩在旧目录里**。这是意外的好消息，省掉一类担心。
- 对照组泄漏：同一份 Run 键里读到 `electron.app.Obsidian` —— 说明正经打包的 Electron 应用
  值名是跟 productName 走的，而 Obsidian 那条路 = 改 exe 版本资源。⇒ 方案 C 最可能是正解。

## 环境更正

`reg.exe` 被沙箱策略拦截，**不绕过**。但 **PowerShell `Get-ItemProperty` 可用** ——
写法：`Get-ItemProperty -Path "HKCU:\...\Run" | Out-File <文件> -Encoding utf8`，再用 Read 读。
（PowerShell 不回传 stdout，这条早就知道，本轮是第一次用它绕开 `reg.exe`。）
