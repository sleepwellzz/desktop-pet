# 2026-09-22（第二次）· 第三次打包前的两处修复

用户的要求很清楚：**先修两件事（自启 + 退出崩溃），再打包；之后进入新开发阶段，视情况再打。**
另外问了流程问题：新阶段是不是继续在本工作区做（答案是肯定的，见 §5）。

## ① 退出崩溃：`Object has been destroyed`

**最刺眼的事实**：探针早就抓到过它 —— `run-tray.out` 里明明白白一行
`[uncaught] TypeError: Object has been destroyed`，同一份报告最后还写着 `✅ 退出用例通过`。
因为它只核对"进程消失"，而进程崩了也一样会消失。**我们把用户可见的崩溃降级成了"日志噪音"。**

根因是两条**从未登记句柄**的定时器：250ms 仲裁推进（裸`setInterval`）、600ms 全屏监听（`startFullscreenWatch` 返回的 dispose 没人接）。它们横跨了窗口的死亡时点。

修复做了机制层 + 守门层：
- `processTimerDisposers` + `stopProcessTimers()`，`quit()` 与 `will-quit` 都调；
- 全屏回调补 `isDestroyed()` 守卫；
- 新增 `tools/check-timers.mjs`（裸 `setInterval` / `*Watch` 未接返回值即失败），
  挂进单测第 ⑳ 节，以后每次必跑；
- 顺手把渲染层控制条那条 1s 定时器也接住句柄（它不是崩溃源，但会被新规则判出来）。

**这一轮最大的收获其实是一连串失败**：想给它做个"修复前有、修复后没有"的确定性复现，
试了三种都不成 —— 忙等会锁死事件循环、Electron 主进程的 `_getActiveHandles` 不可靠、
拦 `app.quit` 会把进程卡成半死。最后我接受"没能复现"这个事实，并把它写进 ADR，
转而用一条静态规则把这类缺陷永久挡住。

> 一个反复出现的模式：**当发现 bash/bug 抓不稳时，不要靠提高运气，要想"它在代码里是不是一眼可见"。**

## ② 自启值名

三条候选全跑了一遍，只有**改 exe 版本资源 ProductName** 有效。
值得记的是 `app.setName()` 那条：`app.getName()` 确实变成了 desktop-pet，**值名纹丝不动** ——
上一轮我判它无效的理由（"文档说不影响 OS 侧名字"）其实是错的推理，只是结论碰巧对。

目标值名也修正了：是 `electron.app.desktop-pet`（前缀 Electron 固定），不是原先写的 `desktop-pet`。

迁移做了，且实测：旧条目消失、新条目生成、**用户已勾的开状态保留，不用重勾**。

## ③ 本轮踩到的小坑（都会变成下一次的学费）

- rcedit 给的是**原生 exe**，不是 JS 模块；含空格路径不能走 `shell: true`。
- exe 版本资源里的**中文会变乱码**（写 Description 时实测出来一串问号）⇒ 一律 ASCII。
- Electron 必须带着**同级的 `resources/`** 才能启动；单独拷一个 exe 出去会"毫无反应且无报错"。
- `electron <app>` **只吃一个 app 参数**，多给一个脚本就被当普通 argv 忽略。
- PowerShell 的 `Get-ItemProperty` **表格输出会折行**，解析长值会读到残缺内容
  ⇒ 读单个值要用 `(...).'名称'` 直接取属性。这条差点让我误判"注册表没变化"。
- `reg.exe` 会被安全策略拦 ⇒ 应用里的迁移改走 PowerShell（那条 deshalb 是硬约束，不是偏好）。
