## M0 窗口层技术验证（完成）

工程：`spikes/m0-window/`。目标是在写业务代码前证明窗口层三项能力可行，任一失败就得换栈。

### 做了什么

1. 先用 koffi 在纯 Node 里验证 Win32 语义（不引 Electron，避免 ABI 干扰）：
   建分层窗口 + 另一个进程的靶窗口，用 SendInput 点两点，看点击归属。
2. 再验证 Electron 44.4.0 宿主：透明置顶窗口 + 精灵渲染 + HUD，同样跑自动点击测试。
3. 全屏检测单独一个探针：拉起铺满显示器的窗口看判据是否翻转。

### 结果

三项判据全过，Electron 选型保留。详见 `spikes/m0-window/README.md` 与 `docs/decisions/004-*.md`。

### 推翻了一个既有决策

ADR 001 第 5 条原定"用 WM_NCHITTEST 采样 alpha 做穿透"。实测发现：

- `WS_EX_LAYERED` 窗口**原生**就做逐像素命中测试，alpha=0 的像素自动把鼠标消息让给下层窗口，跨进程有效；
- Electron 的 `transparent: true` 窗口已经带 `WS_EX_LAYERED`，等于开箱可用；
- 子类化 `GWLP_WNDPROC` 那条路在 Electron 下回调根本不触发（SetWindowLongPtr 返回成功，hitTestCount=0），
  且整窗变成穿透——推测消息在非 Node 线程派发，koffi 拿到默认返回 0（HTNOWHERE）。

于是作废原方案。连带收益：M1 **不需要**把渲染层 alpha 掩码回传主进程，省掉每帧几十 KB 的 IPC。

### 代价 / 新约束

渲染层想穿透的区域 alpha 必须严格为 0。调试 HUD、阴影、半透明遮罩都会变成可点击区域——
宠物本体与调试 UI 得分窗。

### 环境坑（跨会话有用）

- 本会话环境继承了 `ELECTRON_RUN_AS_NODE=1`（WorkBuddy 宿主自己是 Electron 应用），
  直接调 electron.exe 会退化成纯 Node 模式，`require('electron')` 返回字符串。必须删掉该变量。
- 路径含空格时别用 `shell: true` 调 electron.exe。
- Bash shim 缺 `dirname`/`head`/`tail`，命令虽能跑但有噪音；可靠输出用 node 单行脚本。

## M1 渲染闭环（代码完成，待人工验收）

### 做了什么

- 正式代码落到 `src/`，分层见 ADR 005：kernel（纯 TS 内核）/ host（覆盖窗口 + 全屏检测）/
  main（Electron 入口 + preload）/ renderer（canvas 播帧）/ shared（IPC 契约）。
- 宠物包加载与校验：路径穿越防护、魔数嗅探（PNG/WebP 头解析，读真实尺寸）、
  图集尺寸契约（V1=1536x1872）、状态合流（behavior-map 给帧列 + desktop-pet.json 给 fps/锚点）、
  锚点自洽校验（offsetY === groundY - baselineY）、帧列从第 0 列连续。
- 状态机播放器：loop 常驻循环；一次性动作播完回落 fallbackState/idle；同状态重复 setState 不打断。
- 渲染：每帧 clearRect（保证穿透区 alpha=0）、offsetY 纵向补偿对齐 groundY、DPR 适配。
- 交互：拖动（渲染层上报增量、主进程移动窗口）、单击身体播一次挥手。
- 全屏让位：复用 M0 判据，600ms 轮询，状态变化才动作。
- 自检：`electron . --screenshot=<前缀>` 抓两帧 PNG 自动退出。

### 构建上踩的三个坑（已写进 ADR 005）

1. 沙箱 preload 里 `require` 本地模块会被拒（`module not found`）→ preload 用 esbuild 打包。
2. tsc 给渲染层输出 CJS，浏览器没有 `require`（`exports is not defined`）→ 渲染层用 esbuild 打成 IIFE。
3. `ready-to-show` 时页面脚本还没执行，过早 send init 会静默丢消息 → 改成渲染层发 `pet:ready`、
   主进程收到再下发，渲染层幂等处理。

另：tsc 只编译 .ts，`index.html` 要手工拷进 dist（`tools/copy-assets.mjs`）。
