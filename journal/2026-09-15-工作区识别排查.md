# 2026-09-15 · 工作区识别排查（更正前次判断）

## 起因

Justin 反馈：`desktop-pet` 依旧不在「选择工作空间」列表里；每次新建对话都会落进带时间戳的新目录，
浏览/添加入口不起作用。他提出"是否干脆把整个工程打包到另一个工作区重建"。

## 结论先行

**不用搬家。** `desktop-pet` 已经被 WorkBuddy 正式登记为工作区，本次会话的 cwd 就是它。
详见 `docs/decisions/006-工作区识别与登记机制.md`（含全部证据）。

## 更正：前次判断错了

本工程 journal `2026-09-15-M1渲染闭环.md`「补：工作区注册」一节判断
"根因是 `~/.workbuddy/projects/` 下没有索引目录"，并据此手工创建了索引目录与 `.workbuddy/` 标记目录。

**这个判断是错的。** 实测：

- `~/.workbuddy/projects/` 是**会话记录（jsonl）的存储位置**，由会话 cwd 派生，与列表无关；
- 工作区列表的真实数据源是 `workbuddy.db` 的 `workspaces` 表 ∪ 会话历史中保存的工作区路径。

手工造索引目录既不必要也不可能生效。

## 真实的两个机制

1. **列表来源**：`workspaces(path TEXT PRIMARY KEY, last_opened_at INTEGER)` 表。
   实际表中 3 条：艾勒瓦达二期、探索、**desktop-pet**（`last_opened_at` = 本次会话创建时刻）。
2. **时间戳目录来源**：`WorkspaceDomain.generate()` —— 新建对话时若未指定工作区，
   就在「默认根目录」下建时间戳子目录并登记。默认根目录 =
   `~/.workbuddy/app/app-config.json` 的 `defaultWorkspacePath` = `<工作区>`。

关键点：**只有目录真的被用作会话 cwd，才会写进 `workspaces` 表**。
浏览/选中目录本身不写入——这就是"添加了却没变成永久索引"的体感来源。

## 排查手法（下次遇到同类问题可复用）

1. 用 node 单行脚本替代 bash 管道（本环境 shim 缺 `dirname`/`grep`/`head`），列 `~/.workbuddy/` 各目录。
2. 读 `workbuddy.db`：`node --experimental-sqlite`，先列 `sqlite_master` 找表，再 `select *` 看真实数据。
3. 读日志取证：`logs/main.log`（`session-create`、`defaultWorkspacePath`）与 `logs/daemon.log`。
4. 静态定位代码：直接 `Buffer.indexOf` 扫 `resources/app.asar`（未压缩），
   先搜中文 i18n 文案拿 key，再拿 key 反查代码；注意 i18n 会有多语言副本干扰命中数。

## 给 Justin 的操作结论

新建对话时在「选择工作空间」列表里选 `desktop-pet` 条目即可；不要走"新建默认工作区"。
若列表里暂时还看不到，重启一次 WorkBuddy 再看（列表是否启动时缓存，未实测）。
