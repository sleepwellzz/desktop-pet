`GetWindowRect` 把结构体写进 JS 对象，koffi 不回写 → 字段全 undefined →

## 缺陷 2：命中区域不精细 —— 部分修复，待复验

**找到并实现了一个"规格写了、代码没接"的缺口**：
`desktop-pet.json` 声明 `hitTest: "alpha-threshold"` + `hitTestAlphaThreshold: 16`，
但全工程只有类型定义引用它，实际生效的是系统的 "alpha > 0 即命中"。

已在渲染层实现：精灵图加载后清零 `alpha < 16` 的像素。
实测清理 2,000,388 个像素 = `alpha==0` (1,992,481) + `alpha 1–15` (7,907)，
**两处独立测量互相印证**；自检截图确认动画仍在播。

同时用形态学距离分析确认：窗口表面的低 alpha 与半透明像素**全部落在可见轮廓 2px 以内**
（>4px 的孤立点为 0 个）—— 即它们是抗锯齿与 1.5x 缩放插值的产物，不是散落在空白区的噪点。

**因此"点在远离身体的空白处也触发"这一现象尚未被完全解释**，需要一次精确复验来区分：
是用户点在了轮廓 1–2px 的边缘（可接受），还是分层窗口的穿透在实机上并未生效（需重做方案）。
复验动作已写进 PLAN §4。

## 一个被推翻的验证手段

为确证上面的问题，专门搭了 `WindowFromPoint` 网格采样探针，与精灵 alpha 逐点比对。
**结论：方法不成立，探针已删除。**

`WindowFromPoint` 反映的是"客户区覆盖"，不体现分层窗口的 alpha 穿透。

要验证穿透，只能走 M0 的老路：`SendInput` 真实点击 + 观察谁收到事件。
这条负面结论已写进 ADR 007，避免以后重复踩。

## 踩坑与手法

- **koffi 传结构体一律用 Buffer**：顶层结构体和嵌套结构体都会"返回 true 但字段全 undefined"，
  静默失败。本工程已栽两次。
- 探针第一次跑出"全部穿透"这种全 0 结果时，应当先怀疑工具而不是被测对象 —— 这次绕了几轮才回头。
- 需要跟 Electron 打交道的诊断，写成"一条命令内启动→采样→自检→退出"的脚本，
  可以避开沙箱在命令结束后回收子进程的问题（`--screenshot` 模式同理）。
- 图像量化分析用 Python + Pillow（venv 装在
  `~/.workbuddy/binaries/python/envs/default`）；形态学膨胀用 `ImageFilter.MaxFilter` 即可，
  不必引入 numpy/scipy。
