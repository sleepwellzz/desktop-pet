# 2026-09-22 · 动作排两处修订：走路时收起面板 + 托盘显示宠物名

> 接续同日第五次（打包交付）。用户实测了动作排之后提出两条修改。

## 用户原话

> 「我想要在点击左走右走时，悬浮窗先消失再出现；也就是说，其他动作点击时，悬浮条保持不消失，
> 但在左走右走时，悬浮条会在移动过程中消失，等移动结束后再重新出现」
>
> 「我想更改托盘里鼠标悬停时显示的程序名称，把 desktop-pet 改为淘淘」

## ① 走路时收起面板（ADR 039）

这正是 **ADR 038 负面结论第 2 条**列出的三种改法之一（"走路时先收面板"）——
当时如实记的是"机制上确定会发生，好不好看只能实测"。**现在数据取得了：用户不接受。**

三个设计点：

1. **判据是"这一下真的会移动窗口"**（`res.play.targetX !== null`），**不是**"是不是位移姿态"：
   贴着屏幕边缘时位移动作会降级成原地演，那时宠物一步都不动，没有任何理由收走面板。
2. **这份"待恢复"放进内核状态机**（`BarState.restoreAfterWalk` + 两条新事件
   `walk-hide` / `walk-restore`），不是主进程里的一个布尔。理由：它决定"面板要不要自己冒出来"，
   而"面板自己冒出来"**正是 ADR 016 花过学费要根除的体验** —— 这类判断必须能单测。
   **与悬停唤出的根本区别**（日后别拿 ADR 016 来反对这一条）：
   悬停是"无人触发地冒出来"，这里是**用户显式动作的延续**。
3. **三条不变量**：
   - ① 只有 `walk-hide` 能置位，且面板当时必须可见 —— 否则走完会**凭空冒出一个面板**；
   - ② 面板一可见，欠账即作废（用户自己叫回来了）；
   - ③ `pet-hidden` / Esc / × 也作废。

**②③是单测真抓到的，不是想出来的**：少了③，**走路期间宠物被隐藏**（托盘 / 全屏让位）时，
走完 `walk-restore` 会把面板**开到半空**。断言原文：
`FAIL 宠物被隐藏 ⇒ 欠账作废 —— 期望 false，实际 true`。

我还先把不变量写成了"面板一可见就清"（只覆盖 ②），单测立刻指出它漏了"作废时面板恰好不可见"
的那一半。

## ② 托盘悬停提示显示宠物名（ADR 040）

`淘淘 · 空闲` 这种形式，名字**取自宠物包**（`pet.json` 的 `displayName`），
与面板上的身份位同一来源；删掉写死的那句初始 `setToolTip('desktop-pet')`。

顺带把**宠物名在主进程里收成一处** —— 此前 `buildPayload` / `barView` / `__petDebug`
各写一遍 `pack.manifest.displayName ?? pack.manifest.id`，**三份副本正是"两处显示两个名字"的温床**。

**不许顺手改的地方**：**宠物窗口标题必须保持 `desktop-pet`** —— 所有探针靠 `getTitle()` 找窗口，
改了会让整套回归静默失效（表现为"未等到桌宠窗口"，看起来像启动失败）。已加结构性断言钉住。

## ③ 顺带补上一个从未验证过的面（本轮最有价值的一条）

探针点面板**一直用 `b.click()`（DOM 合成事件）**，它**绕过 Windows 的输入路由**。
而 ADR 009 那条"`hide()` 之后系统不再把**真实鼠标按钮事件**路由到该窗口"，
在控制条上**只被键盘路径验证过**（ADR 016 实测的是 `keyDelta`）——
控制条恰好是"会接收按钮事件"的窗口，所以**那一面一直是空的**。

新需求让面板**自己 hide 再 show**，正好把它推进 ADR 009 描述的情形里 ⇒ 必须实测。

新增用例 ⑫c，顺序刻意排成：**先证明正常情况下真实点击有效（基线）→ 再走一次路（hide→show）
→ 再真实点击一次**。基线通过而复查失败 ⇒ 就是 ADR 009 复现。

**实测（`control.json`）**：

| 判据 | 读数 |
|---|---|
| 真实鼠标点击面板按钮（基线） | ✅ 点击生效、`在演=waiting`、再点一次已停 |
| 走路中面板收起 | ✅ `收起=true` |
| 宠物真的左移 | ✅ 620 → 234（**-189px**，落在声明的 180–300 内） |
| 走完面板**自己回来** | ✅ `true` |
| 回来后重新居中 | ✅ 水平偏差 **0** |
| 走完高亮已清 | ✅ |
| **hide→show 之后真实鼠标点击仍有效** | ✅ `在演=waiting` |

⇒ **ADR 009 不适用于控制条，不需要 reload。** 这条以前只是"推测它不适用"，现在是实测。

## 判据

- 单测 **361 → 391 项**全绿（第 ⑪b 节 30 项，覆盖三条不变量的每个分支，
  含"走路期间 tick 不会让它冒出来""走路期间的失焦不丢欠账"）。
- `spikes/m2-control` **PASS**（含新用例 ⑫c）。日志里**无 `[uncaught]`**。
- `node --check` 探针脚本 —— **又拦下一次重名**（`const walking` 与第 ⑫b 节冲突，
  electron 会秒退且不写日志，光看"报告没生成"定位不到）。

## 三个如实记录的取舍 / 观察

1. **恢复面板时照旧抢焦点**。走路前焦点就在面板上（用户刚点的按钮），还回去的正是他原本在的位置；
   代价是那 2–3 秒内如果他切去别的窗口打字，面板回来会抢一次。
   刻意不引入 `showInactive` 的恢复分支 —— 那会新开一条**未验证**的显示路径
   （"面板显示时不带焦点会不会被 `focus(false)` 规则立刻收掉"在本项目没验证过）。
2. **走路期间仍然可以右键唤出面板**（用户显式动作优先，欠账作废），此时会看到面板跟着走完那一小段。
   重叠窗口只有 2–3 秒，没有为此加"打断走路"的规则。
3. **日志里偶尔出现两行连续的"控制条收起"**（机制未坐实，标注为**推测**）：
   推测是"窗口 `hide()` → blur 事件 → `dispatchBar(focus:false)` → 又走一次 `syncBar`，
   而宿主侧的可见性记账（由窗口 `hide` 事件异步更新）还没跟上"；第二次 `bar.hide()` 是空操作，
   对行为无影响。**没修**：修它要把判据从宿主记账改成主进程自己再记一份，
   **两个真相源比一条重复日志更糟**（这个项目已经因为"两处各记一份"栽过）。

## 测试自身的教训

写"托盘不再写死 desktop-pet"这条结构性断言时，**被自己的注释判红**了 ——
`tray.ts` 里那句"**不再用 `desktop-pet`**"的注释本身含有那个字符串。
⇒ 给测试文件加了 `stripComments()`：**结构性检查一律先剥注释**，
否则"断言比它要测的东西更脆"。
