# spikes/m2-status —— 状态链路端到端探针

**用途**：验证「状态源 → 仲裁器 → 动画」这条链真的通到了画面上。
M2 第一步的核心风险是"没有真实状态源，产品空转"，这个探针就是那条验收手段。

## 命令

```bash
# 离线单测（不起窗口，虚拟时钟，138 项断言）
node tools/status-arbiter.test.mjs        # 或 npm run test:status

# 陈旧快照 / 清空会话的回归哨兵（离线、真实适配器 + 真实文件，约 15 秒）
node spikes/m2-status/probe-stale-sessions.mjs

# 端到端（拉起真实应用 + 真实 hook CLI，约 45 秒，屏幕右下角会出现桌宠）
node spikes/m2-status/run-status-e2e.mjs  # 或 npm run e2e:status
```

## `probe-stale-sessions.mjs` 是什么（2026-09-17 新增）

它盯的是**快照的时间语义**，这条链路横跨两层（适配器刻意不补 `Date.now()`、
内核的兜底是 `now`），任何单层的单测都看不到全貌 —— 而且上一轮它实测证实了一条真缺陷：
**没有 `ts` 的陈旧快照会被盖章成"刚刚"，于是"一启动就显示某某在运行中"**（ADR 017）。

六段断言（22 项）：有 ts 的陈旧快照 → 启动即 idle｜刚写的无 ts 快照 → 照常 running（**修复不能误杀**）｜
无 ts + mtime 倒回 1 小时 → 启动即 idle｜简写形态同理｜无 ts 的条目不会被"别的会话被写"续命｜
「清空状态会话」之后面板行数归零且不再冒出补事件。

**它同时是修复的回归哨兵**：只要有人把上面任何一条期望改回去，这里立刻红。

## 怎么取证

"渲染层收到了状态"不足以证明"画面真的换了"。所以探针在渲染层给
`CanvasRenderingContext2D.prototype.drawImage` 打补丁，回读 `sy / 208` ——
即**当前正在绘制的帧行号**。行号就是精灵图的语义坐标：

| 行 | 0 | 3 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|
| 状态 | idle | waving | failed | waiting | running | review |

于是"期望行出现过"= 动画确实切过去了，不依赖任何日志自述。

## 时间线

驱动扮演 agent，用**真实 hook CLI**（`tools/pet-hook.mjs`）写状态文件，
每个状态留 1800ms 窗口，核对窗口内实际出现的行号：

| 注入 | 期望行 | 验的是什么 |
|---|---|---|
| running | 7 | 处理中 |
| needs-input | 6 | 等待输入（并进入粘滞） |
| `--clear` | 0 | 会话被移除 → 补 idle 收尾 |
| ready | 3 → 8 | 一次性动作 + `then` 落点（挥手后落到 review） |
| blocked | 5 | 受阻（趴卧） |
| idle | 0 | 任务结束 |

## 已知坑（都踩过）

- **测批处理菜单（`喂状态.bat`）不能用 `spawnSync(..., { input })`**：写完全部输入后 stdin 立刻 EOF，
  菜单会连续读到空输入 —— 第一版没有空输入保护时直接**无限空转跑满一个核**。
  正确测法是 `spawn` 起进程、**用延时逐行写 stdin 且先不关闭**，这样才能模拟真人按键：
  ```js
  c.stdin.write('4\n'); await wait(2500); c.stdin.write('1\n'); ... c.stdin.end();
  ```
  另外 `c.on('exit')` 必须在 spawn 之后立刻注册，否则子进程先退出会漏掉回调（表现为脚本静默无输出）。
- **`goto :label` 写错标签名不会报错提示得很明显**，bat 直接终止且退出码为 1、后续输出消失。
  症状是"行为看起来对，但退出码不对、最后几行没打印"。
- **探针要等 Electron 起来才会截断日志**。驱动必须先把旧日志删掉，并用运行标识
  （`PET_E2E_RUN`）确认就绪行出自本次运行 —— 否则会读到上一次运行的残留日志，
  在探针还没开始采样时就动手注入（实测注入比采样早 3.7 秒，前两步全丢）。
- **桌宠是 detached 启动的**，`child.kill()` 带不走它下面的进程。收尾要用
  `taskkill /PID <pid> /T /F`。**绝不能按镜像名杀 `electron.exe`** —— WorkBuddy 自身也是 Electron。
- 残留实例会继续读写同一个状态文件，污染下一次运行。
- `idle` 事件**不产生状态切换**（输出本来就是 idle），所以断言必须挂在真实切换上。
