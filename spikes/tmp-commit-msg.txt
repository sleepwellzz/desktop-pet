第三次打包前的两处修复：退出崩溃（ADR 035）+ 自启值名（ADR 036）

① 点「退出宠物」弹 Object has been destroyed
- 根因：两条从未登记句柄的 interval（250ms 仲裁推进 / 600ms 全屏监听）横跨窗口死亡时点
- 修复：processTimerDisposers + stopProcessTimers（quit 与 will-quit 都调）
  + 全屏回调 isDestroyed 守卫
- 防复发：新增 tools/check-timers.mjs（裸 setInterval / *Watch 未接返回值即失败），
  挂进单测第 ⑳ 节
- 判据修正：run-tray 退出用例原来只核对"进程消失"，而崩了也一样会消失 ——
  现在一并检查日志里的 [uncaught]
- 诚实记录：三种确定性复现手段全失败（忙等锁死事件循环 / _getActiveHandles 不可靠 /
  拦截 app.quit 会把进程卡成半死），证据链是"机制清楚 + 用户亲历 + 历史日志佐证"，
  不是"我复现过"

② 开机自启注册表值名（挂起 #15 结项）
- 三条候选逐个实测：app package.json 的 name 无效 / app.setName() 无效
  （app.getName() 变了、值名纹丝不动）/ 改 exe 版本资源 ProductName 有效（rcedit）
- 目标值名修正为 electron.app.desktop-pet（前缀是 Electron 固定的，
  不是先前以为的 desktop-pet）
- make-portable.mjs 加 rcedit 一步（写进版本资源的值一律 ASCII，中文读出来是乱码）
- autostart.ts 加 migrateLegacyAutoStart：只动指向本应用的 / 保住已勾选意图 / 幂等
- 注册表读写改走 PS 而非 reg.exe（后者被安全策略拦），读值直接取属性
  —— 表格输出会折行，解析出的是残缺内容
