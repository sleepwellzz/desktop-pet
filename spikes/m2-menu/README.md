# spikes/m2-menu —— 原生菜单可行性 / 托盘动作

**用途**：M2 ② 的两类验证。
① 「原生菜单能不能用」是纯平台行为，不许推断 —— 先探针，再决定方案；
② 托盘那一堆动作（隐藏/显示、缩放、自启、退出）必须用可观测结果验证，而不是"看着像"。

## 命令

```bash
node spikes/m2-menu/run.mjs                    # 原生菜单可行性（约 25 秒）
node spikes/m2-menu/run-tray.mjs               # 托盘动作（约 45 秒，会弹窗）
node spikes/m2-menu/check-autostart-registry.mjs   # 自启是否真写进注册表（第二来源，约 30 秒）
```

## 怎么取证

- **菜单**：`desktopCapturer` 抓全屏截图（看菜单到底出现没有）+ 在光标附近的若干偏移注入
  **真实点击**，看哪个菜单项回调被触发 + 交互后再点宠物确认输入通路没坏。
  探针会打印每轮的前台窗口类名/标题/尺寸 —— 这个顺带抓出了"桌面被误判成全屏"的缺陷。
- **托盘动作**：主进程提供 `--expose-actions` 接缝把动作表挂到 `globalThis.__petActions`，
  探针直接调它，再用真实点击/拖动、窗口 bounds、`tasklist` 核对 PID 来判定结果。
- **自启**：`getLoginItemSettings` 回读 + PowerShell 直读 `HKCU\...\Run` 做第二来源
  （本机安全策略禁用了 `reg.exe`）。

## 结论（2026-09-16，均已回写 ADR 011）

- 原生菜单在 `WS_EX_NOACTIVATE | TOPMOST` 的透明窗口上**可弹出、可点击**，交互后输入通路完好
  → 不需要自绘菜单（自绘要改窗口尺寸，会触碰命中区域）。
- 托盘动作全部通过：隐藏→显示后仍可点可拖；缩放 0.7→1.0 尺寸正确、底边中点漂移 0、
  命中仍只吃精灵轮廓；自启写注册表并撤销干净；**退出后进程消失**。

## 已知坑（都踩过）

- **菜单在屏幕边缘会整体翻折**：宠物在右下角时，菜单被顶到光标的**右上**方向。
  按直觉猜"右下偏移"必然全落空（第一版 5 个候选点全错）。要么按截图量出的几何去点，
  要么把能力验证搬到屏幕中间做。
- **`pointermove` 的 `e.button` 是 −1**：渲染层里按"只处理左键"过滤 `pointermove`，
  会把整段拖动静默吃掉 —— 症状是 `down/up/move` 计数**全都正常**、窗口一动不动。
- **桌面（WorkerW）会被误判成全屏应用**：点任务栏"显示桌面"条之后前台变成
  `WorkerW`（2560×1600、空标题），`GetShellWindow()`/`GetDesktopWindow()` 都拦不住它。
- **`GetClassNameW` 的返回值不含结尾空字符**：按 `(len−1)*2` 截断会把 `WorkerW` 读成 `Worker`，
  白名单恒不匹配 —— 这个差一错误让上面的修复**静默失效过一轮**。探针现在会把 `fgClass` 打出来。
- **探针驱动必须先用运行标识确认日志/报告出自本次运行**，否则会读到上一次的残留（ADR 010 同款坑）。
- 桌宠是 detached 启动的，收尾用 `taskkill /PID <pid> /T /F`；**绝不能按镜像名杀 `electron.exe`**
  （WorkBuddy 自身也是 Electron）。
